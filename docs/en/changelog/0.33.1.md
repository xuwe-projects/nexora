# Nexora 0.33.1

Release date: 2026-08-11

## Summary

This patch completes the existing `ApplicationOptions::subprocess_windows(false)` contract. An
application can keep singleton enforcement, full multi-window behavior, session restoration, and
tray controls while running every Shell, the unique Settings window, and registered Windows in one
GPUI process. Managed subprocess windows remain the default.

Handler: [@Jixiangup](https://github.com/Jixiangup)

Related Issue/PR: none

## Fixed

- “Open in new window” now creates a complete Shell in the current GPUI event loop when subprocess
  window hosting is disabled, instead of persisting a session without opening a window.
  — Handler: [@Jixiangup](https://github.com/Jixiangup)
- Single-process mode now restores, persists, and removes sessions for extra Shells, the unique
  Settings window, and registered Windows. Full locations and queries, tab order, pinning, active
  tabs, display UUIDs, bounds, and minimized state continue to use the v0.33.0 workspace schema.
  — Handler: [@Jixiangup](https://github.com/Jixiangup)
- Multiple Shells in one process no longer overwrite one global navigation callback.
  `Context<T>::navigate` targets the Shell containing the source entity, `App::navigate` targets the
  active Shell, and unresolved origins fall back to the main Shell.
  — Handler: [@Jixiangup](https://github.com/Jixiangup)
- Settings and registered Windows are tracked by their actual window IDs, and invalid restored
  routes are warned and skipped without aborting application startup.
  — Handler: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Updated the `develop-nexora-apps` and `gpui-desktop-development` Skills to distinguish a singleton
  application from a single operating-system process and document navigation/state boundaries for
  both hosting modes. — Handler: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- There are no breaking public API, configuration schema, HTTP API, Account DTO, SQLx migration,
  database baseline, or Updater protocol changes.
- `subprocess_windows` still defaults to `true`; applications that do not set it retain the v0.33.0
  managed subprocess architecture.
- `subprocess_windows(false)` now changes only the hosting strategy and no longer reduces window
  creation, restoration, or navigation behavior.

## Upgrading from 0.33.0

1. Update every Nexora dependency and the CLI to `v0.33.1`, then refresh the lockfile.
2. Applications requiring one OS process should keep
   `.single_instance(true).subprocess_windows(false).restore_window_sessions(true).tray_enabled(true)`;
   setting only `.subprocess_windows(false)` preserves the other default `true` values.
3. Sync `.agents/skills/develop-nexora-apps` and
   `.agents/skills/gpui-desktop-development` from this release.
4. On target platforms, verify new Shells, Settings uniqueness, registered Windows, restart
   restoration, duplicate-launch activation, and tray window-group commands.

Rolling back requires no database or configuration migration, but applications depending on
complete single-process multi-window behavior should re-enable managed subprocess windows before
returning to v0.33.0.

- `bash scripts/check-scaffold-consumer.sh`

Manual Windows/Linux GUI acceptance was not run in the current environment, and no external
PostgreSQL, OIDC, signing, notarization, or S3/RustFS publishing environment was used. This release
does not change those protocols or integration boundaries; downstream applications should still
regress window creation, restoration, duplicate-launch activation, and tray commands on target
platforms.
