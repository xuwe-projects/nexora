# Nexora 0.24.2

## Fixes

- Restored `apps.<app>.release.channels` multi-channel release configuration, including `default_channel`, channel-level `version`, `build_number`, `minimum_supported_version`, and `runtime_config` overrides, while keeping single-channel `release.channel` compatibility. — Owner: [@openai](https://github.com/openai)
- Restored `nexora build` and `nexora publish` support for `--channel` and `--all-channels`. Multi-channel builds now generate the updater feed URL from the selected channel and reject static `updater.feed_url` values to avoid bundling the wrong update source. — Owner: [@openai](https://github.com/openai)
- Release receipts again record `runtime_config_source`, `runtime_config_sha256`, and `updater_feed`; runtime config changes invalidate the previous receipt and force a regenerated one. — Owner: [@openai](https://github.com/openai)

## Links

- Issue/PR: none

## Compatibility

- No breaking changes. Existing single-channel `release.channel` configuration remains supported.
- Apps using multi-channel `release.channels` must omit static `apps.<app>.updater.feed_url`; Nexora generates it from the app, channel, and publish target.

## Upgrade

1. Upgrade Nexora dependencies and CLI installation tags to `v0.24.2`.
2. iMES can keep its existing `default_channel`, `release.channels.*.runtime_config`, and `updater.channels` configuration.
3. Run `nexora build --channel <channel>` or `nexora build --all-channels` to generate channel-specific release receipts and bundles.
