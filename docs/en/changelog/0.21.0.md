# Nexora 0.21.0

Release date: 2026-08-03

## Summary

This release makes multi-app branding, macOS installer icons, and desktop updater entry points part
of one app registration. The existing signed updater is now an explicitly installed public
`nexora::desktop` capability. Because app registrations gain required branding and platform-icon
fields, the pre-1.0 minor version advances to `0.21.0`.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issues/PRs: none

## Added

- `nexora create` and `nexora init` generate a complete, isolated
  `assets/logos/<app_key>/` PNG/ICNS/ICO set without overwriting existing brand files.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `nexora icons generate --app <app_key>` validates the source PNG and deterministically generates
  standard PNG sizes, ICNS, and ICO. Manual resources require explicit `--force` before replacement.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `nexora::desktop::install_updater`, the public `CheckForUpdates` action, a reusable button, and a
  single app-level session coordinator. Default login, account, settings, and native macOS menu
  entries follow explicit installation. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Signed `latest.json`, S3/RustFS publishing, the independent sidecar, health confirmation, rollback,
  yanking, forced updates, and the updater Skill are part of one production workflow.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora.toml` remains the sole app registration boundary and now declares branding, macOS ICNS,
  Windows ICO, Linux PNG sizes, optional updater app ID, launch checks, and expected Team ID.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `nexora build` validates the selected app's workspace paths and target icon, installs ICNS into the
  app Resources and `CFBundleIconFile`, and writes identity, version, sidecar, and updater bundle
  metadata without mutating Cargo manifests. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Launch checks only check for a version and show a non-modal notification. Both launch and manual
  flows require confirmation before download and share one coordinator.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `examples/updater-macos` now uses isolated branding and the public desktop updater and was built as
  a real arm64 `.app`, `.app.zip`, DMG, and `artifact.json`. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- Existing app registrations must add `branding` plus macOS, Windows, and Linux platform icon
  sections. Old configurations fail before packaging instead of producing unbranded installers.
- Updater UI and network work require an explicit `nexora::desktop::install_updater` call.
- Windows and Linux participate in configuration, scaffolding, and icon generation, but full
  installers and automatic replacement remain unavailable in this release.

## Upgrade from 0.20.0

1. Update the dependency to `v0.21.0`, regenerate the lockfile, and sync
   `.agents/skills/develop-nexora-updater`.
2. Create `assets/logos/<app_key>/` for each app and add branding plus all platform icon fields to the
   same app registration.
3. Run `nexora icons generate --app <app_key>` and `nexora build --app <app_key>`.
4. Build `UpdateConfig` from the bundle and call `nexora::desktop::install_updater` from
   `Application::initialize`; remove private updater dialogs and state machines.
5. Developer ID releases must configure the expected Team ID and continue to inject signing secrets
   externally.

Rolling back to 0.20.0 also requires restoring the old `nexora.toml` schema and private integration.
Generated brand files may remain, but the 0.20.0 CLI does not consume the new fields.
