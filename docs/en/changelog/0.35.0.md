# Nexora 0.35.0

Release date: 2026-08-12

## Summary

This release makes the desktop window model strictly single-process with multiple native windows.
The main window, extra Shells, the unique Settings window, and registered Windows always share one
GPUI event loop, while no window or tab session survives an application restart. It also restructures
Account client failures so connection, timeout, response-read, successful-response contract,
structured rejection, and unstructured-response failures receive accurate and safe diagnostics.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related Issue/PR: none

## Changed

- The application-identity singleton gate is mandatory, and duplicate launches only request
  activation from the running process. Extra Shells, Settings, and registered Windows are created by
  the current `App`; managed window child processes no longer exist. The updater sidecar remains a
  separate update component. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- A cold start always creates one main window and opens `ApplicationOptions::initial_path`.
  Runtime tabs, pinned state, and extra windows are memory-only and are not restored after normal or
  abnormal exit, system restart, or upgrade. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `workspace.toml` schema is now 2. Schema 0 retains `main_window` geometry and drops
  `pinned_tabs`; schema 1 extracts only display, bounds, and maximized/fullscreen state from the
  window whose ID is `main`. All tabs, active tabs, and non-main windows are discarded, while theme,
  component size, DataTable layout, non-secret Account preferences, and ordinary unknown fields are
  preserved. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Account HTTP failures now expose stable categories for client initialization, connection, timeout,
  other transport failure, response read, successful-response contract incompatibility, structured
  server rejection, and unstructured abnormal response. Structured rejection retains the safe
  message, stable code, request ID, and request-ID copy action.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Connection, timeout, temporary server rejection, response-read, and contract failures remain
  retryable and retain Keychain or Credential Manager credentials and recovery eligibility. Only
  explicit permanent failures such as `invalid_grant`, OIDC subject mismatch,
  `account_not_registered`, and `account_suspended` disable recovery and remove credentials.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The Account secure-storage service is now `${application_identity}.account.oidc`, preventing
  applications that share an OIDC configuration from sharing refresh tokens. The old fixed
  `nexora.account.oidc` entry is neither migrated nor deleted automatically.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- A successful `/me` response that cannot be decoded is no longer reported as Account network
  unavailability; it now reports client/server version or response-contract incompatibility.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Account errors and client Debug summaries no longer retain or print the underlying
  `reqwest::Error`, full endpoint, Authorization header, tokens, or raw response body. OIDC UI errors
  also classify endpoints and provider details safely. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- If the initial preference-migration save fails, that launch still ignores all old sessions. A later
  ordinary preference write retries migration under the file lock, preventing retired fields from
  being flattened back into the file or main-window geometry from being lost.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- The `ApplicationOptions::single_instance`, `ApplicationOptions::subprocess_windows`, and
  `ApplicationOptions::restore_window_sessions` fields and builders are removed. Delete old calls;
  there is no replacement switch.
- Public `WindowSession`, `WindowSessionRole`, and `WindowTabSession` types are removed, together
  with the managed-window child-process arguments, roles, handshake, heartbeat, session-patch, and
  close-notification protocol.
- The Account secure-storage namespace changed. Applications must sign in once after upgrade before
  a recoverable credential is stored in their own namespace; Nexora does not read, migrate, or delete
  credentials under the old service.
- HTTP paths, Account DTOs, authorization rules, SQLx migrations, PostgreSQL baselines, and the
  updater-sidecar protocol are unchanged. `/me` still requires a real Bearer token and validates the
  local account state.

## Upgrade from 0.34.0

1. Update every Nexora workspace dependency and the CLI to `v0.35.0`, then regenerate `Cargo.lock`.
2. Remove `.single_instance(...)`, `.subprocess_windows(...)`, and
   `.restore_window_sessions(...)`. Do not add an equivalent local switch or a second singleton or
   window manager.
3. Remove imports, construction, and tests for `WindowSession`, `WindowSessionRole`, and
   `WindowTabSession`. Runtime windows continue to open through Shell, `SettingsWindow`, and
   registered `Window` APIs.
4. Do not delete the complete `workspace.toml`. The first launch migrates it to schema 2, preserving
   only main-window placement/state and ordinary preferences; retired window fields disappear after
   a successful save.
5. Synchronize `.agents/skills/develop-nexora-apps/SKILL.md` and
   `.agents/skills/gpui-desktop-development/SKILL.md`. The scaffolded copies are already updated.
6. On macOS and Windows, sign in once after upgrade so credentials are written into the new
   application-identity secure-storage namespace. Do not read or copy credentials from the old fixed
   service.
7. Validate one-window cold start, runtime multi-window behavior, duplicate-launch activation,
   retained main-window geometry, Account connection/timeout/contract/rejection messages, and the
   temporary/permanent credential policy in the target installer.

Rolling back to v0.34.0 requires no database rollback, but the old version can still read historical
window sessions if schema 2 was never saved successfully. Once 0.35.0 saves schema 2, historical tabs
and extra-window sessions are intentionally gone. Credentials in the new namespace are not used by
v0.34.0, so rollback can require another sign-in.

## Verification

The release gates completed successfully:

- SemVer parsing confirmed `0.35.0` is strictly newer than the latest release, `0.34.0`
- `cargo fmt --all --check`
- `cargo check --workspace --all-targets`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

Coverage includes duplicate-launch singleton activation, multiple windows in one GPUI application,
schema 0/1 migration and migration-save retry, Account connection failure, deterministic timeout,
incompatible `200` JSON, structured `401/403`, unstructured and truncated responses, request-ID
propagation, and redacted Debug output. The scaffold gate resolves dependencies without a lockfile for
both a desktop project and an Account full-stack project, then compiles desktop, server, and migration
test targets.

External PostgreSQL/OIDC, signing, notarization, and S3/RustFS environments were not exercised. No
iMES installer based on 0.35.0 was built before this release, so real iMES login, cold-start windows,
and Keychain migration remain manual acceptance work for the iMES upgrade task.
