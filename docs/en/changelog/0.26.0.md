# Nexora 0.26.0

Release date: 2026-08-04

## Summary

This release completes the Windows x86_64/ARM64 path from WiX MSI and Burn Setup EXE through the
in-app update ZIP, object-storage publishing, and rollback. Every formal package now carries a
shared `nexora-release.json` identity and Markdown release notes verified for size, SHA-256, UTF-8,
and safe links. Desktop applications can read the validated app ID, version, build number, and
channel, while the completion dialog renders only locally or remotely verified notes.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- Windows builds support x86_64 and ARM64 WiX MSI, Burn Setup EXE, and `windows.zip` outputs.
  Publishing writes architecture-specific `latest-<arch>.exe` / `latest-<arch>.msi` aliases and
  single-target `latest.exe` / `latest.msi` aliases. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Formal macOS and Windows packages receive `nexora-release.json` before signing and archiving. It
  records the app key/ID, display name, package, SemVer, positive build number, channel, target, and
  optional notes digest. `nexora::desktop::application_info` exposes the validated read-only
  identity. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `release.notes` supports a default and channel overrides. Build freezes source Markdown as a
  versioned `notes.md`; publish adds its URL, size, and SHA-256 to the signed manifest, and clients
  verify it before download or rendering. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The update-completed Dialog shows version, build number, and trusted Markdown notes while keeping
  immediate restart, deferred restart, and health-confirmed completion on one process-once flow.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The default scaffold adds `release-notes.md`, and the Windows example documents runtime config,
  the sidecar, build, and publish setup. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Windows in-app update staging now uses a hidden sibling directory on the installation volume,
  preflights replacement permissions before exit, atomically overwrites `pending.json`, and keeps
  the temporary sidecar from holding the installation directory as its working directory. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- A failed Windows replacement restores and relaunches the previous version and persists the result
  for the next launch. Unsigned mode keeps Ed25519, SHA-256, ZIP-path, and PE-architecture checks;
  Authenticode mode continues to enforce the chain, thumbprint, and publisher. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- `apps.<app>.targets.required` is optional. `nexora build` defaults to the `rustc -vV` host target,
  accepts repeated explicit `--target` arguments, and no longer installs Rust targets implicitly.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Bundle loading cross-checks the app ID, version, build number, and channel in
  `nexora-updater.json` and `nexora-release.json`. An existing invalid metadata file cannot fall back
  to development mode. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Release-note HTTP requests inherit the updater HTTPS/explicit-HTTP policy and revalidate every
  redirect target so redirects cannot escape the transport boundary. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Windows startup loads updater configuration and release metadata beside the main EXE instead of
  taking the macOS `.app` path. GUI applications and sidecars no longer open an extra console.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Rust now writes Windows update ZIPs with `/` entry separators, avoiding PowerShell backslashes
  rejected by the safe extractor. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Publish planning retains both Windows installer aliases and trusted-notes upload, anonymous
  verification, and signed fields instead of allowing either feature path to replace the other.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

No database migration is required, but updater-enabled formal builds have stricter configuration
and bundle contracts:

- `apps.<app>.release.notes` is required when updater is enabled and may be overridden per channel.
  It must be an in-workspace UTF-8 Markdown file no larger than 1 MiB.
- Formal bundles loaded through `UpdateConfig::from_current_bundle`, `from_app_bundle`, or
  `from_windows_install_dir` must also contain valid `nexora-release.json`. Existing packages must
  be rebuilt with the 0.26.0 CLI; changing only the Rust dependency is insufficient.
- Signed-manifest note integrity fields remain backward compatible. Older manifests can still be
  checked and installed, but the client skips note download when URL, size, or SHA-256 is missing.

Windows installation moves from the previous simplified path to WiX MSI plus Burn Setup EXE. First
install, upgrade, uninstall, and real self-update should still be accepted on Windows x86_64/ARM64.

## Upgrading from 0.25.0

1. Update every Nexora dependency and CLI installation tag to `v0.26.0`, then regenerate lockfiles.
2. Add `notes = "..."` under `[apps.<app>.release]` for every updater-enabled app. Override it under
   `[apps.<app>.release.channels.<channel>]` when channels need different notes; the scaffold
   `release-notes.md` is a suitable starting point.
3. Rebuild with the new CLI and confirm that macOS Resources or the Windows EXE directory contains
   `nexora-updater.json`, `nexora-release.json`, and `notes.md`.
4. On Windows release hosts, install the pinned `cargo-wix` revision, WiX 5.0.2, and matching UI/
   BootstrapperApplications extensions, then run `nexora doctor --fix`, build, and publish dry-run.
5. Review CI target arguments. With no `targets.required`, build uses only the host; use repeated
   `--target` arguments for explicit targets. A complete stable publish still requires every target
   required by the project.
6. Sync downstream `.agents/skills/develop-nexora-updater`, `updater-protocol.md`, and current
   scaffold constraints so future work follows same-volume Windows staging, trusted release
   metadata, and release-note rules. This release does not change custom macro rules.

## Validation

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p nexora -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`
- `cargo check --manifest-path examples/updater-macos/Cargo.toml`
- `cargo check --manifest-path examples/updater-windows/Cargo.toml`

Real Windows x86_64/ARM64 MSI/Burn installation, self-update, and Authenticode were not exercised
from the current macOS host. macOS Developer ID notarization, external PostgreSQL, and a live OIDC
provider were also not exercised. Their platform and external-service boundaries are covered by
unit and integration tests, Windows ZIP tests, and strict static checks.
