# Nexora 0.28.0

Release date: 2026-08-05

## Summary

This release standardizes desktop publish credentials and cross-platform build dependency setup.
Publish targets no longer configure an environment-variable prefix. Access keys, secret keys, and
session tokens fall back independently through the current channel, base Nexora variables, and AWS
variables. Interactive `nexora build` and `nexora doctor --fix` runs can now detect, install, and
recheck macOS and Windows packaging dependencies. Non-interactive environments remain
side-effect-free and return executable installation commands.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- macOS builds check and prepare the Rust toolchain and target, `cargo-bundle`, Homebrew,
  `create-dmg`, and Xcode Command Line Tools when required. When a system installer needs manual
  completion, Nexora explicitly asks the user to rerun the original command. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Windows builds check and prepare the Rust toolchain and target, the pinned modern `cargo-wix`
  revision, Windows SDK, .NET SDK, WiX 5.0.2, and the UI/Bootstrapper extensions. If .NET is absent,
  the official Microsoft `dotnet-install.ps1` installs .NET 10 into Nexora's user-level tool
  directory and injects it only into the current process. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- `nexora doctor` remains a read-only check. `nexora doctor --fix` and `nexora build` share the same
  dependency repair and post-install recheck path, while CI and other non-interactive environments
  never start system installers. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- S3 access keys, secret keys, and optional session tokens are selected independently in
  `NEXORA_PUBLISH_<CHANNEL>_<FIELD>`, `NEXORA_PUBLISH_<FIELD>`, and `AWS_<FIELD>` order. Empty
  strings continue fallback, so one publish operation can safely combine fields from different
  levels. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Scaffolds, macOS/Windows examples, Chinese and English configuration documentation, and the
  `develop-nexora-updater` Skill now describe the same credential and dependency-repair behavior.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Removed

- Removed `credential_env_prefix` from `[publish.targets.*]` and channel overrides. The old field is
  rejected as unknown with no compatibility reader. Legacy provider-prefixed variables such as
  `RUSTFS_ACCESS_KEY_ID` and `RUSTFS_SECRET_ACCESS_KEY` are no longer considered. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

This release has a breaking `nexora.toml` publish-configuration and environment-variable change.
An old target could contain:

```toml
[publish.targets.rustfs]
credential_env_prefix = "RUSTFS"
```

After upgrading, remove `credential_env_prefix` and use the fixed variable convention. A beta
channel can, for example, provide:

```text
NEXORA_PUBLISH_BETA_ACCESS_KEY_ID
NEXORA_PUBLISH_SECRET_ACCESS_KEY
NEXORA_PUBLISH_SESSION_TOKEN
```

This combines a beta-specific access key with the base secret key and session token. Access and
secret keys are required after fallback, while the session token is optional. Update manifests,
remote object layout, Account HTTP contracts, and database migrations are unchanged.

## Upgrading from 0.27.1

1. Update Nexora dependencies to `0.28.0` or Git tag `v0.28.0`, then regenerate lockfiles.
2. Reinstall the standalone CLI package:

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.28.0 cli --locked --force --bin nexora
   ```

3. Remove `credential_env_prefix` from every base target and channel override. Move credentials to
   `NEXORA_PUBLISH_<CHANNEL>_*`, `NEXORA_PUBLISH_*`, or `AWS_*`; each field can migrate
   independently.
4. Run `nexora doctor` on build hosts. Interactive development machines may use
   `nexora doctor --fix`; CI should preinstall dependencies with the commands in the diagnostic
   instead of relying on interactive installers.
5. This release changes the `develop-nexora-updater` Skill and scaffold configuration. Downstream
   projects should sync `.agents/skills/develop-nexora-updater` or rerun `nexora init .` to install
   the updated Skill. Custom macro rules are unchanged, so cargo expand, benchmark, bloat, and asm
   analysis do not apply.

To roll back to `0.27.1`, restore the old `credential_env_prefix` and its complete credential group.
Newly installed Rust, Windows SDK, .NET, WiX, Homebrew, or packaging tools may remain installed and
do not affect the older CLI.

## Validation

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`
- `cargo check --manifest-path examples/updater-macos/Cargo.toml`
- `cargo check --manifest-path examples/updater-windows/Cargo.toml`

This release did not exercise the Windows SDK/.NET/WiX automatic installers or launch the generated
MSI/Setup installer on a Windows host. Windows ARM64, Authenticode, macOS Developer ID notarization,
Linux CLI atomic replacement, an external PostgreSQL instance, and a live OIDC provider were also
not exercised. GitHub Actions will build and validate the six platform CLI assets after the tag is
pushed.
