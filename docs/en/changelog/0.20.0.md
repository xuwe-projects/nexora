# Nexora 0.20.0

Release date: 2026-07-31

This release remains in the early-alpha `0.x` line and uses `v0.19.0` as its sole upgrade baseline.
It adds optional Sidebar navigation search and an explicit opt-in for non-loopback HTTP Account API
endpoints. Because public configuration structs and `ApplicationOptions` gain fields, the pre-1.0
minor version advances to `0.20.0`.

## Added

- `ApplicationOptions` now has a default-off `sidebar_search: bool` field and a
  `sidebar_search(true)` builder. The Shell uses the native `gpui-component::input::Input` between
  the Sidebar Header and navigation list with an `IconName::Search` prefix. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.
- Navigation search matches original title text, tone-less full pinyin, and contiguous pinyin
  initials. It filters only the navigation tree already visible to the current account, temporarily
  expands matching groups, and restores the prior expansion state when cleared. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.
- `ApiSettings` now has `allow_insecure_http`, with a serde default of `false`. HTTPS is always
  accepted, loopback HTTP remains accepted by default, and other HTTP endpoints require explicit
  opt-in. — Owner: [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.

## Changed

- Desktop API documentation, repository configuration examples, and the Account workspace scaffold
  now explain that plain HTTP transmits Bearer tokens in clear text and should be enabled only in a
  controlled environment where that risk is accepted. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.
- The desktop feature adds `pinyin 0.11.0` with default features disabled and only `plain` enabled.
  Nexora consumers that do not enable `desktop` do not pull in this dependency. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.
- The `desktop_basic` example enables Sidebar search, while displayed versions, installation tags,
  OpenAPI metadata, and internal workspace dependency constraints advance to `0.20.0`. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.

## Fixed

- The repository `config/desktop.toml.example` now uses the current `[api].endpoint`,
  `[account.oidc]`, and string-array `scopes` shape, plus `allow_insecure_http = false`, so copying
  the sample no longer fails on obsolete fields. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.
- API endpoint validation errors continue to return fixed explanations without echoing the endpoint,
  URL credentials, query, fragment, Bearer token, or other secrets. — Owner:
  [@Jixiangup](https://github.com/Jixiangup); related issue/PR: none.

## Compatibility and breaking changes

- Rust struct literals for `ApiSettings` must add `allow_insecure_http`. Serde configuration omitting
  the field defaults to `false`; existing HTTPS and loopback HTTP configurations remain valid.
- Rust struct literals for `ApplicationOptions` must add `sidebar_search`. Code using
  `ApplicationOptions::new()`, `Default`, or existing builders retains current behavior because
  search is off by default.
- Non-loopback HTTP remains denied by default. Setting `allow_insecure_http = true` does not add
  encryption; Bearer tokens are still transmitted in clear text.
- There are no database migrations, HTTP route changes, JSON wire-field changes, or OpenAPI path
  changes. To roll back, restore `v0.19.0` and remove the new struct/configuration fields.

## Upgrading from 0.19.0

1. Update the Nexora dependency tag/version to `v0.20.0` and regenerate the lockfile.
2. Add `allow_insecure_http: false` to every `ApiSettings { ... }` literal. The serialized setting may
   be omitted, although writing `false` explicitly is recommended to document policy.
3. Set `[api] allow_insecure_http = true` only when a controlled non-loopback plain-HTTP service is
   unavoidable and the clear-text Bearer-token risk is accepted; prefer HTTPS in production.
4. Add `sidebar_search: false` to `ApplicationOptions { ... }` literals. Enable the feature through
   `ApplicationOptions::new().sidebar_search(true)` when desired.
5. Downstream Account workspace projects should sync the current configuration template and
   `.agents/skills` rules, especially `[api]` safety guidance, `gpui-component` selection constraints,
   and the minimal `pinyin` feature set. Scaffolded projects retain their own initial version `0.1.0`.
