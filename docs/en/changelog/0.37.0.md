# Nexora 0.37.0

Release date: 2026-08-14

## Summary

This release further consolidates the desktop Shell, standard CRUD tables, and the Account user
directory into explicit public contracts. The Shell now uses one 236px/80px Sidebar layout axis with
an animated transition, while collapsed nested navigation remains accessible through official menus.
Global search is driven by a stable Action and real GPUI bindings. CRUD status columns are explicit
and linted, pagination always includes numbered pages, and the Account directory adds reusable
keyword, status, and account-type filters.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related Issue/PR: none

## Added

- Added `global_search::OpenGlobalSearch` and `ShortcutHint`. The Shell renders a complete key
  sequence only when the application has registered a real binding. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added `ShellToolbarOptions`, `ShellToolbarAction::icon_button`, and an options-aware installer to
  standardize toolbar hit areas, icon scale, and trailing spacing. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added `UserListQuery`, `AccountSession::list_users_filtered`, and server-side filtering by user ID,
  username, email, display name, status, and account type. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added `column(status, render = ..., text = ...)` to `CrudTableRow`, compile-time diagnostics, and
  lint rules for status columns, merged business values, boolean switches, and semantic Tags.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

  — Owner: [@Jixiangup](https://github.com/Jixiangup)

- `CrudPanel` shows page `1` even for a single page. Multiple pages use normal official `Pagination`

## Compatibility and breaking changes

- Business status columns in `CrudTableRow` must declare `status`, a dedicated `render`, and plain
  `text`. The new lint rejects merged business values and generic rendering that hides status
  semantics. Boolean statuses use `TableSwitchCell`; other statuses use filled semantic `Tag` variants.
- This is a public macro and scaffold-rule change during the 0.x line, so the release increments MINOR.
  The macro preserves existing fields and HTTP wire representations.
- `GET /users` only adds optional `keyword`, `status`, and `user_type` query parameters. Existing
  `page`, `page_size`, paths, response shapes, and permission keys remain compatible.
- `install_shell_toolbar_actions` and `AccountSession::list_users` remain available. The new layout
  options and filtered-list entry point are additive. There are no SQLx migration, PostgreSQL schema,
  or updater-protocol changes.

## Upgrading from 0.36.0

1. Move every Nexora workspace dependency and the CLI to Git tag `v0.37.0`, remove temporary local
   path/patch entries, and regenerate `Cargo.lock`.
2. Synchronize `.agents/skills/desktop-ui-component-selection`, `.agents/skills/gpui-component`, and
   the scaffold `AGENTS.md`, then run `nexora lint --deny-warnings`.
3. Add `column(status, render = ..., text = ...)` to each business status column, split merged values
   into separate columns, use `TableSwitchCell` for booleans, and filled semantic Tags otherwise.
4. Use `UserListQuery` or `AccountSession::list_users_filtered` when directory filtering is needed;
   existing `list_users(page, page_size)` calls remain valid.
5. Register an application-specific GPUI binding for `OpenGlobalSearch`. Without a binding, the Shell
   naturally omits the shortcut hint.
6. Applications with custom `CrudTableRow` macro usage should inspect `cargo expand`, compare it with
   a handwritten equivalent, and run `cargo bench` plus `cargo bloat`. If targets are missed, use
   `cargo asm` to complete the analysis loop.
7. Manually check Sidebar expansion, collapsed nested menus, search shortcuts, toolbar actions, user
   filters, status columns, and single- and multi-page pagination.

- `cargo fmt --all --check`
- `cargo check --workspace --all-targets`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

`cargo test --workspace --all-targets` also ran the benchmark target that compares the derived
`CrudTableRow` implementation with its handwritten equivalent. The new Account-filtering
`#[sqlx::test]` compiled with the database-tests feature. Its isolated database run could not start
because the base database configured by `config/server.toml` does not exist; no test database was
created or left behind.

This release does not add or modify database migrations. External OIDC, signing, notarization, and
object-storage environments are outside the local release gates.
