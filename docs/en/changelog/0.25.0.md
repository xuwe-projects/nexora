# Nexora 0.25.0

Release date: 2026-08-04

## Summary

This release adds secure session persistence, silent recovery, and automatic token refresh to the
desktop Account login flow. It also restores SHA-256 artifact sidecars and build numbers based on the
build machine's local timezone. macOS uses Keychain, Windows uses Credential Manager, and Linux does
not persist tokens. Signing out clears the in-memory session immediately and then best-effort removes
the credential and revokes the refresh token.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- The desktop Account runtime can store a refresh token, OIDC subject, and minimal profile in macOS
  Keychain or Windows Credential Manager. Startup recovery refreshes the session silently and reruns
  the Account `/me` business gate. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Access tokens refresh in the background before expiry. Transient network and provider errors use
  bounded backoff, while terminal failures such as `invalid_grant`, subject mismatch, or a disabled
  business account revoke recovery and remove the local credential. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- The default login gate now exposes keep-signed-in, recovery retry, and use-another-account actions.
  Custom login pages can use `login_snapshot`, `set_remember_login`, `retry_recovery`, and
  `login_with_other_account`. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The OIDC client adds typed `prompt=select_account`, refresh-token revocation, and a non-fatal result
  when the provider does not advertise a revocation endpoint. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Desktop Account configuration guarantees the `offline_access` scope. Linux explicitly disables
  keep-signed-in and never stores tokens in Secret Service or ordinary files. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- `nexora build` creates a standard `<artifact>.sha256` file for final macOS and Windows artifacts;
  publish uploads and anonymously verifies each sidecar while the signed manifest remains the update
  protocol's trust boundary. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `${BUILD_DATETIME}` now uses the build machine's local 24-hour `yyMMddHHmmss` time while preserving
  strict monotonicity against the preceding build number. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- The Windows installer inspection path now uses the same fixed-offset local time as normal builds,
  avoiding a type mismatch between multi-channel release code and dynamic build numbers. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Compatibility

There are no breaking changes and no database migration is required. Existing single-channel and
multi-channel release configurations remain supported. Applications that do not select keep-signed-in
retain the previous process-only session behavior, and Linux continues not to persist tokens.

A secure-storage failure does not interrupt the active process session, but the next launch cannot
recover silently. Normal sign-out does not perform provider-wide logout or clear browser cookies, so
the browser SSO session may remain available.

## Upgrading from 0.24.2

1. Update all Nexora dependencies and the CLI installation tag to `v0.25.0`, then regenerate lockfiles.
2. Applications using the default login gate need no code changes. A custom `LoginFeature` may opt into
   the new non-sensitive snapshot fields and keep-signed-in, retry, and account-switch actions.
3. Confirm that the OIDC provider permits `offline_access` and refresh tokens. When a
   `revocation_endpoint` is advertised, sign-out best-effort revokes the refresh token.
4. Rerun `nexora build` and `nexora publish --dry-run`; verify the `.sha256` sidecars, anonymous URLs,
   and signed `latest.json` for every final artifact.
5. Downstream projects should sync `.agents/skills/develop-nexora-updater` and its
   `updater-protocol.md` to adopt the local-build-time and SHA-256-sidecar constraints. This release
   does not change the custom macro rules.
