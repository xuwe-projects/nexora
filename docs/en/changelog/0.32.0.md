# Nexora 0.32.0

Release date: 2026-08-07

## Summary

This release completes the production path for desktop update builds, publishing, and Windows
installation transactions. The CLI now diagnoses host prerequisites without installing them,
Windows first-install packaging supports Inno Setup 6/7 with a publisher/display-name default
directory, and the sidecar preserves both the verified main executable identity and Inno uninstall.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- Updater-enabled releases now freeze required Markdown release notes and package verified notes,
  digests, and metadata into installation and update artifacts. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added multi-channel selection, dynamic build receipts, standard SHA-256 sidecars, field-by-field
  S3/RustFS credential fallback, and real Windows/macOS acceptance guidance.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora doctor` and `nexora build` only inspect Rust targets, the Windows SDK, Inno Setup, Xcode,
  and packaging tools. They no longer download software, launch installers, open pages, or modify
  PATH; diagnostics provide official sources and copyable manual commands.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Windows first-install packaging accepts Inno Setup `>= 6.7.3, < 8.0.0`, with CI pinned to 7.0.2.
  Fresh installs default to `%LOCALAPPDATA%\Programs\<publisher>\<display_name>` while `app_id`
  remains the stable installer, updater, and publishing identity. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `nexora build` defaults to the `rustc -vV` host target and treats `targets.required` as a legacy
  compatibility source. Interactive builds select channels; CI uses explicit `--channel` or
  `--all-channels`. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Publish credentials fall back field by field through channel-specific `NEXORA_PUBLISH_*`, base
  `NEXORA_PUBLISH_*`, and `AWS_*`. Build numbers use local-time `yyMMddHHmmss` while remaining
  strictly increasing. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- The Windows sidecar carries the main EXE name already verified from the update ZIP into preflight,
  health launch, and failure recovery instead of scanning the installation directory. Inno Setup's
  `unins000.exe` no longer causes a multiple-main-EXE failure. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- After the Windows directory switch, the sidecar preserves `unins<digits>.exe/.dat/.msg` from the
  rollback backup and rejects staged collisions, keeping the Apps & Features uninstall entry valid.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Windows tooling detection validates the actual compiler-engine version of every Inno Setup 6/7
  candidate, ignores broken or incompatible candidates, and selects the highest compatible one.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Removed

- Removed `nexora doctor --fix`, CLI host-dependency installation paths, and the standalone
  `windows-tooling.yml` workflow. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Removed `credential_env_prefix` from `nexora.toml`; `RUSTFS_*` is no longer a publish credential
  source. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- Automation must replace `nexora doctor --fix` with `nexora doctor` and let an operator or build
  image run the reported manual installation commands.
- Publish configuration must remove `credential_env_prefix` and use
  `NEXORA_PUBLISH_<CHANNEL>_<FIELD>`, `NEXORA_PUBLISH_<FIELD>`, or `AWS_<FIELD>`.
- Every updater-enabled release/channel must configure a readable UTF-8 Markdown `release.notes`.
- `publisher` and `display_name` must be safe Windows directory components. The new default affects
  only fresh installs; existing Inno Setup installations retain their directory.
- This release does not change the HTTP API, Account DTOs, or SQLx baseline. Projects that completed
  the v0.31.1 PostgreSQL 17 rebuild do not need another database rebuild.

## Upgrading from 0.31.1

1. Update all Nexora dependencies and the CLI to `v0.32.0`, then regenerate workspace and example lockfiles.
2. Remove `credential_env_prefix` and add `notes = "path/to/notes.md"` to updater-enabled releases.
3. Replace automated `doctor --fix` calls with read-only `doctor`; prepare dependencies in the build
   image or through an explicit manual step.
4. Review Windows `publisher`, `display_name`, and the fresh-install default directory. Existing
   installations do not move.
5. Sync `.agents/skills/develop-nexora-updater` and the CLI templates, then rebuild the first-install
   package and update ZIP.

Rolling back to v0.31.1 requires restoring the CLI, framework dependencies, lockfile, and previous
publish configuration together. This release does not require a database rollback, but the v0.31.1
PostgreSQL 17 baseline rules still apply.
