# Nexora 0.22.0

Release date: 2026-08-03

## Summary

Build now resolves and freezes a release identity before any target starts. It can read SemVer from
the selected Cargo package and generate a strictly increasing UTC build number. Publish, dry-run,
and yank consume only the build receipt and never recompute dynamic values.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none.

## Added

- `release.version` accepts the exact `${CARGO_PKG_VERSION}` field and resolves the final version of
  `apps.<app>.package` with `cargo metadata --no-deps --format-version 1`. Package-local `version`
  and `version.workspace = true` are both supported. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- `release.build_number` accepts the exact `${BUILD_DATETIME}` field and produces a positive `u64`
  in UTC `yyMMddHHmmss` format. Same-second builds and clock rollback use the greater of the current
  UTC value and the previous local build number plus one. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Before any target starts, build atomically writes `dist/<app>/<channel>/release.json` containing
  the schema, app, package, channel, final version/build number, both sources, signed Unix creation
  second, and planned targets. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Every target in one build shares the frozen identity. An incomplete retry reuses a matching
  receipt; an explicit dynamic build after completion creates a strictly higher number while
  retaining old versioned artifacts. Corrupt or unsupported receipts fail before compilation. —
  Owner: [@Jixiangup](https://github.com/Jixiangup)
- Publish, dry-run, and yank read identity from the receipt and validate current configuration, the
  selected Cargo package version, required targets, every `artifact.json`, file existence, size,
  and SHA-256 before upload. An available release must be strictly greater than remote
  `(version, build_number)`, and publish still never invokes build. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- New scaffolds default to `${CARGO_PKG_VERSION}` and `${BUILD_DATETIME}`. Literal SemVer and
  positive integers remain compatible; unknown expressions, fragments, `${CARGO_VERSION}`,
  arbitrary environment variables, zero, and overflow fail explicitly. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- macOS applications continue to copy the configured ICNS into `Contents/Resources` and set
  `CFBundleIconFile`. DMG files and mounted volumes retain the system-default appearance without a
  separate branded icon. ZIP and DMG are produced from the same resource-complete, signed `.app`.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility

There are no breaking changes. Existing `release.version = "1.2.3"` and
`release.build_number = 42` configurations remain valid; dynamic expressions must occupy the whole
field. Updater clients still compare `(version, build_number)`, and manifest sequence retains its
existing replay-protection responsibility.

This release adds no Windows or Linux packaging, general template engine, or arbitrary environment
variable interpolation.

## Upgrade from 0.21.3

1. Move every Nexora dependency to `v0.22.0` and regenerate lockfiles.
2. Synchronize `.agents/skills/develop-nexora-updater`; its protocol now documents build receipts
   and dynamic release identity.
3. Keep literal values, or adopt the new defaults:

   ```toml
   [apps.<app>.release]
   version = "${CARGO_PKG_VERSION}"
   build_number = "${BUILD_DATETIME}"
   ```

4. Run `nexora build --app <app>`, inspect `dist/<app>/<channel>/release.json`, then run
   `nexora publish --app <app> --dry-run`.

## Validation

- `cargo fmt --all --check`
- `cargo check --workspace`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p nexora -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

Automated coverage includes dynamic/literal configuration, package and workspace versions,
multi-app selection, UTC and monotonic build numbers, receipt retries, frozen publish identity,
artifact integrity, and `.app` ICNS/`CFBundleIconFile`. Real Developer ID signing, notarization, DMG
mounting, and installed-update behavior were not verified in this release environment.
