# Nexora 0.17.0

Release date: 2026-07-28

This release remains in the `0.x` beta phase and does not enter the `1.x` stable channel. The
version uses the standard SemVer value `0.17.0`. This release adds an application-level action
extension point for the desktop Shell panel header so host applications can place stable entries on
the right side of every business page `PanelHeader`.

## Added

- Added the public `PanelHeaderAction` and `install_panel_header_actions` APIs. Host applications can install a list of `Fn(&mut App) -> impl IntoElement` actions during startup; the framework renders them on the right side of business page `PanelHeader`s before the built-in current-tab pin toggle. Owner: [@zhutao525](https://github.com/zhutao525)
- Re-exported the panel-header action APIs from the `nexora::desktop` facade and the `nexora` desktop-feature crate root so applications do not depend on the internal `application` module. Owner: [@zhutao525](https://github.com/zhutao525)

## Changed

- Updated the root workspace version, internal workspace dependency constraints, CLI installation examples, and changelog indexes to `0.17.0`. Owner: [@zhutao525](https://github.com/zhutao525)

## Issues and PRs

- Issues: none. This release comes from the iMES host application's need for a generic desktop framework extension point in the panel header.
- PRs: none. Per the current release flow, this is committed, tagged, and released directly from the `codex/panel-header-actions-v0.17.0` branch.

## Compatibility and breaking changes

- No breaking changes. Existing applications keep the same Shell behavior when they do not install panel-header actions.
- The new public APIs are backward-compatible functionality additions. Per the current Nexora `0.x` version policy, this increments minor and upgrades from `0.16.0` to `0.17.0`.

## Upgrade

1. Update the Nexora tag to `v0.17.0` and refresh the lockfile.
2. To add application-level entries on the right side of every business page header, construct a list of `PanelHeaderAction`s during desktop application startup and call `install_panel_header_actions(actions, cx)`.
3. A later `install_panel_header_actions` call replaces the previous list; pass an empty list to clear installed actions.
4. The action render closure should only read application state and build elements. Navigation, dialogs, or business operations should live in the element event callbacks.
5. This release contains no database migrations and requires no extra data-upgrade step.
