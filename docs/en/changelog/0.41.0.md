# Nexora 0.41.0

Release date: 2026-08-19

This release adds an explicit Alibaba Cloud OSS provider to `nexora publish`, fixing HTTP 400
responses caused by an incompatible immutable-upload condition header on the S3-compatible endpoint.
Generic S3 behavior and publish ordering remain unchanged.

## Added

- `[publish.targets.<name>]` and channel overrides now accept `provider = "aliyun_oss"`. Immutable
  versioned objects, checksums, release notes, and sequence manifests use
  `x-oss-forbid-overwrite: true`, included in the AWS SigV4 canonical headers, so an existing release
  object cannot be overwritten.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

## Changed

- Publish providers are now a constrained configuration enum. Generic S3 remains explicit as
  `provider = "s3"` and continues to send `If-None-Match: *` for immutable objects. Nexora does not
  infer providers from endpoint hostnames. Channel-root branded objects and the final `latest.json`
  remain replaceable.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- Configuration reference, updater documentation, protocol Skill, and new-project scaffold now
  document both providers and their overwrite-protection semantics.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

## Fixed

- Fix Alibaba Cloud OSS rejecting `If-None-Match: *` on its S3-compatible endpoint, which caused the
  first immutable EXE/ZIP upload to return HTTP 400 before branded objects and `latest.json` could be
  published.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- Simplify two equivalent Boolean expressions to the Rust 1.96 Clippy form so the workspace keeps
  passing with `-D warnings`. CRUD Panel and Nexora lint runtime behavior is unchanged.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

## Compatibility and breaking changes

- This is a backward-compatible feature release from `v0.40.3`. Existing `provider = "s3"`
  configurations and S3/RustFS/MinIO behavior are unchanged.
- Alibaba Cloud OSS projects must explicitly set `provider = "aliyun_oss"` on the target or channel
  override. Endpoint, bucket, region, virtual-hosted style, and public download URL remain explicit.
- There are no public Rust API, HTTP API, database schema, updater-manifest schema, release-receipt
  schema, or object-layout changes. `docs/public/openapi.yaml` only synchronizes release metadata to
  `0.41.0`.
- There are no breaking changes or data migrations. Before rolling back to `v0.40.3`, restore the
  provider to the old parser-supported `s3` value, noting that the old immutable upload may still
  receive HTTP 400 from Alibaba Cloud OSS.

## Upgrading from 0.40.3

1. Update all Nexora Git dependencies and CLI installation tags from `v0.40.3` to `v0.41.0`, then run
   `cargo update`.
2. Keep `provider = "s3"` for generic S3/RustFS/MinIO. For Alibaba Cloud OSS, set
   `provider = "aliyun_oss"` on the base target or channel, configure the correct region, and keep
   `force_path_style = false`.
3. Synchronize `.agents/skills/develop-nexora-updater`, run a publish dry-run, then perform a real
   publish and verify anonymous reads of immutable objects, channel-root branded objects, the
   sequence manifest, and `latest.json`.
