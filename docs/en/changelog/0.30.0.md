# Nexora 0.30.0

Release date: 2026-08-06

## Summary

This release completely replaces cargo-wix, WiX 5, MSI, and Burn for first-time Windows
installation with pinned Inno Setup 6.7.3. nexora build now produces only a Simplified Chinese
Setup EXE and a sidecar update ZIP. In-app updates, Ed25519 manifests, SHA-256 validation, safe
extraction, same-volume transactional replacement, health checks, rollback, and S3 publish ordering
remain unchanged.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- Added a framework-maintained static Inno Setup .iss template with a modern Simplified Chinese
  wizard, current-user installation, directory selection, desktop/Start menu shortcuts,
  launch-after-finish, standard silent flags, and running-main-process shutdown.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added strict ISCC preprocessor validation for Unicode, spaces, quotes, control characters,
  invalid Windows paths, the Inno AppId length, and separate x86_64/ARM64 architecture gates.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- nexora build and nexora doctor --fix now require exact Inno Setup 6.7.3. Interactive Windows
  terminals can repair it through winget's official JRSoftware.InnoSetup package; non-interactive
  environments receive the complete command only. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Windows installation is fixed to the unelevated current-user scope under
  %LOCALAPPDATA%\Programs\<app_id> by default. Later installers with the same AppId perform an
  in-place Inno upgrade. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Setup EXE and update ZIP share one staging directory containing the configured, signed main
  executable, updater sidecar, updater configuration, runtime configuration, and release resources.
  The final Setup EXE continues to use the existing optional Authenticode boundary.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Windows artifact.json now records only windows_setup_exe and windows_update_zip. Publish uploads
  both artifacts and checksums, while signed latest.json still references only windows_update_zip.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Updated the develop-nexora-updater Skill, scaffold copy, Windows updater example, and bilingual
  configuration/updater documentation to match the Inno Setup install, build, publish, and
  real-device acceptance contract. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Removed

- Removed cargo-wix, the WiX CLI, WiX UI/Bootstrapper extensions, the Nexora-managed .NET SDK,
  dynamic .wxs generation, MSI packaging, and Burn bundle construction.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Removed platforms.windows.installer, platforms.windows.install_scope, WindowsMsi, msi_path, and
  the windows_msi publish artifact contract. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

This is a breaking configuration and artifact-contract change. v0.30.0 does not read the former
Windows installer selector or machine-scope field, and no longer generates, validates, or publishes
MSI files. The project had not formally released the old WiX/MSI installer, so this release does not
migrate old installation records, UpgradeCodes, or uninstall entries.

Old configuration:

~~~toml
[apps.desktop.platforms.windows]
icon = "assets/logos/desktop/logo-icon.ico"
installer = "wix"
install_scope = "user"
publisher = "Example Publisher"
~~~

New configuration:

~~~toml
[apps.desktop.platforms.windows]
icon = "assets/logos/desktop/logo-icon.ico"
publisher = "Example Publisher"
~~~

## Upgrading from 0.29.0

1. Update all Nexora workspace dependencies to 0.30.0 or Git tag v0.30.0, regenerate lockfiles,
   and reinstall the v0.30.0 CLI.
2. Remove installer and install_scope from every app's Windows configuration; current-user scope is
   now fixed by the framework.
3. Update internal scripts that consume artifact.json or publish directories: remove windows_msi
   and require only windows_setup_exe, windows_update_zip, and their .sha256 files.
4. Run nexora doctor --fix on Windows builders to install pinned Inno Setup 6.7.3 and the Windows
   SDK, then rerun nexora build.
5. Manually sync .agents/skills/develop-nexora-updater in downstream projects. Existing Skills are
   not overwritten by nexora init; replace the updater protocol with the v0.30.0 scaffold copy.
6. Before production release, run Windows 11 smoke tests for x86_64/ARM64 builds, interactive/silent
   install and uninstall, in-place upgrades, running-process handling, and sidecar update rollback.

Rolling back to v0.29.0 requires restoring the former configuration fields, WiX/.NET build
dependencies, and MSI-aware artifact consumers together. Do not make v0.29.0 publish consume a
v0.30.0 two-artifact artifact.json.
