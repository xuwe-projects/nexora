# Nexora 0.21.2

Release date: 2026-08-03

## Summary

This patch fixes macOS updater health restarts where the default configuration loader interpreted
the internal health flag as a TOML path, terminated the replacement process, and forced the sidecar
to roll back.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none.

## Fixed

- `nexora::config::initialize(None)` now ignores
  `--nexora-updater-health-session` / `--nexora-updater-health-file` when either is the first
  argument and continues with the application default configuration path. Explicit paths and
  ordinary positional arguments are unchanged. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added regression tests for updater health arguments and ordinary configuration paths. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Documentation

- Documented configuration loading during the `install_updater` sidecar health launch. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Compatibility

There are no breaking changes. Desktop applications using `initialize(None)` need no source change;
upgrade and rebuild so sidecar arguments can coexist with default configuration loading.

## Upgrade from 0.21.1

1. Move every Nexora dependency to `v0.21.2` and regenerate the lockfile.
2. Rebuild the `.app.zip`, DMG, and sidecar; older clients can install the newly built payload.
3. Verify real replacement, health confirmation, and failure rollback.
