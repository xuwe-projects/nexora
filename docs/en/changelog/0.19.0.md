# Nexora 0.19.0

Release date: 2026-07-29

This release remains in the `0.x` beta phase and does not enter the `1.x` stable channel. The
version uses the standard SemVer value `0.19.0`. This release removes every Account capability that
uploads, stores, synchronizes, or exposes user avatar data. It is a breaking release: all
`avatar_url` fields, avatar HTTP APIs, avatar permissions, avatar-storage injection points, and
related public Rust APIs are removed.

## Removed

- Removed `UserResponse.avatar_url`, `ProvisionUserRequest.avatar_url`, `AvatarUploadResponse`, and
  `UpdateUserAvatarRequest` from Account contracts. Owner: [@zhutao525](https://github.com/zhutao525)
- Removed avatar fields from Account entities, `ExternalIdentity`, `CreateHumanIdentity`,
  `VerifiedIdentity`, store queries, `FromRow` mappings, and local-account writes. Owner:
  [@zhutao525](https://github.com/zhutao525)
- Removed `POST /avatars` and `PATCH /users/{user_id}/avatar`, including handlers, router entries,
  body limits, OpenAPI descriptions, and client methods. Owner: [@zhutao525](https://github.com/zhutao525)
- Removed `AvatarStorage`, `LocalAvatarStorage`, `AvatarUpload`, `AvatarStorageError`,
  `AccountDependencies::avatar_storage`, and the public `nexora::server`/`nexora::account`
  re-exports. Owner: [@zhutao525](https://github.com/zhutao525)
- Removed the ZITADEL avatar metadata key, write path, read fallback, update path, and compensation
  logic. Account no longer maps OIDC `picture` claims into local user profile data. Owner:
  [@zhutao525](https://github.com/zhutao525)

## Changed

- Default user management and the application-shell account area still render the gpui-component
  `Avatar`, but only from `display_name`/name initials or the default icon. They no longer call
  `.src(...)` or read image URLs. Owner: [@zhutao525](https://github.com/zhutao525)
- The default user-provisioning form no longer shows an "Avatar URL" field, while the circular
  marker before user names remains in the list layout. Owner: [@zhutao525](https://github.com/zhutao525)
- Account current-user refresh synchronizes directory username, email, display name, and last-login
  time only; it no longer synchronizes avatars. Owner: [@zhutao525](https://github.com/zhutao525)

## Database

- Added the append-only SQLx migration `202607290001_account_remove_avatar_capability`. It removes
  the `users:avatar.write` permission and built-in role grants, then drops
  `account.users.avatar_url`. The migration permanently deletes historical avatar URL data; it does
  not migrate or backfill those values. Owner: [@zhutao525](https://github.com/zhutao525)
- The migration version is intentionally greater than iMES' current immutable historical migration
  `202607180006_system_dictionary_seed_standard_catalogs`. On an empty database, the current iMES
  seed can still run its old `INSERT INTO account.users (...)` that mentions `avatar_url`, and Nexora
  `202607290001` drops the column afterwards. Existing databases that already applied the high iMES
  migration only see a higher Nexora migration pending, avoiding SQLx low-version/out-of-order risk.
- No previously released migration such as `0001_account_create_rbac` or
  `0009_account_add_user_avatar_permission` was modified, and `_sqlx_migrations` checksums were not
  repaired or patched.

## Documentation

- Updated OpenAPI, HTTP API docs, Rust API docs, desktop Account docs, README install commands, and
  scaffold Skill examples to remove obsolete avatar upload, Avatar URL, and AvatarStorage guidance.
  Owner: [@zhutao525](https://github.com/zhutao525)

## Compatibility and breaking changes

- Breaking change: every `avatar_url` JSON contract field is removed. User-provisioning requests that
  still include `avatar_url` are rejected by `deny_unknown_fields`.
- Breaking change: `POST /avatars` and `PATCH /users/{user_id}/avatar` are no longer registered; API
  callers should treat them as missing routes.
- Breaking change: the `users:avatar.write` permission and built-in admin grant are removed by
  migration. Custom roles should no longer reference that permission.
- Breaking change: `AvatarStorage`/`LocalAvatarStorage`/`AvatarUpload`/`AvatarStorageError` and
  `AccountDependencies::avatar_storage` are removed. Hosts must delete related configuration and
  dependency injection.
- Breaking change: `ExternalIdentity`, `CreateHumanIdentity`, `VerifiedIdentity`, `User`, and Account
  DTOs no longer contain avatar fields. Downstream struct literals, DTO access, and serialization
  tests must be updated.
- The upgrade migration permanently drops `account.users.avatar_url` and the historical data in that
  column. The down migration can only restore the old shape and permission, not the deleted data.
- The visual initial/default `Avatar` remains. It is only a user identity marker and does not mean
  Nexora still manages uploadable avatar data.

## Upgrade

1. Update the Nexora tag to `v0.19.0` and refresh the lockfile.
2. Remove `AccountDependencies::avatar_storage` and all `AvatarStorage`/`LocalAvatarStorage`
   configuration from server composition roots.
3. Delete client calls and assertions for `upload_avatar`, `update_user_avatar`,
   `AvatarUploadResponse`, `UpdateUserAvatarRequest`, and `avatar_url`.
4. Continue merging Nexora and host migrations into one SQLx `Migrator`, and do not edit published
   historical migrations. Current iMES history is compatible because `202607180006 < 202607290001`.
5. Future or updated iMES migrations must stop writing `account.users.avatar_url`; the current
   immutable historical seed does not need to be modified.
6. If the UI still needs a circular user marker, render initials/default icons with
   `Avatar::new().name(display_name).small()` and do not read or pass image URLs.
