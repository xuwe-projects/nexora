# Nexora 0.41.1

Release date: 2026-08-20

This release fixes frozen runtime-configuration loading for formal packages launched outside a
source checkout, and standardizes how downstream applications author Updater `release.notes`.
In-app notes now target end users, while GitHub Releases and developer changelogs retain complete
technical information.

## Fixed

- `nexora::config::initialize(None)` now locates a formal package's resource directory through the
  current executable and a valid `nexora-release.json`. macOS reads
  `Contents/Resources/config`; Windows reads the EXE-sibling `config` directory. Neither path
  depends on cwd or a source checkout.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- Missing, unreadable, or invalid frozen configuration in a formal package now fails explicitly
  instead of falling back to development configuration. Explicit paths, user positional arguments,
  and environment overrides retain their precedence. Updater health argument pairs are never
  mistaken for a configuration path.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- Add regression coverage for macOS and Windows resource locations, formal/development precedence,
  failure boundaries, and nightly/beta/stable channel configuration freezing.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

## Changed

- The `publish-nexora-release` Skill now authors end-user Updater `release.notes` separately for
  updater-enabled applications. The heading version comes from the selected app's resolved Cargo
  package, and the date comes from release preparation. Empty categories are omitted completely;
  Important Notices appear only when users must act or pay special attention.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- In-app notes translate internal crate, API, database, CI, and Updater implementation changes into
  user-visible outcomes and stop when user impact cannot be established. GitHub Releases and
  developer changelogs still retain owners, Issue/PR links, breaking changes, upgrade steps, and
  validation results.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

- Synchronize the CLI scaffold Skill mirror, Skill metadata, bilingual CLI/Updater documentation,
  and generated-project regression assertions. Updater runtime still only validates, freezes,
  signs, publishes, and renders safe Markdown; it does not parse the new headings or categories.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: none

## Compatibility and breaking changes

- This is a backward-compatible patch for `v0.41.0`. It adds or removes no public APIs, HTTP
  routes, database structures, manifest schemas, signing protocols, or publish object layouts.
- Formal packages must carry a valid `nexora-release.json` and frozen configuration generated by
  the updated CLI. A normal `nexora build` satisfies this contract automatically.
- `docs/public/openapi.yaml` only updates its release metadata version to `0.41.1`; the API contract
  is unchanged.
- There are no breaking changes and no manual data migrations.

## Upgrading from 0.41.0

1. Update every Nexora Git dependency and CLI installation tag from `v0.41.0` to `v0.41.1`.
2. Run `cargo update` and confirm that Nexora workspace packages in `Cargo.lock` resolve to
   `v0.41.1`.
3. Synchronize `.agents/skills/develop-nexora-apps`,
   `.agents/skills/develop-nexora-updater`, its `references/updater-protocol.md`, and
   `.agents/skills/publish-nexora-release`. Newly generated projects already carry the synchronized
   Skills.
4. Rebuild formal installers with the updated CLI and verify that each real channel, such as
   nightly, beta, or stable, reads its own frozen `runtime_config`.

cross-host signing and installation environments were not run.
