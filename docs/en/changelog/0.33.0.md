# Nexora 0.33.0

Release date: 2026-08-08

## Summary

This release introduces a unified singleton-main-process and managed multi-window runtime for
Nexora desktop applications. Additional Shell, Settings, and registered Window instances run in
main-managed child processes by default. The authenticated window group synchronizes sessions,
preferences, and Account state, with cross-launch restoration, native system trays, and persistent
DataTable column layouts.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- Added an application-identity singleton gate, one-time handshake credentials, session tokens,
  bounded message frames, and main-supervised child lifecycles. A second launch activates the
  existing window group; coordinated shutdown broadcasts a reason before bounded cleanup.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added a `workspace.toml` window-session model for complete routes, tab ordering, pinned
  partitions, active tabs, display UUIDs, window bounds, and minimized state. Missing displays
  fall back to the visible area of the primary display. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added native macOS/Windows notification-area trays and a Linux StatusNotifierItem implementation
  without GTK/AppIndicator. Closing the main window can exit, minimize to tray, or cancel.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added tab dragging, pinned-partition constraints, a full-route “Open in New Window” action, and
  close confirmation using gpui-component `TabBar`, `PopupMenu`, and `AlertDialog`.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added `DataTableLayoutKey`, `DataTableLayout`, `PersistentDataTableDelegate`, and convenience
  constructors to restore column ordering and widths from stable Feature/Table/Column IDs while
  respecting fixed, non-movable, and width constraints. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `ApplicationOptions` now enables singleton execution, subprocess windows, session restoration,
  and tray support by default, with builders for those switches, shutdown timeouts, identity
  overrides, and tray-unavailable fallback behavior. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Desktop Account sessions are now published by the main process. Child processes receive login,
  token-cache, access-profile, and remote-sign-out state through authenticated IPC, preventing
  concurrent refresh of the same OIDC session. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- User preferences now use main-process field-level merges and window-group broadcasts. The config
  store adds cross-process locking, unique temporary files, durable flushes, and atomic replacement
  while preserving unknown same-schema fields. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Concurrent windows updating different preference fields no longer overwrite one another, and
  temporary files are cleaned precisely on successful and failed writes.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- A future `workspace.toml` schema now disables writing and preserves the original file instead of
  replacing unknown data with the current representation. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Route identities now serialize the full canonical path/query deterministically while preserving
  same-key query ordering, so restored windows retain dynamic and query context.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- This is a desktop default-behavior change in the `0.x` series: singleton execution, subprocess
  windows, restoration, and tray support are enabled after upgrading. Applications that need the
  v0.32.0 single-process behavior must explicitly call
  `.single_instance(false).subprocess_windows(false).restore_window_sessions(false).tray_enabled(false)`.
- Direct `ApplicationOptions` struct literals must initialize the new fields. Prefer
  `ApplicationOptions::new()` with builders, or add `..Default::default()`.
- Legacy v0.32.0 window preferences migrate to the current `workspace.toml` schema on first read;
  no manual conversion is required. Back up or remove the new file before rolling back so an older
  release does not silently ignore new window-session fields.
- Persisted tables need stable Feature, table, and column IDs. Removed columns are ignored and new
  columns append in code order; display text, array indexes, and random values are not stable keys.
- This release does not change the HTTP API, Account DTOs, SQLx migrations, or PostgreSQL baseline.

## Upgrading from 0.32.0

1. Update all Nexora dependencies and the CLI to `v0.33.0`, then regenerate workspace and application lockfiles.
2. Review `ApplicationOptions` construction and either accept the new strong defaults or explicitly
   disable process, restoration, and tray behavior that the application does not need.
3. Use `persistent_data_table_state` or `persistent_crud_table_state` for tables that should persist
   layout, with a long-lived business key for every column.
4. Validate tray behavior, second-launch activation, close confirmation, display removal/restoration,
   and abnormal child cleanup on every supported target platform.
5. This release does not modify scaffold skills, macro rules, or generated-project constraints;
   downstream projects do not need to sync `.agents/skills`.

Rolling back to v0.32.0 requires restoring framework dependencies, the CLI, and lockfiles together.
No database rollback is required. Back up or remove the v0.33.0 `workspace.toml` before letting the
older version recreate compatible preferences.

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets --locked`
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
- `cargo run -p cli --locked -- lint --workspace . --deny-warnings`
- `scripts/check-scaffold-consumer.sh`
- `bun install --frozen-lockfile && bun run build` in `docs/`
- Isolated Linux and Windows tray-module cross-compilation, plus native macOS compilation

This run did not perform real Windows/Linux tray interaction, multi-display session restoration,
or abnormal-child-recovery acceptance. Full Linux workspace cross-compilation remains limited by
the release host's missing `x86_64-linux-gnu-gcc`. External PostgreSQL, OIDC, signing, notarization,
and real S3/RustFS publishing tests were not run; this release contains no database migration.
