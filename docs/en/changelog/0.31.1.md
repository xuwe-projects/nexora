# Nexora 0.31.1

Release date: 2026-08-07

## Summary

This release combines the Windows Inno Setup fixes from v0.30.2 with the PostgreSQL 17 Account
migration baseline fix in one release commit. v0.31.0 was based on v0.30.1 because of a concurrent
release race and is superseded by this version; its public tag remains immutable.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Fixed

- Fixed the first framework migration failing on an empty PostgreSQL 17 database because named
  column-level `NOT NULL` declarations are not independent `pg_constraint` objects there. The new
  baseline preserves every `NOT NULL` semantic and column comment.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Preserved the v0.30.2 fixes for Inno Setup arguments, native compilation coverage, the Simplified
  Chinese language path, and embedded language resources.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Fixed the Windows invalid Inno path fixture creating an invalid directory before production
  validation was reached. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Regenerated four reversible timestamp framework baselines through the SQLx CLI. Account tables,
  indexes, protection functions, and seeded permission semantics are unchanged.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- PostgreSQL 17 is the minimum supported database version for framework migrations. Column-level
  nullability uses `NOT NULL` plus `COMMENT ON COLUMN`.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

This release establishes a new framework SQLx baseline and is migration-breaking:

- `nexora._sqlx_migrations` from v0.29.0 through v0.30.2 is incompatible with v0.31.1.
- Do not rewrite old checksums, delete only history and run against an old schema, or move a public
  tag.
- Existing deployments must back up and verify recovery before rebuilding an empty database. Run
  `nexora::server::migrate(&pool)` before the application migrator on the new database.
- HTTP APIs, Account DTOs, authentication and authorization semantics, updater protocol, and the
  `nexora.toml` schema are unchanged.

## Upgrading from 0.30.2

1. Stop the service, back up the database and retained business data, and perform a restore drill.
2. Update all Nexora dependencies and the CLI to Git tag `v0.31.1`, then regenerate the lockfile.
3. Drop the old database and create an empty UTF-8 database. Do not remove only schemas or history.
4. Run the Nexora v0.31.1 migrator on the host pool, then run the application migrator.
5. Restore only approved data through an audited import; do not restore old DDL, history, or
   checksums.

Rollback requires the v0.30.2 binaries, dependencies, lockfile, and pre-upgrade database snapshot
together. v0.31.1 down migrations are not a legacy-history conversion tool.
