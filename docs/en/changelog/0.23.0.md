# Nexora 0.23.0

Release date: 2026-08-03

## Summary

This release completes the Windows x86_64 desktop release path. `nexora build` can now produce an
NSIS 3 Unicode `Setup.exe` and a self-update ZIP, and the Windows updater sidecar can safely
extract, verify, and apply the update payload. Setup.exe is a first-install artifact only; updater
manifests reference only `windows_update_zip`, and MSI is not generated or run.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none.

## Added

- Windows targets now support `windows_setup_exe` and `windows_update_zip` artifacts. Publish
  uploads Setup.exe as the first-install artifact while writing only `windows_update_zip` into the
  updater payload list. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Windows NSIS packaging configuration supports user/machine scope, publisher, desktop-shortcut
  default, launch-after-install default, minimum Windows build, Authenticode thumbprint, and
  timestamp URL. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The Windows updater runtime now validates update ZIPs with path-escape rejection, duplicate and
  missing-file checks, reparse-point protection, main executable and sidecar signature identity
  checks, and a sidecar replacement entry point. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Added `examples/updater-windows` for validating Setup.exe, update ZIPs, a local RustFS/S3 feed,
  and sidecar update flow on Windows x86_64 hosts. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora doctor` and build dependency checks now support Windows hosts and detect `rc.exe`,
  `makensis.exe`, and `signtool.exe`; NSIS installer scripts are written with Unicode-safe
  encoding. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Build and publish target/artifact validation now branch by macOS or Windows platform while
  preserving the existing macOS `.app.zip` and DMG behavior. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Packaging examples and installation documentation now reference Nexora `v0.23.0`. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Release receipt atomic writes no longer try to sync a directory handle on Windows, avoiding
  access-denied failures before build starts. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Updater bundle configuration now requires Windows signing thumbprint and publisher checks to be
  configured together, avoiding partial identity verification. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Compatibility

There are no breaking changes. Existing macOS artifact names, DMG aliases, and updater manifest
kinds remain compatible. The runtime still recognizes the legacy Windows `windows_zip` kind; new
builds and publish manifests use `windows_update_zip`.

Starting with this release, Windows first-install output is an NSIS `*.setup.exe`, not an MSI.
Self-update downloads and applies only `*.windows.zip`; it does not download or run Setup.exe.

## Upgrade from 0.22.0

1. Move every Nexora dependency to `v0.23.0` and regenerate lockfiles.
2. For Windows apps, complete `platforms.windows` in `nexora.toml`, including ICO,
   `installer = "nsis"`, `install_scope`, `publisher`, and signing policy.
3. Install NSIS 3 Unicode and the Windows SDK `rc.exe`/`signtool.exe` on Windows release hosts, and
   prepare an Authenticode certificate. Keep updater private keys in files or environment secrets
   only.
4. Run `nexora build --app <app>` and confirm `artifact.json` contains only `windows_setup_exe` and
   `windows_update_zip`, with updater manifests referencing only the ZIP.
5. Run `nexora publish --app <app> --dry-run`; once anonymous URL, SHA-256, and signed
   `latest.json` checks pass, run the real publish.
