# Nexora 0.23.0

Release date: 2026-08-03

## Summary

This release unifies desktop settings and legacy migration, persists CRUD DataTable layout and
backend sorting, and adds complete multi-app, multi-channel build/publish/yank planning with
channel runtime config and generated updater feeds.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none.

## Added

- Desktop preferences now live at `~/.xuwe/<cargo-package>/settings.json`. First upgrade reads a
  legacy `workspace.toml` only when the JSON file is absent, atomically writes JSON, and retains the
  legacy file. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- `CrudTableDelegate` now snapshots column order, width, and single-column backend sorting.
  `CrudTableRow` supports `sort_field`, while `persistent_crud_table_state` connects a stable
  `table_id` to shared settings, native column events, and backend reload callbacks. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- `release.channels` lets one app declare nightly, beta, stable, or other safe channels, merging
  root defaults with per-channel version, build number, minimum-version, and runtime-config
  overrides. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Build, publish, and yank accept repeatable `--app` / `--channel` plus `--all-apps` /
  `--all-channels`. Interactive mode multi-selects; non-interactive mode uses each default channel.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora::config::initialize(None)` now resolves explicit paths, a valid command-line TOML,
  standard app-bundle resources, then local base config. Channel builds select explicit,
  conventional channel, or base config and copy it to
  `Contents/Resources/config/<package>.toml` before signing. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Multi-channel updater feeds are derived from the publish target, public base URL, object prefix,
  app key, and channel. Release receipts use schema 2 and record the runtime-config relative path,
  SHA-256, and final feed; artifacts remain channel-isolated. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Every selected build/publish/yank pair completes read-only preflight before compilation or remote
  mutation. Builds run sequentially and report completed, failed, and pending pairs. Scaffolds, CLI
  help, bilingual docs, and packaged Skills now follow the new model. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

- Breaking: every `nexora::Application` implementation must add
  `const PACKAGE_NAME: &'static str = env!("CARGO_PKG_NAME");` for the stable Settings directory.
- Legacy single-channel `release.channel` and its matching static `updater.feed_url` remain
  compatible. New `release.channels` cannot be mixed with either legacy field or a non-empty static
  feed.
- Schema 1 release receipts are not accepted by the schema 2 publisher; rebuild after upgrading.
- This release still does not claim Windows or Linux installer implementation.

## Upgrade from 0.22.0

1. Move every Nexora dependency to `v0.23.0`, regenerate lockfiles, and add `PACKAGE_NAME` to every
   application implementation.
2. Confirm settings are written to `~/.xuwe/<package>/settings.json`; the old `workspace.toml` is
   retained.
3. For persistent tables, provide a stable `table_id`, map backend fields with `sort_field`, read
   restored sorting before the first request, and reset to page one on sort changes.
4. Migrate to `release.default_channel` and `release.channels.<name>`, remove static
   `updater.feed_url` in multi-channel mode, and list every release channel in `updater.channels`.
5. Create secret-free `config/<package>-<channel>.toml` files or keep
   `config/<package>.toml` as fallback. Treat bundled runtime config as public data.
6. Rebuild each channel to create schema 2 receipts before running its publish dry-run.
