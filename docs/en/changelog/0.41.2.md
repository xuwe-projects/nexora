# Nexora 0.41.2

Release date: 2026-08-20

This release fixes a Windows desktop crash caused by re-entering the same GPUI `TableState` when
a standard CRUD table scrolls into a data range that has not been loaded yet.

## Fixed

- `CrudListState` now defers visible-range prefetching until the current DataTable callback has
  returned. Requesting the next page can no longer write sparse-row state while `TableState` still
  holds its mutable lease.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: [xuwe-projects/imes#299](https://github.com/xuwe-projects/imes/issues/299)

- Add a deterministic GPUI regression test that triggers a visible-range change while the table
  state is leased and verifies that the next page is still prefetched without a double-lease panic.

  — Owner: [@Jixiangup](https://github.com/Jixiangup)
  — Related issue/PR: [xuwe-projects/imes#299](https://github.com/xuwe-projects/imes/issues/299)

## Compatibility and breaking changes

- This is a backward-compatible patch for `v0.41.1`. It adds or removes no public APIs, visible
  components, HTTP routes, database structures, Updater manifest schemas, signing protocols, or
  publish object layouts.
- Pagination, page caching, sparse skeletons, and visible-range prefetch behavior are unchanged;
  only the scheduling boundary for prefetching has moved.
- `docs/public/openapi.yaml` only updates its release metadata version to `0.41.2`; the API contract
  is unchanged.
- There are no breaking changes and no manual data migrations.

## Upgrading from 0.41.1

1. Update every Nexora Git dependency and CLI installation tag from `v0.41.1` to `v0.41.2`.
2. Run `cargo update` and confirm that Nexora workspace packages in `Cargo.lock` resolve to the
   commit for `v0.41.2`.
3. Rebuild the desktop application and regress standard CRUD tables, such as customers and
   suppliers, while scrolling across page boundaries.
4. This release changes no Skills or protocols, so `.agents/skills` does not need synchronization.
