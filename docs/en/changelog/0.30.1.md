# Nexora 0.30.1

Release date: 2026-08-07

## Summary

This is a hotfix for the Windows Inno Setup 6 packaging toolchain. `nexora build` and
`nexora doctor --fix` now ask `ISCC.exe` to read an empty script from standard input and parse the
exact compiler-engine version it prints before compilation, instead of trying to parse a patch
version from the help banner. The pinned tool remains Inno Setup 6.7.3.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Fixed

- Fixed Nexora repeatedly requesting installation after winget had successfully installed official
  Inno Setup 6.7.3 because the CLI could not parse a version from `ISCC.exe` output.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Version parsing accepts only the `Compiler engine version: Inno Setup 6.7.3` engine line. The help
  banner containing only `Inno Setup 6` is not mistaken for an exact version.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Added a Windows 2025 CI gate that installs Inno Setup 6.7.3 with the same winget command emitted
  by the CLI, then reads the installed `ISCC.exe` through the production detector. The release
  workflow repeats this validation. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility

- This release does not upgrade to Inno Setup 7 or change Windows artifacts, the in-app update
  protocol, signing boundaries, or the `nexora.toml` schema.
- Projects that completed the 0.30.0 migration need no configuration changes. Windows configuration
  must still omit the `installer` and `install_scope` fields removed in 0.30.0.

## Upgrading from 0.30.0

1. Update Nexora workspace dependencies to 0.30.1 or Git tag `v0.30.1`, then regenerate lockfiles.
2. Reinstall the CLI from `v0.30.1`; an existing official Inno Setup 6.7.3 installation does not
   need to be reinstalled.
3. Rerun `nexora doctor` or `nexora build` and confirm the builder recognizes the existing
   `ISCC.exe`.
