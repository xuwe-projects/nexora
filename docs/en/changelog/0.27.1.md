# Nexora 0.27.1

Release date: 2026-08-05

## Summary

This release fixes the MSVC entry point used for Windows GUI applications. When `nexora build`
sets `/SUBSYSTEM:WINDOWS`, it now also passes `/ENTRY:mainCRTStartup`, allowing applications that
define only Rust `main` and do not declare the `windows_subsystem` crate attribute to link correctly.
The main executable and updater sidecar share the same argument boundary; installer layout, update
protocols, and project configuration remain unchanged.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Fixed

- Windows main executables and updater sidecars now pass the PE resource, `/SUBSYSTEM:WINDOWS`, and
  `/ENTRY:mainCRTStartup` together to `cargo rustc`, preventing MSVC from looking for an undefined
  `WinMain` and failing with LNK2019/LNK1120. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added a regression test for the Windows linker arguments used by both the main process and
  sidecar, including the GUI subsystem and Rust CRT entry point. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Removed the Windows-only unused-import and equivalent conditional-expression warnings introduced
  in `v0.27.0`, restoring the CLI `-D warnings` release gate without changing self-update behavior.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

This release has no breaking changes and includes no database migration, Account HTTP-contract,
update-manifest, remote-object-layout, or `nexora.toml` change. Projects already on `0.27.0` need no
manual migration.

## Upgrading from 0.27.0

1. Update Nexora dependencies to `0.27.1` or Git tag `v0.27.1`, then regenerate lockfiles.
2. Reinstall the standalone CLI package:

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.27.1 cli --locked --force --bin nexora
   ```

3. Run `nexora build` again for Windows applications. Do not add a custom `WinMain`, and no
   `nexora.toml` change is required.
4. This release does not change scaffold Skills, the updater protocol, or custom macro rules.
   Downstream projects do not need to resync `.agents/skills`, and cargo expand, benchmark, bloat,
   and asm checks do not apply.
