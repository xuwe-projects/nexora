# Nexora 0.27.0

Release date: 2026-08-05

## Summary

This release moves the `nexora` command out of the framework crate into a standalone `cli` package,
adds CLI-only self-update, and publishes prebuilt GitHub Release assets for six platform targets.
Application publishing now uses display-name-and-architecture distribution filenames, stable app-key
remote paths, per-channel storage overrides, and credential groups that cannot be mixed. Desktop
startup also fixes the native title source and login-title-bar layout.

Owner: [@Jixiangup](https://github.com/Jixiangup)

Related issue/PR: none

## Added

- Added a standalone `crates/cli` package for the `nexora` binary, scaffolds, lint, build/publish,
  and their integration tests; the `nexora` framework crate is a library-only boundary again.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added `nexora update`. It selects the current target from the official GitHub Release
  `nexora-update.json` over HTTPS, validates schema, version, filename, size, and SHA-256, and safely
  replaces only the CLI. It does not edit project dependencies, source, or desktop applications and
  never requests sudo/UAC. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Added a tag-triggered GitHub Actions release workflow that builds six x86_64/ARM64 CLI assets for
  macOS, Windows, and Linux plus the update manifest, then publishes the Release with these notes
  only after the full asset set is ready. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Publish targets accept `channels.<channel>` field overrides for endpoints, public URLs, HTTP policy,
  and credential prefixes. `object_prefix = ""` places the stable app key directly at the bucket
  root. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- The `updater` crate has a minimal feature boundary. With `runtime` disabled, release metadata and
  `UpdateChannel` remain available without linking GPUI, network download, or platform installer
  runtime code into the CLI. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Changed

- Distribution files use `<display_name>-<arch><suffix>`. macOS DMG/ZIP and Windows EXE/MSI/ZIP
  names no longer contain the Cargo package, version, build number, or full target triple. Internal
  executables and sidecars keep the stable package name. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Versioned remote objects now use
  `[object_prefix/]app_key/channel/version/build/arch/artifact`. Publish uploads and anonymously
  verifies immutable files first, updates channel-root branded files and the sequence manifest next,
  and writes signed `latest.json` last. It no longer creates `latest.dmg`, `latest.exe`, or
  `latest.msi` aliases. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Default publishing credentials use the complete `NEXORA_PUBLISH_*` group and atomically fall back
  to the complete AWS group only when that group is entirely absent. A custom
  `credential_env_prefix` never falls back, and access/secret/session fields cannot be mixed across
  groups. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Windows resources use UTF-8 RC files, a Simplified Chinese string table, and distinct main/updater
  version identities. Display names affect user-facing descriptions while internal file identities
  remain package-based. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- When the application has not explicitly set a native title, `ApplicationOptions` uses the validated
  installed `display_name`; development runs continue to fall back to the application name.
  — Owner: [@Jixiangup](https://github.com/Jixiangup)
- CLI, configuration, updater, and release Skills/documentation now describe the standalone `cli`
  package, new credential groups, branded filenames, and current remote layout. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Login and shell gates keep the `gpui-component` `TitleBar` and use a layout-only wrapper so the
  absolute title bar has full width and non-zero height. Shell-managed LoginGate instances can still
  disable their own title bar to avoid duplication. — Owner: [@Jixiangup](https://github.com/Jixiangup)
- Publish rechecks the remote sequence before mutable writes and stops when an immutable object
  already exists, a branded-file upload fails, or the remote identity is not lower. `latest.json`
  is never overwritten early. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Removed

- Removed the `cli` feature, same-package binary, scaffolds, and CLI tests from the `nexora`
  framework package; they now live in the standalone `cli` package. — Owner:
  [@Jixiangup](https://github.com/Jixiangup)
- Publishing no longer reads `RUSTFS_ACCESS_KEY_ID`, `RUSTFS_SECRET_ACCESS_KEY`, or
  `RUSTFS_SESSION_TOKEN`. — Owner: [@Jixiangup](https://github.com/Jixiangup)

## Compatibility and breaking changes

No database migration or Account HTTP-contract change is included, but the following upgrades are
required:

- The old package `nexora`, `--features cli`, and `--no-default-features` installation arguments no
  longer work. Install package `cli`; the binary remains named `nexora`.
- Publishing environments using `RUSTFS_*` must move to `NEXORA_PUBLISH_*` or a complete AWS group.
  Custom channels should declare isolated `credential_env_prefix` values and cannot assemble a
  credential from multiple groups.
- Distribution filenames and remote object paths changed. Download pages, CI upload paths, and
  operations cleanup scripts must use branded filenames and the new layout; clients continue to
  follow only signed `latest.json`. Old `latest.*` and immutable objects are not removed automatically.
- The `nexora` crate default feature set changes from `desktop,derive,cli` to `desktop,derive`.
  Library-only applications need no extra action; scripts that installed the CLI and framework
  together must separate them.

## Upgrading from 0.26.0

1. Update every Nexora dependency to `0.27.0` or Git tag `v0.27.0`, then regenerate lockfiles.
2. Install the standalone CLI package:

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.27.0 cli --locked --force --bin nexora
   ```

3. Rename `RUSTFS_*` credentials to `NEXORA_PUBLISH_*`. Give beta/nightly targets their own
   `credential_env_prefix` and provide a complete access/secret/optional-session group at once.
4. Update CI and download pages to consume `<display_name>-<arch><suffix>` instead of versioned names
   or `latest.*` installer aliases. Administrators may explicitly remove obsolete aliases but should
   retain historical immutable objects.
5. Confirm that `feed_url` points to `[object_prefix/]app_key/channel/latest.json` and that the app key
   does not change with `display_name`.
6. Sync downstream `.agents/skills/develop-nexora-updater`, its `updater-protocol.md`,
   `publish-nexora-release`, `rust-code-style`, and the latest CLI scaffold constraints. No custom
   macro rule changed, so cargo expand, benchmark, bloat, and asm checks do not apply.
