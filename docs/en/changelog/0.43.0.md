# Nexora 0.43.0

Release date: 2026-08-22

Desktop applications that install `AccountAuthenticator` can now expose a small, explicit set of
account-independent Windows, such as About or license views, before sign-in. Other business Windows
remain protected by the authentication gate. The allowlist uses registered stable Window IDs and is
validated before the GPUI event loop starts.

## Added

- `ApplicationOptions` now provides the
  `unauthenticated_window("window-id")` builder. Applications can register the case-sensitive stable
  ID of a `#[derive(nexora::Window)]` that remains available before sign-in. The existing `settings`
  Window remains available by default and must not be registered again.

- `Application::validate()` and `run()` now validate the allowlist before entering the GPUI event
  loop. Missing IDs, Feature or NavigationGroup IDs, case mismatches, and duplicate entries return a
  structured `ApplicationError` instead of surfacing after startup.

## Changed

- The Shell window gate and runtime tests now share the same authentication policy. An allowlisted
  Window only bypasses the pre-sign-in independent-Window gate; it never creates or forges an
  authenticated session. Typed route extraction, the registered Window factory, native-window
  creation, and lifecycle processing remain unchanged. Non-allowlisted Windows still return the
  authentication error, and signed-in behavior is unchanged.

## Compatibility and breaking changes

- This is a backward-compatible `MINOR` feature release from `v0.42.0`; no existing public API is
  removed or changed.
- Applications without `AccountAuthenticator` are unchanged. Authenticated applications still
  expose only `settings` before sign-in by default; an additional independent Window is available
  only when it is explicitly registered and passes validation.
- This release does not change HTTP APIs, OpenAPI contract content, Account session protocols,
  updater protocols, configuration formats, or database structures. `docs/public/openapi.yaml` only
  updates its release metadata version to `0.43.0`.
- Before rolling back to `v0.42.0`, downstream applications using the new builder must remove their
  `.unauthenticated_window(...)` calls to compile again. A rollback does not modify data, but those
  additional Windows return to being available only after sign-in.

## Upgrading from 0.42.0

1. Update every Nexora Git dependency and CLI installation tag from `v0.42.0` to `v0.43.0`. Run
   `cargo update` and verify that every workspace package resolves to the new version.
2. Only for a genuinely account-independent Window such as an About or license view, add
   `.unauthenticated_window("stable-window-id")` to `ApplicationOptions`. The ID must exactly match a
   `#[derive(nexora::Window)]` registration, and each ID may appear only once.
3. Start the application or call `Application::validate()` explicitly so missing, mistyped,
   case-mismatched, wrong-kind, or duplicate IDs fail before the event loop. Do not allowlist a
   Feature or NavigationGroup, and do not treat this capability as an Account authentication
   substitute.
4. This release changes `.agents/skills/define-page`,
   `.agents/skills/develop-nexora-apps`, and their scaffold templates. Downstream projects that rely
   on these rules should synchronize the latest Skills. Existing projects without customized copies
   need no application-code change.
5. No database or configuration migration, new sign-in, or downtime is required. Applications not
   using the new capability only need to update dependencies and rebuild.

## Verification

- `cargo fmt --all --check`
- `cargo check --workspace --all-targets --all-features`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

This release does not change PostgreSQL, OIDC, object-storage, or release-signing protocols.
Integration checks requiring an external database, Identity Provider, S3/OSS credentials, or real
signing certificates were not run.

The full workspace test suite passed. Three existing tests that require an explicitly configured
Windows tool environment remained ignored under the repository defaults:
`installed_inno_setup_compiles_generated_installer_source`,
`installed_inno_setup_reports_supported_engine_version`, and
`windows_runner_reads_distinct_unicode_version_info_from_actual_pe_files`. The first two require
`NEXORA_TEST_ISCC`; the last requires an actual Windows PE toolchain environment.
