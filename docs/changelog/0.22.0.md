# Nexora 0.22.0

发布日期：2026-08-03

## 摘要

本版本让 build 首次解析并冻结 release identity，支持从所选 Cargo package 读取 SemVer，并以
UTC 时间生成严格递增的构建号。publish、dry-run 与 yank 只消费构建收据，不再重新计算动态值。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- `release.version` 支持完整字段 `${CARGO_PKG_VERSION}`，通过
  `cargo metadata --no-deps --format-version 1` 读取 `apps.<app>.package` 的最终版本；package 自有
  `version` 与 `version.workspace = true` 均受支持。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- `release.build_number` 支持完整字段 `${BUILD_DATETIME}`，以 UTC `yyMMddHHmmss` 生成正 `u64`；
  同秒构建或时钟回拨时取当前 UTC 值与上次本地构建号加一的较大值。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- build 在任何 target 开始前原子写入 `dist/<app>/<channel>/release.json`。收据记录 schema、app、
  package、channel、最终 version/build number、两项来源、创建 Unix 秒和计划 targets。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- 同一次 build 的所有 target 共用已冻结身份；未完成构建重试复用匹配收据，完整动态构建后再次
  显式 build 生成严格更高的构建号，同时保留旧版本化产物。损坏或不支持的收据在构建前失败。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- publish、dry-run 与 yank 从收据读取身份，并在上传前校验当前配置、所选 Cargo package 版本、
  required targets、每个 `artifact.json`、文件存在性、大小和 SHA-256。available release 必须
  严格高于远端 `(version, build_number)`；publish 仍不会隐式 build。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- 新脚手架默认使用 `${CARGO_PKG_VERSION}` 和 `${BUILD_DATETIME}`。显式 SemVer 与正整数继续
  兼容；未知表达式、片段插值、`${CARGO_VERSION}`、任意环境变量、0 和溢出都会明确失败。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- macOS 应用继续把配置的 ICNS 复制到 `Contents/Resources` 并写入 `CFBundleIconFile`；DMG 文件
  及挂载卷保留系统默认外观，不设置独立品牌图标。ZIP 与 DMG 都来自资源写入并签名后的同一个
  `.app`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

没有破坏性变更。已有 `release.version = "1.2.3"` 和 `release.build_number = 42` 配置保持有效；
采用动态表达式的项目必须让表达式占满字段。updater 客户端继续比较
`(version, build_number)`，manifest sequence 的职责没有改变。

本版本没有增加 Windows 或 Linux 打包实现，也没有增加通用模板引擎或任意环境变量插值。

## 从 0.21.3 升级

1. 将全部 Nexora 依赖统一更新到 `v0.22.0` 并重新生成 lockfile。
2. 同步 `.agents/skills/develop-nexora-updater`；其 protocol 已包含构建收据和动态身份契约。
3. 可继续保留显式版本与构建号，或改用下面的默认动态配置：

   ```toml
   [apps.<app>.release]
   version = "${CARGO_PKG_VERSION}"
   build_number = "${BUILD_DATETIME}"
   ```

4. 执行 `nexora build --app <app>`，检查 `dist/<app>/<channel>/release.json`，再执行
   `nexora publish --app <app> --dry-run`。
