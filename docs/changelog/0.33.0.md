# Nexora 0.33.0

发布日期：2026-08-08

## 摘要

本版本为 Nexora 桌面应用引入统一的单例主进程与受管多窗口运行机制。额外 Shell、Settings
和注册 Window 默认由主进程创建的子进程承载，窗口组通过认证 IPC 同步会话、偏好与 Account
状态；应用同时获得跨启动窗口恢复、原生系统托盘，以及 DataTable 列布局持久化能力。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 增加应用身份级单例门禁、一次性握手凭据、会话令牌、受限消息帧和主进程监管的子进程生命周期；
  重复启动会激活既有窗口组，整体退出会先广播退出原因并在有限等待后清理残留子进程。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加 `workspace.toml` 窗口会话模型，持久化完整路由、标签顺序、固定分区、活动标签、显示器
  UUID、窗口边界和最小化状态；缺失显示器会安全回退到主显示器的可见区域。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加 macOS/Windows 原生通知区域托盘，以及不依赖 GTK/AppIndicator 的 Linux
  StatusNotifierItem 实现；关闭主窗口时可选择退出、最小化到托盘或取消。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加基于 `gpui-component` `TabBar`、`PopupMenu` 和 `AlertDialog` 的标签拖拽、固定分区约束、
  完整路由“使用新窗口打开”入口和窗口关闭确认。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加 `DataTableLayoutKey`、`DataTableLayout`、`PersistentDataTableDelegate` 及便捷构造函数，
  以稳定 Feature/Table/Column ID 恢复列顺序和宽度，同时遵守固定列、不可移动列和宽度限制。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- `ApplicationOptions` 默认启用单例主进程、子进程窗口、窗口会话恢复和托盘，并提供对应 builder、
  子进程退出超时、应用身份覆盖和托盘不可用降级策略。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 桌面 Account 会话改为由主进程统一发布，子进程通过认证 IPC 接收登录、令牌缓存、访问快照和
  远程退出状态，避免多个进程并发刷新同一 OIDC 会话。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 用户偏好写入改为主进程字段级合并与窗口组广播；配置存储增加跨进程文件锁、唯一临时文件、
  刷盘和原子替换，未知同版本字段继续保留。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- 并发窗口修改不同偏好字段时不再由最后写入者覆盖其他字段；临时文件在成功或失败路径上都会
  精确清理。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 读取到未来 `workspace.toml` schema 时停止写入并保留原文件，不再用当前版本结构覆盖未知数据。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 路由身份现在稳定序列化完整规范化 path/query，同键 query 值保持顺序，恢复窗口时不会丢失
  动态参数或查询上下文。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 这是 `0.x` 阶段的桌面默认行为变更：升级后单例、子进程窗口、会话恢复和托盘默认开启。
  需要保持 v0.32.0 单进程窗口行为的应用必须显式调用
  `.single_instance(false).subprocess_windows(false).restore_window_sessions(false).tray_enabled(false)`。
- 直接使用结构体字面量构造 `ApplicationOptions` 的代码必须补齐新增字段；建议改用
  `ApplicationOptions::new()` 与 builder，或使用 `..Default::default()`。
- v0.32.0 的旧窗口偏好会在首次读取后迁移到 `workspace.toml` 当前 schema；无需手工转换。
  回滚前应备份或删除新版 `workspace.toml`，避免旧版本忽略新窗口会话字段。
- 自定义持久化表格必须为 Feature、表格和列提供稳定 ID。删除的列会被忽略，新列按代码顺序
  追加；不要把展示文字、数组下标或随机值作为持久化键。
- 本版本不修改 HTTP API、Account DTO、SQLx migration 或 PostgreSQL 基线。

## 从 0.32.0 升级

1. 把全部 Nexora 依赖与 CLI 更新为 `v0.33.0`，重新生成 workspace 和应用 lockfile。
2. 检查 `ApplicationOptions` 构造方式；确认接受新的强默认，或显式关闭不需要的进程、恢复和托盘能力。
3. 为需要列布局持久化的表格改用 `persistent_data_table_state` 或
   `persistent_crud_table_state`，并为每列提供长期稳定的业务键。
4. 在目标平台验证系统托盘、重复启动激活、窗口关闭确认、显示器拔插恢复和异常子进程回收。
5. 本版本没有修改脚手架 Skill、宏规则或生成项目约束，下游项目无需同步 `.agents/skills`。

回滚到 v0.32.0 时必须同时恢复框架依赖、CLI 和 lockfile。数据库无需回滚；建议先备份或移除
v0.33.0 写入的 `workspace.toml`，再由旧版本重新生成兼容偏好。

已执行并通过：

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets --locked`
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
- `cargo run -p cli --locked -- lint --workspace . --deny-warnings`
- `scripts/check-scaffold-consumer.sh`
- `bun install --frozen-lockfile && bun run build`（`docs/`）
- Linux 与 Windows 托盘模块隔离交叉编译，以及 macOS 本机编译

本次未在 Windows/Linux 真机执行托盘交互、跨显示器会话恢复和子进程异常回收人工验收；
完整 Linux workspace 交叉编译还受发布机缺少 `x86_64-linux-gnu-gcc` 限制。未执行外部
PostgreSQL、OIDC、签名、公证或真实 S3/RustFS 发布测试；本版本没有数据库迁移。
