# Nexora 0.30.1

发布日期：2026-08-07

## 摘要

这是 Windows Inno Setup 6 打包链路的热修复版本。`nexora build` 与
`nexora doctor --fix` 现在让 `ISCC.exe` 从标准输入读取空脚本，并解析它在编译前输出的精确
编译器引擎版本，不再尝试从帮助横幅中解析补丁版本。固定工具版本仍为 Inno Setup 6.7.3。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- 修复 winget 已成功安装官方 Inno Setup 6.7.3 后，Nexora 仍报告“无法从 ISCC.exe 输出解析
  Inno Setup 版本”并重复要求安装的问题。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 版本解析只接受 `Compiler engine version: Inno Setup 6.7.3` 这一编译器引擎输出；只含
  `Inno Setup 6` 的帮助横幅不会被误判为精确版本。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 新增 Windows 2025 CI 门禁，使用与 CLI 指引相同的 winget 命令真实安装 Inno Setup 6.7.3，
  再由生产探测代码读取已安装 `ISCC.exe`。发布工作流也重复执行该验证。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性

- 本版本不升级到 Inno Setup 7，也不改变 Windows 安装产物、应用内更新协议、签名边界或
  `nexora.toml` schema。
- 已完成 0.30.0 迁移的项目无需修改配置；Windows 配置仍不得包含 0.30.0 已删除的
  `installer` 与 `install_scope` 字段。

## 从 0.30.0 升级

1. 把 Nexora workspace 依赖更新为 0.30.1 或 Git tag `v0.30.1`，重新生成 lockfile。
2. 使用 `v0.30.1` 重新安装 CLI；无需重新安装已经存在的官方 Inno Setup 6.7.3。
3. 重新运行 `nexora doctor` 或 `nexora build`，确认构建机识别现有 `ISCC.exe`。

## 验证

发布前执行并通过：

- `cargo fmt --all --check`
- `cargo check --workspace --locked`
- `cargo test --workspace --all-targets --locked`
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
- `cargo run -p cli --locked -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`
- `cargo build -p cli --release --locked`，并确认产物输出 `nexora 0.30.1`
- Windows 2025 runner 真实安装官方 Inno Setup 6.7.3，并由生产探测代码读取到 `6.7.3`

本热修复不把安装向导、卸载、原地升级或 sidecar 更新声明为新增验证范围。
