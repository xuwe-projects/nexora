# Nexora 0.41.1

发布日期：2026-08-20

本版本修复正式安装包在非源码工作目录启动时的冻结运行配置加载边界，并统一
下游应用的 Updater `release.notes` 生成规则。应用内更新说明现在面向最终用户，
GitHub Release 与开发者 Changelog 继续保留完整技术信息。

## 修复

- `nexora::config::initialize(None)` 现在通过当前可执行文件与合法
  `nexora-release.json` 定位正式包资源目录。macOS 从 `Contents/Resources/config`
  读取，Windows 从 EXE 同级 `config` 读取，不再依赖 cwd 或源码仓库。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 正式包中冻结配置缺失、不可读或无效时现在明确失败，不会回退到开发配置；
  显式路径、用户位置参数和环境覆盖的优先级保持不变。Updater health 内部参数及
  其值不会被误判为配置路径。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 增加 macOS、Windows、正式/开发优先级、失败边界以及 nightly/beta/stable
  channel 冻结配置的回归测试。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 调整

- `publish-nexora-release` Skill 现在为启用 Updater 的应用单独生成面向最终用户的
  `release.notes`。标题版本来自所选 app 实际解析的 Cargo package，日期来自本次
  发布准备日期；没有内容的分类完全省略，“重要提醒”只在用户必须操作或注意
  时出现。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 应用内说明要求把内部 crate、API、数据库、CI 与 Updater 实现改写为用户可感知
  结果；无法确认用户影响时停止生成。GitHub Release/开发者 Changelog 仍保留处理人、
  Issue/PR、破坏性变更、升级步骤和验证结果。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- CLI 脚手架 Skill 镜像、Skill 元数据、中英文 CLI/Updater 文档与生成项目回归断言
  已同步。Updater 运行时仍只校验、冻结、签名、发布和展示安全 Markdown，不解析
  新标题或分类。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 兼容性与破坏性变更

- 这是 `v0.41.0` 的向后兼容补丁，不新增或删除公开 API、HTTP 路由、数据库结构、
  manifest schema、签名协议或发布对象布局。
- 正式安装包必须携带由新版 CLI 生成的合法 `nexora-release.json` 与冻结配置；
  正常 `nexora build` 会自动满足该约束。
- `docs/public/openapi.yaml` 只同步发布元数据版本到 `0.41.1`，API 契约未变。
- 无破坏性变更，无需手工数据迁移。

## 从 0.41.0 升级

1. 将所有 Nexora Git 依赖与 CLI 安装 tag 从 `v0.41.0` 更新为 `v0.41.1`。
2. 运行 `cargo update`，确认 `Cargo.lock` 中 Nexora workspace package 指向 `v0.41.1`。
3. 同步 `.agents/skills/develop-nexora-apps`、`.agents/skills/develop-nexora-updater`、
   `.agents/skills/develop-nexora-updater/references/updater-protocol.md` 与
   `.agents/skills/publish-nexora-release`。新生成项目已携带同步后的 Skill。
4. 使用新版 CLI 重新构建正式安装包，验证 nightly/beta/stable 等实际 channel
   能读取各自冻结的 `runtime_config`。

## 验证

- `cargo fmt --all --check`
- `cargo check --workspace`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`
- `publish-nexora-release` Skill `quick_validate` 与仓库/脚手架 Skill 镜像字节一致性检查

本版本未修改 PostgreSQL、OIDC、对象存储或发布签名协议，未执行依赖外部数据库、
Identity Provider、S3/OSS 凭据或异构宿主签名安装环境的集成验证。
