# Nexora 0.41.0

发布日期：2026-08-19

本版本为 `nexora publish` 新增显式阿里云 OSS provider，修复 S3 兼容接口上传不可变发布对象时
因条件请求头不兼容而返回 HTTP 400 的问题。通用 S3 行为与发布顺序保持不变。

## 新增

- `[publish.targets.<name>]` 及其 channel override 现在接受 `provider = "aliyun_oss"`。阿里云 OSS
  的不可变 versioned 对象、checksum、release notes 与 sequence manifest 使用
  `x-oss-forbid-overwrite: true`，并把该 header 纳入 AWS SigV4 canonical headers，避免覆盖既有
  发布对象。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 变更

- publish provider 改为受约束的配置枚举。通用 S3 继续显式配置 `provider = "s3"` 并对不可变
  对象发送 `If-None-Match: *`；Nexora 不根据 endpoint 域名推断 provider。channel 根 branded
  对象与最后上传的 `latest.json` 仍不带防覆盖条件，允许后续发布更新。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 配置参考、Updater 文档、协议 Skill 与新项目脚手架同步说明两个 provider 的防覆盖语义。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 修复

- 修复阿里云 OSS S3 兼容 endpoint 拒绝 `If-None-Match: *`，导致首个不可变 EXE/ZIP 等对象上传
  返回 HTTP 400、发布无法进入 branded 对象和 `latest.json` 阶段的问题。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 将两处等价布尔判断改为 Rust 1.96 Clippy 建议的最简形式，使 workspace 在
  `-D warnings` 下继续通过；CRUD Panel 和 Nexora lint 的运行行为不变。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 兼容性与破坏性变更

- 这是 `v0.40.3` 的向后兼容功能版本；现有 `provider = "s3"` 配置及 S3/RustFS/MinIO 行为不变。
- 使用阿里云 OSS 的项目需在目标或 channel override 中显式配置 `provider = "aliyun_oss"`；endpoint、
  bucket、region、virtual-hosted style 与公开下载 URL 仍由项目明确提供。
- 不修改公开 Rust API、HTTP API、数据库 schema、Updater manifest schema、release receipt schema
  或对象布局；`docs/public/openapi.yaml` 仅同步发布元数据版本到 `0.41.0`。
- 无破坏性变更，无需数据迁移。回退到 `v0.40.3` 前，应把阿里云 OSS provider 配置恢复为旧版可
  解析的 `s3`，但该旧行为仍可能在不可变对象上传时收到 HTTP 400。

## 从 0.40.3 升级

1. 将全部 Nexora Git 依赖与 CLI 安装 tag 从 `v0.40.3` 更新为 `v0.41.0`，然后运行
   `cargo update`。
2. 通用 S3/RustFS/MinIO 保持 `provider = "s3"`；阿里云 OSS 在基础 target 或对应 channel 中
   配置 `provider = "aliyun_oss"`、正确 region，并保持 `force_path_style = false`。
3. 同步本版本的 `.agents/skills/develop-nexora-updater`，运行 publish dry-run，再执行真实发布并
   确认不可变对象、channel 根 branded 对象、sequence manifest 与 `latest.json` 均可匿名读取。
