# Nexora 0.19.0

发布日期：2026-07-29

本版本继续处于 `0.x` beta 阶段，不进入 `1.x` 稳定通道；版本号使用标准 SemVer `0.19.0`。
本次发布从 Account 模块移除所有可上传、可存储、可同步的用户头像数据能力。这是破坏性版本：
所有 `avatar_url` 字段、头像 HTTP API、头像权限、头像存储注入点和相关公开 Rust API 都被删除。

## Removed

- 删除 Account contracts 中的 `UserResponse.avatar_url`、`ProvisionUserRequest.avatar_url`、
  `AvatarUploadResponse` 与 `UpdateUserAvatarRequest`。处理人：[@zhutao525](https://github.com/zhutao525)
- 删除 Account 实体、`ExternalIdentity`、`CreateHumanIdentity`、`VerifiedIdentity`、store 查询、
  `FromRow` 映射和本地账号写入中的头像字段。处理人：[@zhutao525](https://github.com/zhutao525)
- 删除 `POST /avatars` 与 `PATCH /users/{user_id}/avatar` 的 handler、router、body limit、
  OpenAPI 描述和客户端方法。处理人：[@zhutao525](https://github.com/zhutao525)
- 删除 `AvatarStorage`、`LocalAvatarStorage`、`AvatarUpload`、`AvatarStorageError`、
  `AccountDependencies::avatar_storage` 及 `nexora::server`/`nexora::account` 公开 re-export。
  处理人：[@zhutao525](https://github.com/zhutao525)
- 删除 ZITADEL avatar metadata key、写入、读取回填、更新和补偿逻辑；Account 不再读取 OIDC
  `picture` claim 作为本地用户资料。处理人：[@zhutao525](https://github.com/zhutao525)

## Changed

- 默认用户管理列表和应用 Shell 登录用户区域继续渲染 gpui-component `Avatar` 组件，但只根据
  `display_name`/名称显示首字母或默认图标，不再调用 `.src(...)` 读取图片 URL。处理人：
  [@zhutao525](https://github.com/zhutao525)
- 默认用户创建表单删除“头像 URL”输入，仍保留用户名前的圆形视觉标识位置。处理人：
  [@zhutao525](https://github.com/zhutao525)
- Account 当前用户刷新只同步目录中的 username、邮箱、展示名和最近登录时间，不再同步头像。
  处理人：[@zhutao525](https://github.com/zhutao525)

## Database

- 新增 append-only SQLx 迁移
  `202607290001_account_remove_avatar_capability`：删除 `users:avatar.write` 权限及内置角色关联，
  并 `DROP COLUMN account.users.avatar_url`。该迁移会永久删除历史头像 URL 数据，不迁移、不回填。
  处理人：[@zhutao525](https://github.com/zhutao525)
- 迁移版本号刻意高于 iMES 当前不可变历史迁移 `202607180006_system_dictionary_seed_standard_catalogs`：
  空数据库合并 Nexora 与当前 iMES 迁移时，iMES 历史 seed 仍可先执行其包含 `avatar_url` 的旧
  `INSERT INTO account.users (...)`，随后 Nexora `202607290001` 删除列；已应用 iMES 高位迁移的
  现有数据库也只会看到更高版本的 Nexora 迁移，不触发 SQLx 低版本补跑/out-of-order 风险。
- 没有修改 `0001_account_create_rbac`、`0009_account_add_user_avatar_permission` 或任何已发布旧迁移；
  没有修补 `_sqlx_migrations` checksum。

## 兼容性与破坏性变更

- 破坏性变更：所有 JSON 契约中的 `avatar_url` 字段被删除；带 `avatar_url` 的创建用户请求会被
  `deny_unknown_fields` 拒绝。
- 破坏性变更：`POST /avatars` 与 `PATCH /users/{user_id}/avatar` 不再注册；调用方应视为路由不存在。
- 破坏性变更：`users:avatar.write` 权限和内置 admin 角色关联会被迁移清理；自定义角色也不应再引用该权限。
- 破坏性变更：`AvatarStorage`/`LocalAvatarStorage`/`AvatarUpload`/`AvatarStorageError` 和
  `AccountDependencies::avatar_storage` 被删除；宿主必须移除相关配置与依赖注入。
- 破坏性变更：`ExternalIdentity`、`CreateHumanIdentity`、`VerifiedIdentity`、`User` 和
  Account DTO 不再包含头像字段；下游必须更新结构体字面量、DTO 访问和序列化测试。
- 迁移会永久删除 `account.users.avatar_url` 及其中历史数据。回滚 down 迁移只能恢复表结构和旧权限形状，
  不能恢复已删除的数据。
- 视觉上的首字母/默认 `Avatar` 仍保留，只代表用户视觉标识，不代表 Nexora 仍管理可上传头像数据。

## 升级

1. 把 Nexora tag 更新为 `v0.19.0` 并重新锁定依赖。
2. 从服务端 composition root 中移除 `AccountDependencies::avatar_storage` 和所有
   `AvatarStorage`/`LocalAvatarStorage` 配置。
3. 删除客户端对 `upload_avatar`、`update_user_avatar`、`AvatarUploadResponse`、
   `UpdateUserAvatarRequest`、`avatar_url` 字段的调用和断言。
4. 更新数据库迁移组合：继续把 Nexora 与宿主迁移合并为同一个 SQLx `Migrator`，并保证已发布旧迁移
   不被修改。iMES 当前历史 seed 可依赖 `202607180006 < 202607290001` 的顺序兼容空库。
5. 如果下游未来新增或修改 iMES 迁移，不得再向 `account.users.avatar_url` 写入数据；当前不可变历史迁移
   无需修改。
6. 如果 UI 仍需要圆形用户标识，使用 `Avatar::new().name(display_name).small()` 一类首字母/默认图标，
   不要读取或传递图片 URL。
