# Nexora 0.38.2

发布日期：2026-08-17

## 摘要

本补丁修复 Account 用户列表无法解析正常 URL query 的问题。`GET /users?page=1&page_size=25`
不再返回 `400 invalid_query_parameter`，默认用户管理页面可以继续加载并展示 DataTable。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- `UserListQuery` 使用独立的扁平 wire 反序列化模型，避免 URL query 经过 Serde `flatten` 缓冲后
  将 `page` 与 `page_size` 作为字符串交给 `u32` 解析。默认分页与带 `keyword`、`status`、
  `user_type` 的完整筛选请求现在都能被 Axum `Query` 正确提取。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加不依赖数据库的 Axum Router 回归测试，覆盖默认分页、完整筛选，以及未知 query 字段继续
  返回 `400 invalid_query_parameter` 的错误契约。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- HTTP 方法、路径和 wire 参数保持不变：仍使用 `GET /users` 与扁平的 `page`、`page_size`、
  `keyword`、`status`、`user_type`。
- 公开 Rust API 保持不变：调用方仍通过 `UserListQuery.page: PageQuery` 访问分页值；序列化结果、
  默认值、枚举值和未知字段拒绝行为均保留。
- 本版本没有数据库迁移、配置项、桌面 UI、权限、响应结构或生成项目结构变更。
- 本版本没有修改 `.agents/skills`、宏规则或脚手架约束，下游无需同步 Skill。

## 从 0.38.1 升级

1. 把 Nexora workspace 依赖与 CLI 切换到 Git tag `v0.38.2`，删除临时 path/patch 并重新生成
   `Cargo.lock`。
2. 重新构建并部署服务端；该修复位于 Account 查询契约的服务端反序列化路径，服务端必须重启后
   才会生效。桌面端与服务端建议统一使用同一 tag。
3. 无需修改 `GET /users` 调用、配置或数据库，也无需执行新增迁移。
4. 验证默认分页、关键词筛选、状态筛选、用户类型筛选和未知 query 参数错误响应。

回滚到 0.38.1 不需要数据库或配置回滚，但会重新引入用户列表正常分页请求返回
`400 invalid_query_parameter` 的问题。

字段仍返回稳定的 `400 invalid_query_parameter`。本次改动不访问数据库、OIDC 或 ZITADEL，相关
外部环境测试不适用。签名、公证、对象存储和二进制发布 CI 不影响本次源码版本升级。
