# Nexora 0.28.0

发布日期：2026-08-05

## 摘要

本版本统一桌面发布凭证和跨平台构建依赖准备流程。发布目标不再配置凭证环境变量前缀，
Access Key、Secret Key 与 Session Token 分别按当前 channel、Nexora 通用变量和 AWS 通用变量
逐字段回退。交互式 `nexora build` 与 `nexora doctor --fix` 现在可以检测、安装并复检 macOS
与 Windows 打包依赖；非交互环境保持无副作用，只返回可直接执行的安装命令。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- macOS 构建会检查并按需准备 Rust 工具链与 target、`cargo-bundle`、Homebrew、
  `create-dmg` 和 Xcode Command Line Tools；系统安装器需要人工完成时会明确要求重跑原命令。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 构建会检查并按需准备 Rust 工具链与 target、固定 revision 的现代 `cargo-wix`、
  Windows SDK、.NET SDK、WiX 5.0.2 及 UI/Bootstrapper 扩展。没有 .NET 时使用微软官方
  `dotnet-install.ps1` 把 .NET 10 安装到 Nexora 用户级工具目录，并只为当前进程注入路径。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `nexora doctor` 保持只读检查，`nexora doctor --fix` 与 `nexora build` 复用同一依赖修复和
  安装后复检路径；CI 或其他非交互环境不会启动系统安装器。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- S3 发布凭证的 Access Key、Secret Key 与可选 Session Token 分别按
  `NEXORA_PUBLISH_<CHANNEL>_<FIELD>`、`NEXORA_PUBLISH_<FIELD>`、`AWS_<FIELD>` 的顺序
  独立选择；空字符串继续回退，因此同一次发布可以安全组合不同层级的字段。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 脚手架、macOS/Windows 示例、中英文配置文档和 `develop-nexora-updater` Skill 已同步新的
  凭证约定与依赖修复行为。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Removed

- 删除 `[publish.targets.*]` 及其 channel override 中的 `credential_env_prefix`；旧字段现在按
  未知字段拒绝，不提供兼容读取。`RUSTFS_ACCESS_KEY_ID`、`RUSTFS_SECRET_ACCESS_KEY` 等旧式
  provider 前缀变量不再参与凭证解析。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本包含 `nexora.toml` 发布配置和环境变量约定的破坏性变更。旧配置例如：

```toml
[publish.targets.rustfs]
credential_env_prefix = "RUSTFS"
```

升级后必须删除 `credential_env_prefix`，并使用固定变量约定。例如 beta channel 可以配置：

```text
NEXORA_PUBLISH_BETA_ACCESS_KEY_ID
NEXORA_PUBLISH_SECRET_ACCESS_KEY
NEXORA_PUBLISH_SESSION_TOKEN
```

上例允许 beta 专用 Access Key 与通用 Secret Key/Session Token 组合。Access Key 和 Secret Key
最终必须存在，Session Token 可选。更新 manifest、远程对象布局、Account HTTP 契约和数据库
迁移均未改变。

## 从 0.27.1 升级

1. 把 Nexora 依赖更新为 `0.28.0` 或 Git tag `v0.28.0`，然后重新生成 lockfile。
2. 重新安装独立 CLI：

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.28.0 cli --locked --force --bin nexora
   ```

3. 删除所有基础发布目标和 channel override 中的 `credential_env_prefix`，把凭证迁移到
   `NEXORA_PUBLISH_<CHANNEL>_*`、`NEXORA_PUBLISH_*` 或 `AWS_*`。每个字段可以独立迁移。
4. 在构建机运行 `nexora doctor` 检查依赖；交互式开发机可以运行
   `nexora doctor --fix`，CI 应按错误中给出的命令预装依赖，不依赖交互安装器。
5. 本版本修改了 `develop-nexora-updater` Skill 和脚手架配置，下游项目应同步
   `.agents/skills/develop-nexora-updater`，或重新运行 `nexora init .` 写入更新后的 Skill。
   本版本没有修改自定义宏规则，不需要额外执行 `cargo expand`、bench、bloat 或 asm 分析。

回滚到 `0.27.1` 时，需要恢复旧版要求的 `credential_env_prefix` 和对应的完整凭据组；新安装的
Rust、Windows SDK、.NET、WiX、Homebrew 或打包工具可以保留，不影响旧版 CLI。

## 验证

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`
- `cargo check --manifest-path examples/updater-macos/Cargo.toml`
- `cargo check --manifest-path examples/updater-windows/Cargo.toml`

本次发布未在 Windows 真机启动 Windows SDK/.NET/WiX 自动安装流程，也未启动生成的 MSI/Setup
安装器；同时未执行 Windows ARM64、Authenticode、macOS Developer ID 公证、Linux CLI 原子
替换、外部 PostgreSQL 或真实 OIDC Provider 联调。GitHub Actions 会在 tag 推送后构建并校验
六个平台 CLI 资产。
