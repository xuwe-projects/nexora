# Nexora 0.20.0

发布日期：2026-07-31

本版本继续处于 early-alpha `0.x` 阶段，以 `v0.19.0` 为唯一升级起点。新增可选的 Sidebar
导航搜索，并为桌面 Account API 增加显式的非 loopback HTTP 放行开关。由于公开配置结构体与
`ApplicationOptions` 增加字段，按 pre-1.0 SemVer 将次版本提升到 `0.20.0`。

## Added

- `ApplicationOptions` 新增默认关闭的 `sidebar_search: bool` 与
  `sidebar_search(true)` builder；启用后 Shell 在 Sidebar Header 与导航列表之间渲染原生
  `gpui-component::input::Input`，并使用 `IconName::Search` 前缀。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。
- Sidebar 搜索支持标题原文、无声调全拼和拼音首字母连续子串匹配。过滤基于当前账号已经
  有权看到的导航树；搜索时使用临时展开集合，清空搜索词后恢复原来的展开/折叠状态。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。
- `ApiSettings` 新增 serde 默认值为 `false` 的 `allow_insecure_http`。HTTPS 始终允许，
  loopback HTTP 默认允许，其他 HTTP 只有显式设置为 `true` 时才允许。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。

## Changed

- 桌面 API 配置文档、仓库配置样例和 Account workspace 脚手架现在都解释纯 HTTP 会明文传输
  Bearer Token，并只在调用方接受风险的内网或受控环境中展示显式放行方式。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。
- 桌面 feature 增加最小依赖 `pinyin 0.11.0`，关闭默认 features，仅启用 `plain`；未启用
  `desktop` feature 的 Nexora 使用方不会引入该依赖。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。
- `desktop_basic` 示例启用 Sidebar 搜索，便于直接验证新能力；当前版本展示、安装 tag、
  OpenAPI 版本与 workspace 内部依赖约束同步更新到 `0.20.0`。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。

## Fixed

- 修正仓库 `config/desktop.toml.example` 的旧配置形状：使用 `[api].endpoint`、
  `[account.oidc]` 与字符串数组 `scopes`，并补齐 `allow_insecure_http = false`，避免复制样例后
  因字段过期而加载失败。— 处理人：[@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。
- API endpoint 校验错误继续只返回固定说明，不回显 endpoint、URL 凭据、query、fragment、
  Bearer Token 或其他秘密。— 处理人：[@Jixiangup](https://github.com/Jixiangup)；关联 Issue/PR：无。

## 兼容性与破坏性变更

- Rust 结构体字面量构造 `ApiSettings` 时必须新增 `allow_insecure_http` 字段；从 TOML 等 serde
  配置反序列化时该字段缺省为 `false`，现有 HTTPS 与 loopback HTTP 配置无需修改。
- Rust 结构体字面量构造 `ApplicationOptions` 时必须新增 `sidebar_search` 字段。通过
  `ApplicationOptions::new()`、`Default` 或现有 builder 构造的代码行为不变，搜索默认关闭。
- 非 loopback HTTP 仍默认拒绝；只有显式设置 `allow_insecure_http = true` 才改变行为。该开关
  不提供加密，Bearer Token 仍会以明文传输。
- 没有数据库迁移、HTTP 路由、JSON wire 字段或 OpenAPI 路径变更；回滚时把依赖恢复到
  `v0.19.0`，移除新增结构体字段与配置项即可。

## 从 0.19.0 升级

1. 将 Nexora 依赖 tag/版本更新到 `v0.20.0` 并重新生成 lockfile。
2. 检查所有 `ApiSettings { ... }` 字面量并补充 `allow_insecure_http: false`。配置文件可暂不添加
   该字段；建议显式写出 `false` 以记录安全策略。
3. 只有在确需访问受控网络中的非 loopback 纯 HTTP 服务且已经接受 Bearer Token 明文风险时，
   才设置 `[api] allow_insecure_http = true`；生产部署优先改用 HTTPS。
4. 检查 `ApplicationOptions { ... }` 字面量并补充 `sidebar_search: false`；需要导航搜索时改用
   `ApplicationOptions::new().sidebar_search(true)`。
5. 使用 Account workspace 脚手架的下游项目应同步最新配置模板与 `.agents/skills` 规则，尤其是
   `[api]` 安全说明、`gpui-component` 组件选择约束和 `pinyin` 最小 feature 依赖约束。脚手架
   新项目自身的初始 package 版本仍保持 `0.1.0`。
