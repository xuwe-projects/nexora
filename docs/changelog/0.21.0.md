# Nexora 0.21.0

发布日期：2026-08-03

## 摘要

本版本把多应用品牌资源、macOS 安装图标和桌面更新入口纳入同一份 app 注册，并将已有签名
updater 通过 `nexora::desktop` 暴露为显式安装的公共能力。由于 `nexora.toml` 的 app 配置新增
必填品牌与平台图标字段，按 pre-1.0 SemVer 将次版本提升到 `0.21.0`。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- `nexora create` 与 `nexora init` 为每个 app 在 workspace 根目录生成独立的
  `assets/logos/<app_key>/` 完整 PNG、ICNS 和 ICO 资源集；已存在的品牌文件保持不覆盖。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `nexora icons generate --app <app_key>`，校验源 PNG 的格式、尺寸和透明通道，并确定性
  生成标准多尺寸 PNG、ICNS 与 ICO；手工资源需要显式 `--force` 才允许覆盖。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `nexora::desktop::install_updater`、公共 `CheckForUpdates` Action、可复用按钮和 app 级
  单会话协调；默认登录页、账户菜单、设置和 macOS 原生应用菜单按安装状态显示入口。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 签名 `latest.json`、S3/RustFS 发布、独立 sidecar、健康确认、失败回滚、撤回与强制更新能力
  纳入统一 updater 生产链路和 `develop-nexora-updater` Skill。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora.toml` 继续作为唯一 app 注册边界，并新增 `branding`、macOS ICNS、Windows ICO、
  Linux 多尺寸 PNG、可选 updater app ID、启动检查和预期 Team ID 配置。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `nexora build` 按所选 app 做 workspace 路径与图标格式预检，把 ICNS 写入 `.app` Resources 和
  `CFBundleIconFile`，同时写入 identifier、版本、sidecar 与 updater bundle 配置；不修改 Cargo
  manifest。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 启动后台检查只检查版本，发现更新时显示非模态通知；手动检查与后台检查都必须由用户确认后
  才下载。多入口共享同一协调器。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `examples/updater-macos` 已迁移到独立品牌目录与 `nexora::desktop` 公共 updater，并实际产出
  arm64 `.app`、`.app.zip`、DMG 和 `artifact.json`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 现有 `nexora.toml` app 注册必须新增 `[apps.<key>.branding]`、
  `[apps.<key>.platforms.macos]`、`windows` 和 `linux` 配置。旧配置会在 build/publish 前返回明确
  反序列化或资源诊断，不再生成无品牌安装包。
- updater 入口改为显式安装。未调用 `nexora::desktop::install_updater` 的应用不会显示入口，
  也不会启动网络任务。
- Windows/Linux 已纳入配置、初始化和图标生成模型，但本版本仍不提供完整安装包或自动安装更新。

## 从 0.20.0 升级

1. 将依赖更新为 `v0.21.0`，重新生成 lockfile，并同步新的
   `.agents/skills/develop-nexora-updater`。
2. 为每个 app 建立 `assets/logos/<app_key>/`，在同一 app 注册中补齐 `branding` 与三平台图标。
3. 运行 `nexora icons generate --app <app_key>`，再运行 `nexora build --app <app_key>` 验证资源。
4. 桌面入口从 bundle 构建 `UpdateConfig`，在 `Application::initialize` 中调用
   `nexora::desktop::install_updater`；删除应用私有 updater 弹窗和状态机。
5. macOS Developer ID 发布必须配置预期 Team ID，并继续从外部秘密系统注入签名材料。

回滚到 0.20.0 时需同时恢复旧 `nexora.toml` schema 与应用私有接入代码；已经生成的品牌资源可
保留，但 0.20.0 CLI 不会消费新增字段。
