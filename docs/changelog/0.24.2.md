# Nexora 0.24.2

## 修复

- 恢复 `apps.<app>.release.channels` 多通道发布配置，兼容 `default_channel`、channel 级 `version`、`build_number`、`minimum_supported_version` 与 `runtime_config` 覆盖，同时保留单通道 `release.channel` 写法。— 处理人：[@openai](https://github.com/openai)
- `nexora build` 与 `nexora publish` 重新支持 `--channel` 和 `--all-channels`，多通道模式下按所选 channel 生成 `latest.json` feed URL，并禁止静态 `updater.feed_url` 避免打包错误的更新源。— 处理人：[@openai](https://github.com/openai)
- release receipt 恢复记录 `runtime_config_source`、`runtime_config_sha256` 与 `updater_feed`，runtime config 变化会使旧 receipt 失效并重新生成。— 处理人：[@openai](https://github.com/openai)

## 关联

- Issue/PR：无

## 兼容性

- 无破坏性变更。单通道 `release.channel` 配置继续可用。
- 使用多通道 `release.channels` 时需要删除静态 `apps.<app>.updater.feed_url`，由 Nexora 根据 app、channel 和 publish target 自动生成。

## 升级

1. 将 Nexora 依赖和 CLI 安装 tag 升级到 `v0.24.2`。
2. iMES 可保留既有 `default_channel`、`release.channels.*.runtime_config` 与 `updater.channels` 配置。
3. 重新运行 `nexora build --channel <channel>` 或 `nexora build --all-channels` 生成对应 channel 的 release receipt 与 bundle。

## 验证

- `cargo fmt --all --check`
- `cargo check -p nexora --features cli`
- `cargo test -p nexora --features cli --test build`
- `cargo clippy -p nexora --features cli --all-targets -- -D warnings`
- `cargo run -p nexora --features cli -- lint --workspace . --deny-warnings`
- `cargo check --workspace` 曾执行但 300 秒超时，未作为通过项；本次改动的 CLI 发布路径已由上述 nexora crate check、Clippy、build 集成测试与仓库 lint 覆盖。
