# Nexora 0.35.0

发布日期：2026-08-12

## 摘要

本版本把桌面窗口模型收敛为严格的单应用进程、多原生窗口：主窗口、额外 Shell、唯一
Settings 和注册 Window 始终共享同一个 GPUI 事件循环，但退出后不再恢复任何窗口或标签
会话。同时重构 Account 客户端的错误边界，让连接、超时、响应读取、成功响应契约不兼容、
结构化拒绝和非结构化异常响应可以得到准确且安全的诊断。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Changed

- 应用身份级单例门禁固定启用；重复启动只向现有进程发送激活请求。额外 Shell、Settings
  和注册 Window 均使用当前 `App` 创建，不再存在窗口承载子进程。Updater sidecar 继续作为
  独立更新组件保留。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 冷启动固定只创建一个主窗口并打开 `ApplicationOptions::initial_path`。运行期标签、置顶状态
  和额外窗口只存在于内存，不再跨正常退出、异常退出、系统重启或升级恢复。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `workspace.toml` schema 升至 2。schema 0 保留原 `main_window` 几何并丢弃
  `pinned_tabs`；schema 1 只从 ID 为 `main` 的窗口记录提取显示器、边界和最大化/全屏状态。
  全部标签、活动标签和非主窗口记录被丢弃，主题、组件尺寸、DataTable 布局、Account 非秘密
  偏好和普通未知字段继续保留。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Account HTTP 错误现在公开稳定类别：客户端初始化、连接失败、请求超时、其他传输失败、
  响应读取失败、成功响应契约不兼容、结构化服务端拒绝和非结构化异常响应。结构化拒绝继续
  保留安全消息、错误码、request ID 和复制 request ID 操作。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 连接、超时、临时服务拒绝、响应读取和契约不兼容均视为可重试失败，保留 Keychain 或
  Credential Manager 凭据与恢复资格。只有 `invalid_grant`、OIDC subject 不一致、
  `account_not_registered`、`account_suspended` 等明确永久错误才禁止恢复并清理凭据。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Account 安全存储 service 改为 `${application_identity}.account.oidc`，避免使用相同 OIDC
  配置的不同应用共享 refresh token。旧的固定 `nexora.account.oidc` 项不会自动迁移或删除。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- 修复成功 `/me` 响应无法解码时被误报为“无法连接 Account 服务”的问题；现在明确报告
  客户端与服务端版本或响应契约不兼容。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Account 错误与客户端 Debug 摘要不再保存或打印底层 `reqwest::Error`、完整 endpoint、
  Authorization header、token 或原始响应正文。OIDC UI 错误也对 endpoint 和 Provider
  返回细节做安全归类。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 即使首次窗口偏好迁移写盘失败，本次启动仍忽略全部旧会话；后续普通偏好写入会在锁内重新
  执行迁移，避免旧字段被未知字段透传或主窗口几何丢失。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 删除 `ApplicationOptions::single_instance`、`ApplicationOptions::subprocess_windows`、
  `ApplicationOptions::restore_window_sessions` 字段及同名 builder。删除旧调用；没有替代开关。
- 删除公开 `WindowSession`、`WindowSessionRole`、`WindowTabSession` 类型，以及受管窗口
  子进程使用的参数、角色、握手、心跳、会话 patch 和关闭通知协议。
- Account 安全存储命名空间发生变化。升级后的应用需要重新登录一次，新的可恢复凭据才会写入
  应用自身命名空间；框架不会读取、迁移或删除旧 service 下的凭据。
- 不修改 HTTP 路径、Account DTO、授权规则、SQLx migration、PostgreSQL 基线或 Updater
  sidecar 协议。`/me` 仍必须携带真实 Bearer token 并校验本地账号状态。

## 从 0.34.0 升级

1. 把全部 Nexora workspace 依赖和 CLI 更新至 `v0.35.0`，重新生成 `Cargo.lock`。
2. 删除 `.single_instance(...)`、`.subprocess_windows(...)` 和
   `.restore_window_sessions(...)`；不要增加等价本地开关或第二套单例/窗口管理。
3. 删除对 `WindowSession`、`WindowSessionRole`、`WindowTabSession` 的导入、构造和测试。
   运行期额外窗口继续通过 Shell、`SettingsWindow` 和注册 `Window` API 打开。
4. 不要清除整个 `workspace.toml`。首次启动会迁移到 schema 2，仅保留主窗口位置状态和普通
   偏好；成功写回后退休窗口字段会消失。
5. 同步 `.agents/skills/develop-nexora-apps/SKILL.md` 和
   `.agents/skills/gpui-desktop-development/SKILL.md`。脚手架内嵌副本已经更新。
6. macOS/Windows 应用升级后重新登录一次，以写入新的应用身份级安全存储命名空间；不要读取
   或复制旧固定 service 中的凭据。
7. 在目标安装包验证冷启动只有主窗口、运行期多窗口、重复启动激活、主窗口几何保留，以及
   Account 连接/超时/契约/结构化拒绝的提示和临时/永久凭据策略。

回滚到 v0.34.0 不涉及数据库回滚，但旧版本仍可能读取尚未成功写成 schema 2 的窗口会话。
若 0.35.0 已成功保存 schema 2，旧的标签和额外窗口会话已经按产品要求永久丢弃。新命名空间
中的安全凭据不会被 v0.34.0 使用，回滚后可能需要再次登录。

## 验证

发布前已执行并通过：

- 使用 SemVer 解析器确认 `0.35.0` 严格高于最新已发布版本 `0.34.0`
- `cargo fmt --all --check`
- `cargo check --workspace --all-targets`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

测试包含单例重复启动激活、同一 GPUI 应用内多窗口、schema 0/1 迁移及迁移写盘重试、Account
连接失败、确定性超时、`200` 不兼容 JSON、结构化 `401/403`、非结构化响应、截断响应、request
ID 传播和脱敏 Debug 输出。脚手架门禁从无 `Cargo.lock` 的桌面项目及 Account 全栈项目重新解析
依赖，并编译桌面端、服务端和 migration 测试目标。

未执行连接真实 PostgreSQL/OIDC、签名、公证或 S3/RustFS 的外部环境验证。发布前未构建基于
0.35.0 的 iMES 安装包，因此真实 iMES 登录、窗口冷启动和 Keychain 迁移仍需由 iMES 升级任务
在 macOS 安装包中人工验收。
