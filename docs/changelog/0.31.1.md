# Nexora 0.31.1

发布日期：2026-08-07

## 摘要

本版本把 v0.30.2 的 Windows Inno Setup 修复与 PostgreSQL 17 Account 迁移基线修复整合到同一
发布提交。v0.31.0 因并行发布竞态建立在 v0.30.1 上，已由本版本取代；公开的 v0.31.0 tag
保持不可变。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- 修复 PostgreSQL 17 空库执行首个框架迁移时，命名列级 `NOT NULL` 约束没有注册为独立
  `pg_constraint`，导致 `COMMENT ON CONSTRAINT users_id_not_null` 失败的问题。新的基线保留
  全部 `NOT NULL` 语义与列注释。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 保留 v0.30.2 的 Inno Setup 参数、真实编译入口、简体中文语言文件路径和内嵌语言资源修复。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 修复 Windows 非法 Inno 路径测试夹具在进入生产校验前就创建非法目录的问题。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 使用 SQLx CLI 重新生成四组可逆 timestamp 框架基线；Account 表、索引、保护函数和权限种子
  语义不变。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- PostgreSQL 17 是当前框架迁移的最低受支持版本。列级非空语义使用 `NOT NULL` 与
  `COMMENT ON COLUMN` 表达。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本重新建立框架 SQLx 基线，属于破坏性迁移版本：

- v0.29.0 至 v0.30.2 的 `nexora._sqlx_migrations` 与 v0.31.1 不兼容。
- 不得修改旧 checksum、只删除迁移历史后在旧 schema 上运行新基线，或移动公开 tag。
- 已有部署必须先备份并验证恢复，再清库重建；新库仍先运行
  `nexora::server::migrate(&pool)`，再运行应用 Migrator。
- HTTP API、Account DTO、认证授权语义、Updater 协议与 `nexora.toml` schema 未改变。

## 从 0.30.2 升级

1. 停止服务，备份数据库及允许保留的业务数据，并完成恢复演练。
2. 把全部 Nexora 依赖和 CLI 更新到 Git tag `v0.31.1`，重新生成 lockfile。
3. 删除旧数据库并创建 UTF-8 空库；不要只删除 `account`/`nexora` schema 或历史表。
4. 在宿主唯一 `PgPool` 上先运行 Nexora v0.31.1 迁移，再运行应用迁移。
5. 只通过受审计的数据导入恢复允许保留的数据，不恢复旧 DDL、历史或 checksum。

回滚必须同时恢复 v0.30.2 二进制、依赖、lockfile 和升级前数据库快照。v0.31.1 down migration
不是旧历史转换工具。
