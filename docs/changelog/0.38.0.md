# Nexora 0.38.0

发布日期：2026-08-14

## 摘要

本版本为 Account 增加完整的非人类身份闭环：管理员可以创建 ZITADEL machine user，在统一用户
目录中管理服务账号资料、状态与角色，并生成、轮换或撤销 Client Credentials 和 PAT。Secret 与
PAT 只在成功创建时返回一次，Nexora 仅保存不可还原的凭据元数据。Bearer 认证同时支持本地
discovery/JWKS 校验的 JWT，以及每次请求实时 introspection 的 PAT/opaque token；桌面默认用户页
提供独立的服务账号创建、凭据管理与一次性密钥交付交互。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 新增 `human` / `service_account` 显式账号类型、服务账号说明字段、凭据元数据表与四项细粒度
  权限；迁移会为历史账号回填类型，并保持超级管理员为人员账号。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增服务账号创建与资料更新 API，以及凭据列出、创建/轮换和撤销 API；公开 contracts、
  `Account` facade、桌面 HTTP client 与 OpenAPI 契约同步覆盖这些资源。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 ZITADEL machine user、Client Secret 与 PAT 适配器。凭据创建使用服务账号范围内的
  `Idempotency-Key`，Client Secret 串行轮换，Provider 变更失败时执行补偿或返回稳定错误码。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增默认桌面服务账号 FormDialog、凭据管理面板与一次性 Secret/PAT 展示；人员账号和服务账号
  继续复用统一用户表、状态与角色入口，界面按权限隐藏或禁用高风险操作。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- Account Bearer 验证改为组合验证：JWT 继续使用 discovery/JWKS 本地验证，PAT 与其他 opaque
  token 每次请求都通过 ZITADEL `/oauth/v2/introspect` 实时验证，不缓存成功结果。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `/me` 对人员账号继续从 ZITADEL 刷新资料；服务账号直接返回本地授权快照，避免进入只适用于
  人员的资料同步路径。暂停服务账号会在本地状态门禁立即拒绝 JWT 与 PAT。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 用户列表的账号类型筛选改为显式 `user_type`；服务账号不自动获得 `member` 角色，初始角色仅由
  调用方提供，并复用统一的角色替换与权限蕴含规则。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Account workspace 脚手架配置模板新增 introspection Client ID/Secret 占位值及安全注释；本版
  没有修改 `.agents/skills`、宏规则或生成项目结构，下游无需同步新的 Skill。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Security

- Client Secret 和 PAT 明文不写入数据库、日志、Debug 输出或凭据列表，只在创建成功响应中交付
  一次；列表与协调仅保存 Provider ID、类型、时间、状态、来源和操作者等非敏感元数据。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- PAT/opaque token 的 Provider 不可用、inactive、issuer 不符或 audience 不符都会失败关闭；
  introspection Secret 通过专用敏感配置注入并在 Debug 中脱敏。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 服务端 `[oidc]` 配置新增必填 `introspection_client_id` 与
  `introspection_client_secret`。0.37.0 只需要 issuer、audience 与管理 PAT；0.38.0 在启动时还会
  建立 PAT/opaque token introspection 验证器，缺失或无效的 resource-server 凭据会使初始化失败。
- 直接构造 `AccountDependencies` 的宿主必须新增
  `service_account_directory: Option<Arc<dyn ServiceAccountDirectory>>`。不需要服务账号管理时显式
  传 `None`；ZITADEL 组合入口会传入与人员目录共用的 `ZitadelUserDirectory`。
- 新迁移新增 PostgreSQL enum、`account.users.user_type`、`description`、索引、
  `account.service_account_credentials` 与四项权限。历史超级管理员回填为 `human`；其他历史账号中
  username 与 email 同时为空的记录回填为 `service_account`，其余回填为 `human`。上线前应确认这
  条历史数据分类符合部署实际。
- 新增 HTTP 路径和 DTO 为增量契约，但 `User` 响应增加 `description`，`user_type` 语义从历史
  推断改为数据库显式值。0.x 阶段的必填配置、公开构造结构和数据分类变化要求版本递增 MINOR。

旧配置：

```toml
[oidc]
issuer_url = "https://identity.example.com"
audience = "nexora-api"
organization_id = "zitadel-organization-id"
project_id = "zitadel-project-id"
personal_access_token = "replace-through-secret-injection"
```

新配置：

```toml
[oidc]
issuer_url = "https://identity.example.com"
audience = "nexora-api"
organization_id = "zitadel-organization-id"
project_id = "zitadel-project-id"
personal_access_token = "replace-through-secret-injection"
introspection_client_id = "nexora-resource-server-client-id"
introspection_client_secret = "replace-through-secret-injection"
```

旧构造：

```rust
AccountDependencies {
    pool,
    token_verifier,
    identity_directory,
}
```

新构造：

```rust
AccountDependencies {
    pool,
    token_verifier,
    identity_directory,
    service_account_directory: None,
}
```

## 从 0.37.0 升级

1. 在 ZITADEL 为 API resource server 准备可调用 introspection 的 Client ID/Secret，并通过
   `OIDC__INTROSPECTION_CLIENT_ID` 与 `OIDC__INTROSPECTION_CLIENT_SECRET` 或密钥系统注入；不要
   复用或提交管理 PAT、Client Secret 与任何已生成 PAT。
2. 把全部 Nexora workspace 依赖和 CLI 切换到 Git tag `v0.38.0`，删除临时本地 path/patch，
   然后重新生成 `Cargo.lock`。
3. 若宿主直接构造 `AccountDependencies`，增加 `service_account_directory`；暂不启用 Provider
   服务账号管理时传 `None`，需要完整 ZITADEL 能力时复用 `ZitadelUserDirectory`。
4. 备份数据库并审计历史 `account.users` 中 username 与 email 同时为空的非超级管理员，确认其
   应作为服务账号。随后在唯一共享 `PgPool` 上先运行 `nexora::server::migrate(&pool)`，再运行
   应用自己的 SQLx Migrator，最后调用 `Server::initialize`。
5. 根据职责向管理员角色授予 `service_accounts:provision`、`service_accounts:profile.write`、
   `service_accounts:credentials.read` 和 `service_accounts:credentials.write`；后者会蕴含读取权限。
6. 部署后验证 JWT 登录、PAT introspection、服务账号暂停门禁、一次性凭据交付、Client Secret
   轮换、PAT 撤销以及人员账号的原有创建/状态/角色流程。

回滚前必须先在 ZITADEL 撤销本版创建的 Client Secret/PAT，并按需停用或删除 machine user，
否则只回滚本地数据库会留下仍可在 Provider 使用的孤儿凭据。随后备份服务账号及凭据元数据，
停止 0.38.0 实例，执行本迁移的 down，再部署 0.37.0 并恢复旧配置。down 会永久删除四项权限、
全部凭据元数据、显式账号类型和说明字段，不会自动撤销 Provider 资源；已有服务账号数据无法由
0.37.0 表达，因此回滚不是无损操作。
