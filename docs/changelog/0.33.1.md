# Nexora 0.33.1

发布日期：2026-08-11

## 摘要

本补丁版本补全 `ApplicationOptions::subprocess_windows(false)` 的既有契约：应用可以继续启用
单例门禁、完整多窗口、窗口会话恢复和托盘，同时让全部 Shell、唯一 Settings 与注册 Window
运行在同一个 GPUI 进程中。默认的受管子进程窗口模式保持不变。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- 关闭子进程窗口承载后，“使用新窗口打开”现在会在当前 GPUI 事件循环中创建新的完整 Shell，
  不再只生成会话而没有实际窗口。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 同进程模式现在会恢复、持久化并在单独关闭时清理额外 Shell、唯一 Settings 和全部注册 Window
  会话；完整路由与 query、标签顺序、置顶分区、活动标签、显示器 UUID、窗口边界和最小化状态
  继续使用 v0.33.0 的 `workspace.toml` schema。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 多个同进程 Shell 不再互相覆盖全局导航处理器。`Context<T>::navigate` 会选择 Entity 所在窗口
  的 Shell，`App::navigate` 会选择活动 Shell，来源不可用时确定性回退到主 Shell。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Settings 与注册 Window 改为按真实窗口 ID 跟踪会话和最终边界，单进程与子进程模式都不再把
  第一个窗口误当作唯一独立窗口。无效恢复路由只记录警告并跳过，不会中止整个应用。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 更新 `develop-nexora-apps` 与 `gpui-desktop-development` Skill，明确“应用单例”与“单个操作系统
  进程”的区别，以及两种窗口承载模式下统一的导航和状态边界。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 没有公开 API、配置 schema、HTTP API、Account DTO、SQLx migration、数据库基线或 Updater
  协议破坏性变更。
- `subprocess_windows` 的默认值仍为 `true`；未显式设置该选项的应用继续使用 v0.33.0 的受管
  子进程窗口架构。
- `subprocess_windows(false)` 现在只改变窗口承载方式，不再隐式削弱窗口创建、恢复或导航能力。

## 从 0.33.0 升级

1. 把全部 Nexora 依赖与 CLI 更新为 `v0.33.1`，并重新生成 lockfile。
2. 需要严格单个操作系统进程的应用显式保留
   `.single_instance(true).subprocess_windows(false).restore_window_sessions(true).tray_enabled(true)`；
   只写 `.subprocess_windows(false)` 时其余三项已经沿用默认 `true`。
3. 同步本版本的 `.agents/skills/develop-nexora-apps` 和
   `.agents/skills/gpui-desktop-development`，避免继续把默认单例行为误解为严格单进程。
4. 在目标平台人工验证新增 Shell、Settings 单例、注册 Window、重启恢复、重复启动激活和托盘
   窗口组命令。

回滚到 v0.33.0 不需要数据库或配置迁移；但依赖同进程完整多窗口能力的应用会重新遇到
`subprocess_windows(false)` 的旧缺陷，应先恢复受管子进程模式再回滚。

已执行并通过：

- `cargo test -p nexora --features desktop,derive --test application --test runtime --test preferences`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

当前环境没有执行 Windows/Linux 手工 GUI 验收，也没有连接外部 PostgreSQL、OIDC、签名、公证或
S3/RustFS 发布环境。本版本不修改这些协议或集成边界；下游应用仍应按升级步骤在目标平台回归
窗口创建、恢复、重复启动激活和托盘命令。
