# Nexora 0.42.0

发布日期：2026-08-22

本版本为 `stable`、`beta`、`nightly` 建立不可混用的本机安装身份，使安装目录、进程单例、
updater 状态与操作日志、Account 登录凭据和用户偏好按通道隔离；同时为 updater 增加有界、
尽力而为且不影响更新事务的本地操作日志。

## 新增

- CLI 现在从 stable 基础值为 beta 固定派生 `<app_id>.beta` / `<display_name> Beta`，为 nightly
  固定派生 `<app_id>.nightly` / `<display_name> Nightly`。派生身份贯穿 bundle/Setup AppId、
  默认安装目录、快捷方式与外部分发文件名、进程单例与激活 IPC、updater 状态、Account 凭据
  和用户偏好；stable 继续使用原有基础身份与数据位置。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 正式安装包新增纯文本 `nexora-install-identity` 标记。Windows 安装器仅允许空目录、身份匹配
  的现有目录，或能由同一 AppId 的 HKCU 卸载登记识别出的历史 stable 目录；运行时 updater
  也会验证当前包、暂存包和恢复中的待安装包，拒绝跨通道替换。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- 每次 updater 检查、下载或完整更新都会在当前通道状态目录的 `logs` 子目录建立操作会话。
  主进程写入 `main.log`，安装 sidecar 在同一会话续写 `sidecar.log`；仅保留最近 10 个会话，
  每个会话合计最多 1 MiB，并遮蔽凭据字段与 URL 查询参数。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 变更

- 正式包中的可信发布身份现在优先于 `ApplicationOptions::application_identity`。该选项仍可为
  没有正式发布元数据的开发和测试进程指定身份，但不能再把已签入安装包的通道身份改写成
  其它值。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- CLI 会拒绝基础 `app_id`、可选 `updater.app_id` 已以 `.beta`/`.nightly` 结尾，或基础
  `display_name` 已以 ` Beta`/` Nightly` 结尾的配置，防止重复派生或伪造通道身份。Windows
  安装器也不再用三个通道共享的技术 EXE 文件名作为关闭其它应用的过滤条件。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

- updater 操作日志采用尽力而为语义：日志目录创建、锁定、写入或轮转失败只产生告警，不会
  改变检查、下载、替换、健康确认或回滚事务的结果。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：无

## 兼容性与破坏性变更

- 这是 early-alpha `0.x` 阶段的破坏性 `MINOR` 版本。`stable` 的 app ID、显示名称、安装目录、
  单例、凭据、偏好和 updater 状态均保持原位置，可以原地升级。
- `v0.41.2` 及更早版本构建的 beta/nightly 使用过与 stable 相同的本机身份；`v0.42.0` 不读取、
  迁移或删除这些旧数据。beta/nightly 用户必须把新版本安装到各自的新目录，并重新登录、重新
  设置偏好。不要把旧凭据、偏好或 updater 状态手工复制到新通道。
- 旧配置如果把 `.beta`、`.nightly`、` Beta` 或 ` Nightly` 手工写入基础值，将在 CLI 校验阶段
  失败。旧写法如 `app_id = "com.example.app.beta"`；新写法统一为无后缀的
  `app_id = "com.example.app"`，由所选 channel 自动派生。`updater.app_id` 与 `display_name`
  使用同一规则。
- 正式安装场景中，运行时 `application_identity` 覆盖不再生效；开发与测试运行没有
  `nexora-release.json` 时的行为不变。依赖运行时覆盖来混用正式安装身份的应用必须改为分别
  构建对应 channel。
- 回滚到 `v0.41.2` 或更早版本不会读取新 beta/nightly 的隔离数据，并可能重新落回旧共享身份；
  回滚时应保留各通道新目录，不要让旧安装器覆盖它们。stable 的原地回滚路径不受影响。
- `nexora-release.json` schema、签名清单、对象存储布局、HTTP API、OpenAPI 契约和数据库结构
  均未改变；`docs/public/openapi.yaml` 仅同步发布元数据版本到 `0.42.0`。

## 从 0.41.2 升级

1. 将所有 Nexora Git 依赖与 CLI 安装 tag 从 `v0.41.2` 更新为 `v0.42.0`，运行
   `cargo update` 并确认 workspace package 均解析到新版本。
2. 检查 `nexora.toml`：为 stable 保留无通道后缀的基础 `app_id`、可选 `updater.app_id` 和
   `display_name`；删除曾经手工添加的 beta/nightly 后缀。
3. 使用 `v0.42.0` CLI 分别重建 stable、beta、nightly。stable 可以继续原目录升级；beta 和
   nightly 必须使用新安装包与各自默认的新目录，用户随后重新登录并设置偏好。
4. 不要迁移或复制旧通道的凭据、偏好、updater 状态及日志；如需回退 beta/nightly，保留新旧
   安装目录并明确选择对应版本，不要交叉覆盖。
5. 脚手架 `nexora.toml` 已补充基础身份注释；已有项目无需重新生成，但应按第 2 步人工核对。
   本版本未修改 `.agents/skills`，下游无需同步 Skill。
