# Nexora 0.31.0

> 此版本建立在 v0.30.1 上，未包含并行发布的 v0.30.2 Windows Inno 修复；请使用 v0.31.1。

发布日期：2026-08-07

## 摘要

本版本修复 Nexora v0.29.0 至 v0.30.1 框架基线无法在 PostgreSQL 17 空库执行的问题。新的
Account 基线保留全部 `NOT NULL` 数据约束和列注释，但不再给列级 `NOT NULL` 声明仅在
PostgreSQL 18 才会注册为独立 `pg_constraint` 的约束名，也不再尝试通过
`COMMENT ON CONSTRAINT` 注释这些对象。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- 修复首个框架迁移在 PostgreSQL 17 上执行到 `COMMENT ON CONSTRAINT users_id_not_null` 时返回
  `constraint "users_id_not_null" for table "users" does not exist`，导致全新数据库无法启动的
  问题。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加迁移源码回归测试，禁止重新引入命名 `NOT NULL` 列约束及其约束注释，同时确认关键列
  继续保持 `NOT NULL`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 修复 Windows 上非法 Inno Setup 路径测试先创建非法临时目录、尚未进入生产校验逻辑即失败的
  测试夹具问题；测试现在直接验证路径定义边界。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 使用 SQLx CLI 重新生成四组可逆 timestamp 框架基线；Account 表结构、权限目录、保护函数、
  索引和种子权限语义保持不变。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 明确 PostgreSQL 17 为当前框架迁移的最低受支持数据库版本，并记录列级非空语义应通过
  `NOT NULL` 与 `COMMENT ON COLUMN` 表达。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本再次建立框架 SQLx 基线，因此属于破坏性迁移版本：

- v0.29.0、v0.30.0 和 v0.30.1 的 `nexora._sqlx_migrations` 与 v0.31.0 不兼容。
- 不得修改旧迁移 checksum、删除旧历史表后在原 schema 上强行运行新基线，或恢复旧 DDL。
- 已有数据库必须先保护需要保留的业务数据，然后清库重建；新库仍先执行
  `nexora::server::migrate(&pool)`，再执行应用自己的 Migrator。
- HTTP API、Account DTO、认证授权语义、桌面 UI、Updater 协议和 `nexora.toml` schema 均未
  改变。

## 从 0.30.1 升级

1. 停止旧服务，备份数据库及允许保留的业务数据，并确认 v0.30.1 数据库快照可恢复。
2. 把全部 Nexora workspace 依赖更新为 `0.31.0` 或 Git tag `v0.31.0`，重新生成 lockfile，
   并重新安装 v0.31.0 CLI。
3. 删除旧数据库并创建 UTF-8 空库；不要只删除 `account`/`nexora` schema 或迁移历史表。
4. 在同一个宿主 `PgPool` 上先运行 Nexora v0.31.0 框架迁移，再运行应用迁移。
5. 只通过受审计的数据导入流程恢复允许保留的业务数据；不得恢复旧 migration history、旧 DDL
   或旧 checksum。

回滚到 v0.30.1 时必须同时恢复升级前的 v0.30.1 二进制、依赖、lockfile 和数据库快照；
v0.31.0 down migration 不是旧历史转换工具。

## 验证

当前已执行并通过：

- `cargo fmt --all --check`
- `cargo test --workspace --all-targets --locked`
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
- `cargo run -p cli --locked -- lint --workspace . --deny-warnings`
- `cargo test -p migrate --all-features --test data_preservation`
- `cargo test -p account --no-default-features --features database-tests --test postgres_store`
- 使用真实 Inno Setup 6.7.3 执行 `installed_inno_setup_reports_pinned_engine_version`
- `scripts/check-scaffold-consumer.sh`
- `bun install --frozen-lockfile && bun run build`（`docs/`）
- 在 PostgreSQL 17 隔离空库执行完整框架 migration `run`
- 对同一隔离库重复执行 `run`，确认幂等
- 执行 `migrate info`
- 执行 `revert latest` 后重新 `run`

本版本不修改 Skill 或脚手架结构；下游只需同步版本与上述数据库重建规则。
