# Nexora 0.27.1

发布日期：2026-08-05

## 摘要

本版本修复 Windows GUI 应用的 MSVC 入口点选择：`nexora build` 在设置
`/SUBSYSTEM:WINDOWS` 时同步传递 `/ENTRY:mainCRTStartup`，使只定义 Rust `main` 且没有声明
`windows_subsystem` crate 属性的应用也能正确链接。主程序与 updater sidecar 共用同一参数
边界，不改变安装器、更新协议或项目配置。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- Windows 主程序和 updater sidecar 的 `cargo rustc` 参数现在同时包含 PE 资源、
  `/SUBSYSTEM:WINDOWS` 与 `/ENTRY:mainCRTStartup`，避免 MSVC 转而查找未定义的 `WinMain`
  并报出 LNK2019/LNK1120。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加 Windows 链接参数回归测试，固定主程序和 sidecar 所使用的 GUI 子系统与
  Rust CRT 入口点。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 清理 `v0.27.0` 在 Windows 上的未使用导入和等价条件表达式告警，恢复 CLI 的
  `-D warnings` 发布门禁，不改变 CLI 自更新逻辑。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本没有破坏性变更，没有数据库迁移、Account HTTP 契约、更新 manifest、远程对象
布局或 `nexora.toml` 配置变更。已升级到 `0.27.0` 的项目无需手工迁移。

## 从 0.27.0 升级

1. 把 Nexora 依赖更新为 `0.27.1` 或 Git tag `v0.27.1`，然后重新生成 lockfile。
2. 重新安装独立 CLI：

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.27.1 cli --locked --force --bin nexora
   ```

3. 重新执行 Windows 应用的 `nexora build`。不需要为应用补充 `WinMain`，也不需要
   修改 `nexora.toml`。
4. 本版本没有修改脚手架 Skill、更新协议或自定义宏规则，下游项目无需额外同步
   `.agents/skills`，也不需要 `cargo expand`、bench、bloat 或 asm 验证。
