# Nexora 0.43.0

发布日期：2026-08-22

本版本允许安装了 `AccountAuthenticator` 的桌面应用显式开放少量不依赖账号的独立 Window，
例如关于页或许可信息；其他业务窗口仍保持登录门禁。白名单使用注册表中的稳定 Window ID，
并在 GPUI 事件循环启动前完成严格校验。

## 新增

- `ApplicationOptions` 新增
  `unauthenticated_window("window-id")` 构建器。应用可以按区分大小写的稳定 ID 登记未登录时
  仍可打开的 `#[derive(nexora::Window)]`；既有 `settings` Window 继续默认放行，无需重复登记。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
  — 关联 Issue/PR：
  [xuwe-projects/nexora#3](https://github.com/xuwe-projects/nexora/pull/3)、
  [xuwe-projects/imes#294](https://github.com/xuwe-projects/imes/issues/294)

- 应用在 `Application::validate()` 和 `run()` 进入 GPUI 事件循环前校验白名单。不存在的 ID、
  Feature 或 NavigationGroup ID、大小写不匹配和重复登记都会返回结构化 `ApplicationError`，
  避免启动后才暴露配置错误。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 变更

- Shell 开窗门禁与运行时测试现在共用同一认证策略。白名单只跳过独立 Window 的未登录门禁，
  不会创建或伪造登录会话；随后仍执行既有的强类型路由提取、Window factory、原生开窗和
  生命周期流程。未登记窗口仍返回认证错误，登录后的行为不变。

  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

- 中英文应用文档、`define-page` 与 `develop-nexora-apps` Skill，以及 CLI 随脚手架分发的对应
  Skill 模板已同步未登录 Window 约束。

## 兼容性与破坏性变更

- 这是从 `v0.42.0` 递增的向后兼容 `MINOR` 功能版本；没有删除或改变既有公开 API。
- 未安装 `AccountAuthenticator` 的应用行为不变。安装认证器的应用仍默认只在未登录时放行
  `settings`；只有显式登记且通过校验的额外独立 Window 会获得同样的开窗权限。
- 本版本不改变 HTTP API、OpenAPI 契约内容、Account 会话协议、Updater 协议、配置格式或
  数据库结构；`docs/public/openapi.yaml` 仅同步发布元数据版本到 `0.43.0`。
- 回滚到 `v0.42.0` 前，使用新构建器的下游应用必须移除
  `.unauthenticated_window(...)` 调用才能重新编译。回滚不会修改数据，但额外 Window 将恢复为
  登录后才能打开。

## 从 0.42.0 升级

1. 将全部 Nexora Git 依赖与 CLI 安装 tag 从 `v0.42.0` 更新为 `v0.43.0`，运行
   `cargo update` 并确认 workspace package 均解析到新版本。
2. 仅在确有关于页、许可信息等不依赖账号的独立 Window 时，在
   `ApplicationOptions` 上添加 `.unauthenticated_window("稳定-window-id")`。ID 必须精确匹配
   `#[derive(nexora::Window)]` 的注册 ID，并且每个 ID 只能登记一次。
3. 启动或显式调用 `Application::validate()`，让未知、类型错误、大小写不匹配或重复的 ID 在
   进入事件循环前失败。不要把 Feature 或 NavigationGroup 加入白名单，也不要把该能力当作
   Account 认证替代方案。
4. 本版本修改了 `.agents/skills/define-page`、`.agents/skills/develop-nexora-apps` 及脚手架中的
   对应模板；依赖这些规则的下游项目应同步最新 Skill。未自定义相关 Skill 的已有项目无需改动
   应用代码。
5. 无需数据库迁移、配置迁移、重新登录或停机；不使用新能力的应用只需更新依赖并重新构建。

Provider、S3/OSS 凭据或真实签名证书的集成验证。

完整 workspace 测试已通过；其中 3 个依赖显式 Windows 工具环境的既有测试仍按仓库默认配置
保持忽略：`installed_inno_setup_compiles_generated_installer_source`、
`installed_inno_setup_reports_supported_engine_version` 和
`windows_runner_reads_distinct_unicode_version_info_from_actual_pe_files`。前两项需要配置
`NEXORA_TEST_ISCC`，后一项需要实际 Windows PE 工具链环境。
