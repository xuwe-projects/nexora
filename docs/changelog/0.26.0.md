# Nexora 0.26.0

发布日期：2026-08-04

## 摘要

本版本补全 Windows x86_64/ARM64 从 WiX MSI、Burn Setup EXE、应用内更新 ZIP 到对象存储
发布和失败回滚的完整链路，并为所有正式产物增加统一的 `nexora-release.json` 发布身份与经过
大小、SHA-256、UTF-8 和链接安全校验的 Markdown 版本日志。桌面应用可读取真实 app ID、版本、
构建号与通道；更新完成页只展示本地或远程验证通过的日志。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- Windows 构建同时支持 x86_64 与 ARM64 的 WiX MSI、Burn Setup EXE 和 `windows.zip`，并为
  安装器生成架构专用 `latest-<arch>.exe` / `latest-<arch>.msi`；单目标发布额外生成
  `latest.exe` / `latest.msi`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 正式 macOS 与 Windows 产物在签名和归档前写入 `nexora-release.json`，记录 app key/ID、
  display name、package、SemVer、正整数 build number、channel、target 和可选日志摘要；
  `nexora::desktop::application_info` 向应用暴露经过校验的只读发布身份。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- `release.notes` 支持默认值和 channel 覆盖；build 把源 Markdown 冻结为版本化 `notes.md`，
  publish 在签名 manifest 中加入 URL、大小与 SHA-256，客户端验证后才下载和渲染。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 更新完成 Dialog 增加版本、构建号和可信 Markdown 日志，并对“立即重启”“稍后重启”和
  健康确认后的完成状态保持统一的一次性流程。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 默认脚手架新增 `release-notes.md`，Windows 示例补齐运行时配置、sidecar、构建和发布说明。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- Windows 应用内更新暂存区移动到安装目录同卷的隐藏兄弟目录；退出前预检替换权限，
  `pending.json` 以可覆盖旧记录的原子方式提交，临时 sidecar 不再把安装目录保持为工作目录。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 替换失败会恢复并重新启动旧版本，将失败结果持久化到下一次启动；无 Authenticode
  模式仍执行 Ed25519、SHA-256、ZIP 路径和 PE 架构校验，有 Authenticode 模式继续校验证书链、
  thumbprint 与 publisher。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `apps.<app>.targets.required` 改为可选；`nexora build` 默认使用 `rustc -vV` 的 host target，
  也可重复传入 `--target` 显式构建指定目标，不再隐式安装 Rust target。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- updater bundle 加载会交叉校验 `nexora-updater.json` 与 `nexora-release.json` 的 app ID、
  version、build number 和 channel；已有元数据文件非法时不允许回退开发模式。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- 版本日志 HTTP 请求沿用 updater 的 HTTPS/显式 HTTP 策略，并在每次重定向时重新校验目标，
  防止通过跳转绕过传输安全边界。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Windows 启动从主 EXE 同级加载 updater 配置和发布元数据，不再误走 macOS `.app` 路径；GUI
  主程序与 sidecar 不创建多余控制台窗口。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 更新 ZIP 由 Rust 直接生成并固定使用 `/` 条目分隔符，避免 PowerShell 反斜杠归档
  被安全解压器拒绝。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 发布计划同时保留 Windows 安装器别名与可信 notes 上传、匿名校验和签名字段，避免两条并行
  实现互相覆盖。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本没有数据库迁移，但对启用 updater 的正式构建收紧了配置和 bundle 契约：

- `apps.<app>.release.notes` 现在是启用 updater 时的必填能力，可在 channel 下覆盖。路径必须是
  workspace 内不越界的 UTF-8 Markdown，大小不超过 1 MiB。
- 通过 `UpdateConfig::from_current_bundle`、`from_app_bundle` 或 `from_windows_install_dir` 加载的
  正式 bundle 必须同时包含合法 `nexora-release.json`。旧安装包需要使用 0.26.0 CLI 重新构建，
  不能只替换框架依赖。
- 签名 manifest 的 notes 完整性字段保持向后兼容；旧 manifest 仍可检查和安装更新，但客户端在
  URL、大小或 SHA-256 任一缺失时不会下载日志。

Windows 安装器从旧的简化路径升级到 WiX MSI + Burn Setup EXE。首次安装、升级、卸载和真实
自动更新仍应在目标 Windows x86_64/ARM64 环境执行验收。

## 从 0.25.0 升级

1. 将全部 Nexora 依赖和 CLI 安装 tag 更新到 `v0.26.0`，重新生成 lockfile。
2. 为每个启用 updater 的 app 在 `[apps.<app>.release]` 增加 `notes = "..."`，需要不同日志时在
   `[apps.<app>.release.channels.<channel>]` 覆盖；可从脚手架 `release-notes.md` 开始维护。
3. 使用新 CLI 重新执行 `nexora build`，确认 macOS Resources 或 Windows EXE 同级同时存在
   `nexora-updater.json`、`nexora-release.json` 和 `notes.md`。
4. Windows 发布机安装固定 revision 的 `cargo-wix`、WiX 5.0.2 以及匹配的 UI/
   BootstrapperApplications 扩展，然后运行 `nexora doctor --fix`、build 和 publish dry-run。
5. 检查 CI 中的 target 参数：未声明 `targets.required` 时默认只构建 host；需要多目标时显式重复
   `--target`，完整 stable 发布仍必须包含项目要求的全部目标。
6. 下游项目同步 `.agents/skills/develop-nexora-updater`、`updater-protocol.md` 和最新脚手架约束，
   让后续实现遵守 Windows 同卷暂存、可信发布元数据与版本日志规则。本版本未修改自定义宏规则。
