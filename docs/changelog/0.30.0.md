# Nexora 0.30.0

发布日期：2026-08-06

## 摘要

本版本把 Windows 首次安装程序从 cargo-wix、WiX 5、MSI 与 Burn 完整迁移到固定版本
Inno Setup 6.7.3。nexora build 现在只生成简体中文 Setup EXE 与 sidecar 更新 ZIP；
应用内更新、Ed25519 清单、SHA-256、安全解压、同卷事务替换、健康检查、回滚和 S3 发布
顺序保持不变。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 新增框架维护的静态 Inno Setup .iss 模板，支持简体中文现代向导、当前用户安装、安装目录
  选择、桌面与开始菜单快捷方式、完成后运行、标准静默参数和运行中主程序关闭。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增严格的 ISCC 预处理参数校验，覆盖 Unicode、空格、引号、控制字符、Windows 非法路径、
  Inno AppId 长度，以及彼此独立的 x86_64/ARM64 架构限制。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- nexora build 与 nexora doctor --fix 现在检测精确版本 Inno Setup 6.7.3；交互式 Windows
  终端可通过 winget 官方 JRSoftware.InnoSetup 包修复，非交互环境只输出完整安装命令。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- Windows 安装固定为无需提升权限的当前用户范围，默认目录为
  %LOCALAPPDATA%\Programs\<app_id>；后续相同 AppId 安装执行 Inno 原地升级。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Setup EXE 与更新 ZIP 复用同一 staging，其中包含已按配置签名的主程序、updater sidecar、
  updater 配置、runtime 配置和 release resources；最终 Setup EXE 继续使用现有可选
  Authenticode 边界签名。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows artifact.json 只记录 windows_setup_exe 与 windows_update_zip。publish 上传
  两项产物及其 SHA-256，但签名 latest.json 仍只引用 windows_update_zip。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 同步 develop-nexora-updater Skill、脚手架副本、Windows updater 示例和中英文配置/
  updater 文档，使安装、构建、发布和真机验收契约与 Inno Setup 一致。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Removed

- 删除 cargo-wix、WiX CLI、WiX UI/Bootstrapper 扩展、Nexora 管理的 .NET SDK、动态 .wxs
  生成、MSI 和 Burn bundle 构建逻辑。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 删除 platforms.windows.installer 与 platforms.windows.install_scope 配置字段，以及
  WindowsMsi、msi_path 和 windows_msi 发布产物契约。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

这是配置和发布产物契约的不兼容变更。v0.30.0 不读取旧的 Windows 安装器选择或 machine
scope 字段，也不生成、校验或发布 MSI。项目尚未正式发布旧 WiX/MSI 安装程序，因此本版本
不迁移旧安装记录、UpgradeCode 或卸载项。

旧配置：

~~~toml
[apps.desktop.platforms.windows]
icon = "assets/logos/desktop/logo-icon.ico"
installer = "wix"
install_scope = "user"
publisher = "Example Publisher"
~~~

新配置：

~~~toml
[apps.desktop.platforms.windows]
icon = "assets/logos/desktop/logo-icon.ico"
publisher = "Example Publisher"
~~~

## 从 0.29.0 升级

1. 把所有 Nexora workspace 依赖更新为 0.30.0 或 Git tag v0.30.0，重新生成 lockfile，
   并重新安装 v0.30.0 CLI。
2. 从所有 app 的 Windows 配置中删除 installer 和 install_scope；当前用户范围现在由
   框架固定。
3. 更新读取 artifact.json 或发布目录的内部脚本：移除 windows_msi，只要求
   windows_setup_exe 与 windows_update_zip 及其 .sha256。
4. Windows 构建机运行 nexora doctor --fix，安装固定版本 Inno Setup 6.7.3 与 Windows
   SDK，然后重新执行 nexora build。
5. 下游项目手工同步 .agents/skills/develop-nexora-updater；现有 Skill 不会被
   nexora init 覆盖，应以 v0.30.0 脚手架副本更新其中的 updater protocol。
6. 在 Windows 11 分别完成 x86_64/ARM64 构建、交互/静默安装、卸载、原地升级、运行中程序
   处理和 sidecar 更新回滚冒烟，再将产物进入生产发布。

回滚到 v0.29.0 时，需要同时恢复旧配置字段、WiX/.NET 构建依赖和包含 MSI 的 artifact
消费逻辑；不要让 v0.29.0 publish 读取 v0.30.0 的双产物 artifact.json。

## 验证

发布前实际执行并通过：

- cargo fmt --all --check
- cargo test --workspace --all-targets
- cargo clippy --workspace --all-targets --all-features -- -D warnings
- cargo run -p cli -- lint --workspace . --deny-warnings
- bash scripts/check-scaffold-consumer.sh
- cd docs && bun install --frozen-lockfile && bun run build
- 当前生效的 CLI 源码、模板、updater protocol、配置文档和 Windows 示例已扫描确认不存在
  WiX、cargo-wix、Burn、MSI、.NET 或已删除配置字段的打包依赖。

当前发布宿主为 macOS，尚未执行 Windows 11 上的 nexora doctor --fix、ISCC 实际编译、
交互/静默安装与卸载、原地升级、运行中程序关闭、Authenticode 和已安装应用 sidecar
更新/回滚冒烟；本版本不把这些项目声明为已验证。
