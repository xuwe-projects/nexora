# Nexora 0.32.0

发布日期：2026-08-07

## 摘要

本版本完成桌面更新构建、发布与 Windows 安装事务的生产化收口。CLI 现在只读检查宿主依赖，
Windows 首次安装支持 Inno Setup 6/7 并使用发布者与展示名称组成默认目录；sidecar 使用已验证的
精确主 EXE 身份，且在应用内更新后保留 Inno Setup 卸载能力。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 为 updater-enabled release 强制冻结 Markdown release notes，并把校验后的日志、摘要和元数据
  写入安装包与更新产物。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加多 channel 选择、动态构建号收据、标准 SHA-256 旁车、S3/RustFS 发布凭据逐字段回退和
  Windows/macOS 真实验收文档。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora doctor` 与 `nexora build` 对 Rust target、Windows SDK、Inno Setup、Xcode 和打包工具
  只执行检测，不再下载、安装、打开页面或修改 PATH；诊断会给出官方入口与可复制的人工命令。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 首次安装接受 Inno Setup `>= 6.7.3, < 8.0.0`，CI 固定验证 7.0.2。新安装默认目录改为
  `%LOCALAPPDATA%\Programs\<publisher>\<display_name>`；`app_id` 继续只承担稳定安装、更新和发布
  身份。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `nexora build` 默认使用 `rustc -vV` 的 host target，`targets.required` 降为兼容项；交互模式
  支持 channel 选择，CI 使用显式 `--channel`/`--all-channels`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- publish 凭据按 channel 专用 `NEXORA_PUBLISH_*`、基础 `NEXORA_PUBLISH_*`、`AWS_*` 逐字段
  回退，空值继续回退；构建号使用本地时区的 `yyMMddHHmmss` 并保持严格递增。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- Windows sidecar 不再扫描安装目录猜测主程序，而是将更新 ZIP 已验证的主 EXE 名称显式传给
  helper，用于预检、健康启动和失败恢复；Inno Setup 的 `unins000.exe` 不再触发“多个候选主
  EXE”。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 更新目录切换后从回滚备份保留 `unins<数字>.exe/.dat/.msg`，并拒绝更新 ZIP 覆盖这些
  文件，保证 Apps & Features 卸载入口在更新后继续有效。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Windows 工具探测会验证所有 Inno Setup 6/7 候选的实际 compiler engine version，忽略损坏或
  不兼容候选并选择最高兼容版本。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Removed

- 删除 `nexora doctor --fix`、CLI 自动安装宿主依赖的路径和独立 `windows-tooling.yml` workflow。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 删除 `nexora.toml` 的 `credential_env_prefix`；`RUSTFS_*` 不再作为发布凭据来源。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- CLI 脚本必须把 `nexora doctor --fix` 改为 `nexora doctor`，再由操作者执行诊断给出的人工安装命令。
- 发布配置必须删除 `credential_env_prefix`，并改用 `NEXORA_PUBLISH_<CHANNEL>_<FIELD>`、
  `NEXORA_PUBLISH_<FIELD>` 或 `AWS_<FIELD>`。
- 启用 updater 的每个实际 release/channel 必须配置可读取的 UTF-8 Markdown `release.notes`。
- `publisher` 与 `display_name` 必须是安全的 Windows 目录组件；新的默认目录只影响首次安装，
  已有 Inno Setup 安装继续沿用原目录。
- 本版本不修改 HTTP API、Account DTO 或 SQLx 基线。已按 v0.31.1 完成 PostgreSQL 17 清库重建的
  项目无需再次清库重建。

## 从 0.31.1 升级

1. 把全部 Nexora 依赖与 CLI 更新为 `v0.32.0`，重新生成 workspace 和示例 lockfile。
2. 删除 `credential_env_prefix`，为 updater-enabled release 增加 `notes = "path/to/notes.md"`。
3. 把自动执行 `doctor --fix` 的脚本改为只运行 `doctor`，在构建机镜像或人工准备阶段安装依赖。
4. 检查 Windows `publisher`、`display_name` 和新安装默认目录；已有安装无需迁移目录。
5. 同步 `.agents/skills/develop-nexora-updater` 及 CLI 内置模板，再重新构建首次安装包和更新 ZIP。

回滚到 v0.31.1 时必须同时恢复 CLI、框架依赖、lockfile 与旧发布配置。数据库无需因本版本单独
恢复，但仍必须遵守 v0.31.1 的 PostgreSQL 17 基线规则。
