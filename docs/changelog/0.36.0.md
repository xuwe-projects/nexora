# Nexora 0.36.0

发布日期：2026-08-14

## 摘要

本版本把桌面 Shell、全局搜索、主题和标准 CRUD 列表收敛为可扩展的公共契约。Shell 现在按
原型保持 Sidebar 直达窗口顶部，右侧独立承载标题栏、紧凑标签栏和页面内容；标签前缀固定
展示后退、前进和刷新，刷新能力由当前 Feature 明确声明。应用可以注册主题预设、搜索提供者
和工具栏动作，标准主数据列表则通过 `CrudQuery`、`CrudListState` 与 `CrudPanel` 统一分页、
筛选、排序、选择和行操作。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 新增 `CrudQuery` 派生宏及查询元数据，覆盖分页大小边界、筛选控件、触发方式、校验、默认值
  和可选服务端排序枚举；请求 DTO 继续归应用所有，序列化 wire 不由框架改写。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `CrudListState<Row, Query>` 与新版 `CrudPanel<Row, Query>`，统一首次加载、刷新、加载更多、
  分页、筛选、服务端排序、已加载行选择、行操作委托和错误状态；请求可通过
  `create_with_app` 在执行时解析认证或业务上下文。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增全局搜索提供者、模式、分区、异步请求、历史解析与动作模型。应用搜索历史按账号隔离，
  可在偏好中禁用或清理。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `ShellToolbarAction`、Feature 刷新可用性与刷新生命周期。标签前缀始终显示后退、前进、
  刷新；不可刷新页面只禁用按钮，不再改变标签栏结构。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `ApplicationOptions` 支持注册应用主题预设和默认预设；主题目录同时包含浅色、深色主题，设置
  页面从运行期目录动态展示并切换。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `TableSwitchCell`，为表格内受控布尔切换提供统一的 loading、disabled 和回调边界。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

  搜索触发器按原型收敛宽度、高度、图标、提示文本和快捷键。标签项显示 Feature 图标前缀。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

  `xuwe` 迁移为 `nexora`，未知主题和颜色模式安全回退到应用默认值。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `CrudTableRow` 的 sortable 列必须声明服务端排序映射，避免把桌面列 key 当作后端排序枚举。
  `CrudTable` 继续持有稳定表格布局和选择状态。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 默认 Account 用户与角色页面迁移到新的 Shell、刷新和官方表单组件边界；示例、脚手架、组件
  选型规则和中英文桌面文档同步升级。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- GPUI 固定到 `cc053a4a6fa2fd0e8793201ed9099466af1be0b1`，`gpui-component` 与 assets
  固定到 `55b6bb88905d8e76cd23d9e3ebea3151dcdb84a0`，脚手架输出同一组合。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- 修复标签栏根节点错误占满剩余高度而在页面上方产生大块空白的问题；标签栏现在保持固定高度。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 修复 Sidebar 被右侧标题栏整体下压的问题，导航和品牌区现在从窗口顶部开始。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 修复刷新按钮只在部分页面条件渲染、造成标签前缀缺失的问题；按钮始终存在并准确反映当前
  Feature 的可用状态。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 删除旧 `Card`、`FormItem`、`LabeledControl`、`CrudPanelToolbar`、`PanelHeaderAction` 及
  对应安装入口。标准控件改用 `gpui-component`；应用级顶部动作改用 `ShellToolbarAction`。
- `CrudPanel` 改为 `CrudPanel<Row, Query>`，构造参数、筛选、排序、选择和操作通过
  `CrudListState` 与委托配置。复杂工作台应使用普通布局组合官方组件，不应伪装成标准 CRUD。
- `CrudTableRow` 的 sortable 字段若没有服务端排序映射将编译失败；应用必须显式映射到自己的
  后端枚举。`CrudQuery` 必须标记唯一分页字段，sort 字段必须为 `Option<Sort>`。
- `FormDialog` 不再承载旧表单字段包装器；表单内容直接组合 `gpui_component::form::field()`。
- `workspace.toml` schema 3 会保存 Sidebar 与搜索历史偏好；回滚到 v0.35.0 会忽略这些新字段，
  不涉及数据库、HTTP API 或更新器协议回滚。

## 从 0.35.0 升级

1. 把全部 Nexora workspace 依赖和 CLI 更新到 `v0.36.0`，并重新生成 `Cargo.lock`。
2. 先在应用 workspace 使用本地 Nexora 路径完成编译迁移；验证完成后再切换到本 release tag。
3. 把 `PanelHeaderAction` 注册迁移到 `ShellToolbarAction`；为所有远程数据 Feature 实现
   `reload_availability` 与 `reload`，静态页面保留禁用刷新。
4. 用官方 `field()`、`GroupBox`、`Button`、`Input`、`Select`、`DataTable` 和 `Switch` 替换已删除
   的旧 UI 包装器。复杂工作台保留页面私有布局，不套新版 `CrudPanel`。
5. 为标准单列表请求派生 `CrudQuery`，为 sortable 列补充服务端枚举映射，再使用
   `CrudListState` 和新版 `CrudPanel`。不要改变现有 HTTP wire、筛选字段或服务端接口。
6. 若应用需要自有品牌主题，通过 `ApplicationOptions::theme_preset` 注册一组浅色/深色主题，
   并用 `default_theme_preset` 指定默认 ID。
7. 人工核对 Sidebar 顶部对齐、搜索触发器、紧凑标签栏、Feature 图标前缀、后退/前进/刷新、
   主题切换、标准列表筛选/排序/选择和复杂工作台布局。

## 验证

发布前执行以下门禁：

- 使用 SemVer 解析器确认 `0.36.0` 严格高于 `0.35.0`
- `cargo fmt --all --check`
- `cargo check --workspace --all-targets`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

iMES 已先通过本地路径依赖完成编译迁移，并通过 workspace check、iMES 测试和 Portal 测试。
本版本未修改 SQLx migration、PostgreSQL schema、HTTP 路径、请求字段或服务端筛选语义，因此
无需数据库迁移或后端兼容开关。外部 PostgreSQL/OIDC、签名、公证与对象存储环境不在本次本地
门禁范围内。
