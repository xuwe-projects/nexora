# Nexora 0.40.0

发布日期：2026-08-17

## 摘要

Account 统一了本地账号与 ZITADEL 的服务账号、项目角色和用户授权关系。服务账号现在可以按
username 创建或确认复用 Provider 中的既有 machine user；角色创建、改名、删除以及用户角色
替换会同步 ZITADEL Project。产品内的 Secret/PAT 创建、列表和撤销能力已删除，PAT 由开发人员
直接在 ZITADEL 管理，Nexora 仅保留 introspection 鉴权。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 服务账号创建请求新增 `use_existing`。本地或 ZITADEL 已存在同 username 的 machine user 时，
  首次请求返回 `409 service_account_reuse_confirmation_required`，确认后可导入或复用；命中
  human user 时返回 `409 service_account_username_type_conflict`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- Account 使用 ZITADEL v2 `AuthorizationService` 管理用户在默认 Project 下的完整角色集合，并在
  本地写入失败时尽力恢复 Provider 原角色。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 系统 owner 下的自定义角色创建、改名和删除同步 ZITADEL Project 角色定义。分配角色前会幂等
  确保全部目标角色存在，因此升级前已有的本地角色可在首次分配时自动补齐。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 人员用户、服务账号以及默认用户管理页面的角色替换统一先写 ZITADEL authorization，再写本地
  `account.user_roles`；移除角色时同样替换 Provider 中的完整角色集合。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 服务账号创建界面移除初始凭据选项，并使用官方确认弹窗处理同 username 账号复用。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `[account.oidc].introspection_client_id` 与 `introspection_client_secret` 继续用于 opaque PAT
  introspection；未配置时仍保持 JWT-only 鉴权。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Removed

- 删除产品内“账号与凭据”入口、凭据表单和一次性明文展示。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 删除服务账号凭据 HTTP 路由、客户端方法、公共 DTO、Rust 领域能力、Provider 适配方法以及
  `service_account_credentials` 权限。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新迁移删除 `account.service_account_credentials` 表及其枚举；ZITADEL 中实际存在的 Secret/PAT
  不会被删除。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 这是公开 API 与数据库结构的破坏性变更，因此版本从 `0.39.0` 升至 `0.40.0`。
- 下游必须删除以下 HTTP 调用：
  `GET/POST /service-accounts/{id}/credentials`、
  `POST /service-accounts/{id}/credentials/reconcile` 和
  `DELETE /service-accounts/{id}/credentials/{credential_id}`。这些路径升级后返回 `404`。
- 下游 Rust 代码必须删除凭据 DTO、凭据 client 方法及凭据领域类型的引用。创建服务账号时只提交
  账号资料、角色和可选 `use_existing`，不再提交 `initial_credential`。
- 升迁移会永久删除 Nexora 本地保存的非敏感凭据元数据。Provider 中的 Secret/PAT 本体不受影响；
  下迁移只重建空表、枚举和权限，无法恢复已删除的元数据。
- 部署使用的 ZITADEL 管理 PAT 必须拥有 Project 角色和 Project authorization 的查询、创建、更新、
  删除权限。未满足时角色或服务账号变更会失败关闭，不会只写本地造成静默漂移。
- 没有新增配置项、宏、Skill 或脚手架规则；introspection 配置保持兼容。

## 从 0.39.0 升级

1. 把全部 Nexora workspace 依赖切换到 Git tag `v0.40.0`，重新生成 `Cargo.lock`，桌面端与服务端
   使用同一 tag。
2. 确认 Account 使用的管理 PAT 具有 ZITADEL Project role 与 authorization 管理权限。
3. 启动时先在宿主唯一 `PgPool` 上运行 `nexora::server::migrate(&pool)`；迁移会删除本地凭据元数据
   表，但不会调用 ZITADEL 删除任何实际凭据。
4. 删除应用内所有凭据管理入口和 HTTP 调用。需要 PAT 时由开发人员在 ZITADEL 后台创建，并以
   Bearer token 调用应用 API。
5. 验证角色创建、改名、删除及用户角色增删会同时反映到 ZITADEL Project。已有本地角色会在首次
   分配时自动幂等创建对应 Provider 角色定义。

回滚到 `0.39.0` 前先停止新版本服务并执行下迁移。下迁移会恢复空的凭据表、枚举和权限，但不会
恢复升级时删除的元数据；需要继续使用旧凭据页面时只能重新协调或重新创建 Provider 凭据。
