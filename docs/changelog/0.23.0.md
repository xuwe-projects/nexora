# Nexora 0.23.0

发布日期：2026-08-03

## 摘要

本版本统一桌面用户设置路径并迁移旧偏好，为 CRUD DataTable 增加列布局和后台排序持久化，
同时让 build、publish 与 yank 完整支持多 app、多 channel、通道运行配置和自动 updater feed。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 桌面偏好统一保存到 `~/.xuwe/<cargo-package>/settings.json`；首次升级会在新文件不存在时读取
  旧 `workspace.toml`，使用临时文件和原子替换写入 JSON，并保留旧文件。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- `CrudTableDelegate` 新增列顺序、列宽和单列后台排序快照，`CrudTableRow` 派生支持
  `sort_field`，`persistent_crud_table_state` 以稳定 `table_id` 接入共享 Settings、原生列交互和
  后台重载回调。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `release.channels` 支持一个 app 同时声明 nightly、beta、stable 等通道，并通过根级默认值与
  channel 覆盖合并 version、build number、最低支持版本和 runtime config。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- build、publish、yank 新增可重复 `--app` / `--channel` 及 `--all-apps` /
  `--all-channels`，交互模式支持多选，非交互模式使用各 app 的默认通道。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- `nexora::config::initialize(None)` 现在按显式路径、有效命令行 TOML、标准 app bundle 资源、
  本地基础配置的顺序加载；各 channel 在构建时按显式路径、通道约定路径、基础路径选择配置，
  并在签名前写入 `Contents/Resources/config/<package>.toml`。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- 多通道 updater feed 根据 publish target、public base URL、object prefix、app key 和 channel
  自动生成并写入各自 bundle。release receipt 升级到 schema 2，记录运行配置相对路径、
  SHA-256 和最终 feed，所有产物继续按 channel 隔离。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- 多组合 build/publish/yank 在任何构建或远端 mutation 前完成全部只读预检；构建顺序执行，
  失败报告已完成、失败和未执行组合。scaffold、CLI help、双语文档和打包 Skill 已同步新模型。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 破坏性变更：实现 `nexora::Application` 的应用必须新增
  `const PACKAGE_NAME: &'static str = env!("CARGO_PKG_NAME");`，用于稳定 Settings 目录。
- 旧单通道 `release.channel` 和匹配的静态 `updater.feed_url` 继续兼容。新式
  `release.channels` 不能与旧字段或非空静态 feed 混用。
- schema 1 release receipt 不会被 schema 2 发布流程读取；升级后需重新执行 build。
- 本版本仍只声明和验证 Windows/Linux 图标与路径，不声称新增对应平台安装包实现。

## 从 0.22.0 升级

1. 将全部 Nexora 依赖更新到 `v0.23.0`，重新生成 lockfile，并为每个 `Application` 实现新增
   `PACKAGE_NAME`。
2. 确认新设置写入 `~/.xuwe/<package>/settings.json`；旧 `workspace.toml` 会保留。
3. 需要表格持久化时，为业务表提供稳定 `table_id`，用 `sort_field` 映射后台字段，并在首次
   请求前读取恢复排序；排序变化回到第一页并请求服务端。
4. 把新项目迁移为 `release.default_channel` 与 `release.channels.<name>`；删除多通道模式下的
   静态 `updater.feed_url`，并把全部通道加入 `updater.channels`。
5. 为各通道创建不含秘密的 `config/<package>-<channel>.toml`，或保留
   `config/<package>.toml` 作为回退。运行配置会进入安装包，应视为公开数据。
6. 重新执行 `nexora build --app <app> --channel <channel>` 生成 schema 2 receipt，再运行
   对应 publish dry-run。
