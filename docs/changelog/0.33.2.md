# Nexora 0.33.2

发布日期：2026-08-11

## 摘要

本补丁版本修复 `configuration` crate 在 Windows/MSVC 上因缺少 `windows/std` 而无法把
`windows_result::Error` 保留为 `std::io::Error` 错误来源的编译失败，修复 Windows 单例门禁
未识别 `ERROR_LOCK_VIOLATION` 导致二次启动失败的问题，并增强 GitHub Release 工作流在
Release 已存在时的安全重跑与资产补全能力。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Fixed

- `configuration` 的 Windows 专用 `windows` 依赖显式启用 `std`，使现有
  `.map_err(std::io::Error::other)` 满足 `std::error::Error` 约束，同时继续保留底层 Windows
  错误类型。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 桌面单例门禁现在使用 `fs2` 提供的标准锁竞争错误进行跨平台判断。Windows
  `ERROR_LOCK_VIOLATION (33)` 不再因映射为 `ErrorKind::Uncategorized` 而中止二次启动，现有
  主进程会正常收到激活请求。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- GitHub Release 发布作业现在只在 Release 不存在时创建草稿；已有草稿或公开 Release 会继续
  覆盖上传完整资产，并同步标题与版本说明，使 tag 发布流程可以安全重跑。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 没有公开 Rust API、配置格式、配置路径、HTTP API、Account DTO、SQLx migration、数据库
  基线或 Updater 协议破坏性变更。
- Windows 原子配置替换继续使用 `MoveFileExW`、`MOVEFILE_REPLACE_EXISTING` 和
  `MOVEFILE_WRITE_THROUGH`；保存、更新、跨进程锁、临时文件与错误来源语义保持不变。
- 桌面单例身份、运行时目录、锁文件名、本地 IPC 协议和公开 API 保持不变；本版本只修正
  Windows 对既有锁竞争状态的识别。
- `windows/std` 仅在 `configuration` 的 Windows target-specific dependency 上启用，根
  workspace 依赖仍保持 `default-features = false`，不会扩大其他 crate 的 feature 集。

## 从 0.33.1 升级

1. 把全部 Nexora 依赖与 CLI 更新为 `v0.33.2`，并重新生成 lockfile。
2. Windows/MSVC 下重新构建应用；不需要修改配置文件、环境变量或业务代码。二次启动会继续
   激活已有主进程，而不会把正常锁竞争报告为 I/O 错误。
3. 本版本没有修改 Skill、脚手架生成规则或宏约束，下游项目不需要同步 `.agents/skills`。

回滚到 v0.33.1 不需要数据库或配置迁移，但 Windows/MSVC 构建会重新遇到
`windows_result::Error: StdError is not satisfied` 编译错误，桌面二次启动也可能重新把
`ERROR_LOCK_VIOLATION` 当成 I/O 失败。发布工作流会恢复为无法安全补全已存在 Release 资产的
旧行为。

完整 workspace 与脚手架消费者验证使用官方 `protoc 34.0` 和本机
`protoc-gen-rust-grpc`。脚手架检查从没有 `Cargo.lock` 的普通桌面项目和 Account 全栈项目重新
解析依赖，并编译桌面端、服务端与 migration 测试目标。文档使用 Bun 1.3.14 和 VitePress
1.6.4 构建通过。

workspace 测试有 3 项依赖人工预装打包工具的用例按既有条件忽略：2 项需要
`NEXORA_TEST_ISCC` 指向兼容 ISCC，1 项需要显式提供 `rc.exe` 与 MSVC linker 的人工验收环境。

`configuration` 的编译与测试在真实 Windows/MSVC 环境执行。当前环境没有执行 Linux/macOS
手工平台验收，也没有连接外部 PostgreSQL、OIDC、签名、公证或 S3/RustFS 发布环境；本版本
不修改这些协议或集成边界。
