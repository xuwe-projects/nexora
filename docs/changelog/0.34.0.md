# Nexora 0.34.0

发布日期：2026-08-11

## 摘要

本版本把 Nexora 桌面的默认窗口承载方式改为单进程多窗口。主窗口、额外 Shell、唯一
Settings 和注册 Window 现在默认共享同一个 GPUI 应用进程、应用级 Global、业务模型与缓存，
避免每个窗口重复初始化完整应用运行时。同时修复单独关闭子窗口后立即退出时，旧会话因主进程
尚未消费 `WindowClosed` 而在下次启动被错误恢复的问题。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Changed

- `ApplicationOptions::default()` 现在令 `subprocess_windows` 默认为 `false`。额外 Shell、
  Settings 和注册 Window 通过同一 GPUI 事件循环中的 `App::open_window` 创建，应用的
  `Application::initialize`、Account、Preferences、Updater、业务 Global 和共享 Model 只需要
  一份运行时。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 每个窗口继续独立持有 Shell、Feature UI Entity、标签、焦点、输入、订阅、任务和表单草稿；
  框架不会跨窗口复用同一个 UI Entity。需要共享的大型业务集合和缓存应放在应用级 Global 或
  共享 Model 中。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `.subprocess_windows(true)` 继续提供原有受管子进程模式，供确实需要故障隔离、安全隔离或
  独立服务生命周期的应用显式选择；单例门禁、完整多窗口、会话恢复、唯一 Settings、注册
  Window 和托盘窗口组能力在两种模式下均保留。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `develop-nexora-apps` 与 `gpui-desktop-development` Skill、脚手架内嵌副本和中英文桌面文档
  已同步新的默认进程模型及共享状态边界。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- 主进程整体退出时会先向受管子进程发布退出原因，等待它们提交最终窗口会话 patch，再同步
  消费积压的偏好 patch、会话 patch 和 `WindowClosed`，最后刷盘权威快照。已经单独关闭的窗口
  不再于下次启动重新出现，退出时仍打开的窗口继续恢复。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 退出阶段不再响应新的子进程窗口创建请求；尚未实际创建的新会话会从最终快照中清理，避免
  下次启动恢复一个用户从未看到的窗口。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 增加默认单进程、显式多进程兼容入口，以及“最终会话 patch 后收到窗口关闭”顺序的回归测试。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 这是 `0.x` 阶段的默认配置行为变更：未显式设置 `subprocess_windows` 的应用从多个受管进程
  改为单个操作系统进程。依赖进程故障隔离、安全隔离或独立服务生命周期的应用必须显式调用
  `.subprocess_windows(true)`。
- 已显式设置 `.subprocess_windows(false)` 或 `.subprocess_windows(true)` 的应用保持其选择；
  `single_instance`、`restore_window_sessions` 和 `tray_enabled` 的默认值不变。
- 没有删除或重命名公开 Rust API，也不修改 `workspace.toml` schema、HTTP API、Account DTO、
  SQLx migration、数据库基线或 Updater 协议，无需数据或配置迁移。
- 默认同进程模式共享应用级状态，但不会自动合并下游 Feature 内部自行复制的业务数据。应用应把
  确实跨窗口共享的数据提升到应用 Global 或共享 Model，同时保留窗口局部 UI 状态。

## 从 0.33.2 升级

1. 把全部 Nexora 依赖与 CLI 更新为 `v0.34.0`，并重新生成 lockfile。
2. 接受默认单进程多窗口的应用无需增加配置。检查应用级业务数据是否由 Global 或共享 Model
   持有，避免各窗口的 Feature 自行复制大型集合或缓存。
3. 需要受管子进程隔离的应用在 `ApplicationOptions` 中显式增加
   `.subprocess_windows(true)`；不要同时关闭单例、会话恢复或托盘，除非产品确实不需要这些能力。
4. 同步本版本的 `.agents/skills/develop-nexora-apps/SKILL.md` 和
   `.agents/skills/gpui-desktop-development/SKILL.md`。脚手架内嵌 Skill 已同步，新生成项目会直接
   使用新的默认说明。
5. 在目标平台验证多窗口创建、逐个关闭后立即退出、保持窗口打开时退出、重启恢复、Settings
   单例、注册 Window、重复启动激活和托盘窗口组命令。

回滚到 v0.33.2 不需要数据库或配置迁移。若要在回滚后继续保持单进程多窗口，请在应用代码中
显式保留 `.subprocess_windows(false)`；否则 v0.33.2 会恢复受管子进程默认值。

## 验证

发布前已执行并通过：

- 使用版本解析器确认 `0.34.0` 严格高于最新已发布版本 `0.33.2`
- `cargo fmt --all --check`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo run -p cli -- lint --workspace . --deny-warnings`
- `bash scripts/check-scaffold-consumer.sh`
- `cd docs && bun install --frozen-lockfile && bun run build`

脚手架检查会从没有 `Cargo.lock` 的普通桌面项目和 Account 全栈项目重新解析依赖，并编译桌面端、
服务端与 migration 测试目标。当前 macOS 环境未执行 Windows/Linux 人工 GUI 验收，也未连接外部
PostgreSQL、OIDC、签名、公证或 S3/RustFS 发布环境；本版本不修改这些协议或集成边界。多窗口
进程数量和 RSS 仍需由下游应用结合真实业务数据在目标平台验收，发布门禁不声明固定内存阈值。
