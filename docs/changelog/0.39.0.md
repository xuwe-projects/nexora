# Nexora 0.39.0

发布日期：2026-08-17

## 摘要

Account 现在支持不绑定身份 Provider 的内部服务主体。它继续使用现有
`service_account` 用户类型，以 `identity_id = null` 明确表达“不参与认证”，可作为审计记录的
稳定本地操作者，同时不会出现在默认用户管理列表或误入 ZITADEL 凭据流程。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 新增可逆 SQLx 迁移，允许 `account.users.identity_id` 为空，并用数据库约束保证人员账号仍然
  必须绑定非空 Provider 身份。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `User` 与 `UserResponse` 使用可选 `identity_id`，HTTP wire 字段保持存在，并对内部服务主体返回
  `null`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Changed

- 普通 `GET /users` 集合和默认用户管理页面排除 `identity_id = null` 的内部服务主体；人员用户与
  Provider machine user 的现有行为不变。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 对内部服务主体调用资料或凭据接口时，稳定返回
  `409 internal_service_account`，并在访问 ZITADEL 前结束请求。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

- 公开 Rust API 中 `User.identity_id` 与 `UserResponse.identity_id` 从 `String` 改为
  `Option<String>`；直接读取这些字段的下游必须处理 `None`。
- HTTP `User.identity_id` 字段仍为 required，但 schema 从 `string` 改为 `string | null`。现有人员与
  Provider 服务账号仍返回字符串。
- 没有新增 `audit` 用户类型。内部主体继续使用 `service_account`，以是否存在 `identity_id` 区分
  Provider 账号与本地主体。
- 新迁移只放宽列可空性并增加人员身份约束，不修改或删除现有数据。默认列表过滤不会影响通过
  本地 `id` 建立的审计外键。
- 没有新增配置项、权限、桌面控件、宏、Skill 或脚手架规则。

## 从 0.38.2 升级

1. 把 Nexora workspace 依赖切换到 Git tag `v0.39.0` 并重新生成 `Cargo.lock`；桌面端与服务端使用
   同一 tag。
2. 启动时先在宿主唯一 `PgPool` 上运行 `nexora::server::migrate(&pool)`，再运行应用自己的迁移。
3. 应用迁移可将不登录、不持有 Secret/PAT 的内部服务账号 `identity_id` 更新为 `NULL`；审计关联
   继续使用本地 8 位用户 `id`，不要用 Provider identity 作为审计外键。
4. 验证内部主体不出现在 `GET /users` 和默认用户页面，且人员账号与真实 Provider 服务账号仍可
   正常管理。

回滚到 0.38.2 前，必须先删除内部主体或为全部 `identity_id = NULL` 的记录重新绑定有效 Provider
身份；下迁移会在仍有空身份时主动失败，避免静默破坏审计数据。
