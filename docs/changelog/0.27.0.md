# Nexora 0.27.0

发布日期：2026-08-05

## 摘要

本版本把 `nexora` 命令行从框架 crate 拆成独立 `cli` package，并增加只更新 CLI 自身的
`nexora update` 与六个平台目标的 GitHub Release 预编译资产。应用发布链路改用展示名称加架构的
外部分发文件名、稳定 app key 的远端目录、channel 级对象存储覆盖和互不混用的凭据组；桌面启动
同时修正原生标题来源与登录页标题栏布局。

处理人：[@Jixiangup](https://github.com/Jixiangup)

关联 Issue/PR：无

## Added

- 新增独立 `crates/cli` package，承载 `nexora` binary、脚手架、lint、build/publish 和完整集成
  测试；框架 `nexora` crate 回归纯 library 边界。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 `nexora update`：只从官方 GitHub Release 的 HTTPS `nexora-update.json` 选择当前 target，
  校验 schema、版本、文件名、大小和 SHA-256 后安全替换当前 CLI；不修改项目依赖、源码或桌面
  应用，也不会请求 sudo/UAC。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 新增 tag 驱动的 GitHub Actions 发布工作流，为 macOS、Windows、Linux 的 x86_64/ARM64 构建
  六个 CLI 资产和更新 manifest，并在全部资产就绪后使用本页说明发布 Release。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 发布目标支持 `channels.<channel>` 按字段覆盖 endpoint、公开 URL、HTTP 策略和凭据前缀；
  `object_prefix = ""` 可让稳定 app key 直接位于 bucket 根目录。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- `updater` crate 增加最小 feature 边界；关闭 `runtime` 时仍可复用发布元数据和
  `UpdateChannel`，CLI 无需链接 GPUI、网络下载或平台安装运行时。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## Changed

- 外部分发文件统一为 `<display_name>-<arch><suffix>`；macOS DMG/ZIP 与 Windows EXE/MSI/ZIP
  不再把 Cargo package、版本、build number 或完整 target triple 写入文件名。内部 executable
  与 sidecar 继续使用稳定 package 名。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 远端版本化对象布局改为
  `[object_prefix/]app_key/channel/version/build/arch/artifact`。publish 先上传并匿名验证不可变
  产物，再更新 channel 根的品牌化文件和 sequence manifest，最后写入签名 `latest.json`；不再
  生成 `latest.dmg`、`latest.exe` 或 `latest.msi` 别名。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- 默认发布凭据改为完整的 `NEXORA_PUBLISH_*` 组，仅在整组不存在时原子回退完整 AWS 组；自定义
  `credential_env_prefix` 不回退，access/secret/session 不会跨组混用。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)
- Windows 资源使用 UTF-8 RC、简体中文字符串表和独立的主程序/updater 版本身份；展示名称只进入
  用户可见描述，内部文件身份保持 package 稳定。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- `ApplicationOptions` 会在应用未显式设置原生标题时，以经过校验的安装元数据 `display_name`
  作为默认标题；开发运行继续回退应用名。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- CLI、配置、updater 和发布 Skill/文档全部切换到独立 `cli` package、新凭据组、品牌化文件名
  与新版远端布局。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## Fixed

- 登录页和 Shell 登录门禁继续复用 `gpui-component` 的 `TitleBar`，并通过纯布局容器确保绝对
  定位标题栏具有完整宽度和非零高度；Shell 托管场景仍可关闭 LoginGate 自带标题栏，避免重复。
  — 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 发布在写 mutable 对象前重新检查远端 sequence，并在不可变对象已存在、品牌化文件上传失败或
  远端身份不低于本地时停止，不会提前覆盖 `latest.json`。— 处理人：
  [@Jixiangup](https://github.com/Jixiangup)

## Removed

- 从 `nexora` framework package 删除 `cli` feature、同包 binary、脚手架和 CLI 测试；这些内容
  已迁移到独立 `cli` package。— 处理人：[@Jixiangup](https://github.com/Jixiangup)
- 发布凭据不再读取 `RUSTFS_ACCESS_KEY_ID`、`RUSTFS_SECRET_ACCESS_KEY` 或
  `RUSTFS_SESSION_TOKEN`。— 处理人：[@Jixiangup](https://github.com/Jixiangup)

## 兼容性与破坏性变更

本版本没有数据库迁移，也没有 Account HTTP 契约变更，但包含以下升级门禁：

- 原安装命令中 package `nexora`、`--features cli` 和 `--no-default-features` 已失效；CLI 现在从
  package `cli` 安装，binary 名仍为 `nexora`。
- 使用 `RUSTFS_*` 的发布环境必须迁移到 `NEXORA_PUBLISH_*` 或完整 AWS 凭据组。自定义 channel
  应声明独立 `credential_env_prefix`，不能依赖字段跨组补齐。
- 分发文件名和对象目录发生变化。下载页、CI 上传路径和运维清理脚本必须使用品牌化文件名与新
  布局；客户端继续只跟随签名 `latest.json`。旧 `latest.*` 与旧不可变对象不会自动删除。
- `nexora` crate 默认 feature 从 `desktop,derive,cli` 改为 `desktop,derive`。只依赖框架 library
  的应用不需要额外操作；把 CLI 与框架一起安装的脚本需要拆分。

## 从 0.26.0 升级

1. 把全部 Nexora 依赖更新为 `0.27.0` 或 Git tag `v0.27.0`，重新生成 lockfile。
2. 使用独立 CLI package 重新安装：

   ```bash
   cargo install --git https://github.com/xuwe-projects/nexora --tag v0.27.0 cli --locked --force --bin nexora
   ```

3. 把 `RUSTFS_*` 凭据改为 `NEXORA_PUBLISH_*`；beta/nightly 等隔离环境在对应 target channel 中
   设置自己的 `credential_env_prefix`，并一次性提供完整 access/secret/可选 session 组。
4. 更新引用构建产物的 CI/下载页：使用 `<display_name>-<arch><suffix>`，不要再查找版本化文件名
   或 `latest.*` 安装器别名。需要清理旧别名时由管理员明确执行，不要删除历史不可变对象。
5. 检查 `feed_url` 指向 `[object_prefix/]app_key/channel/latest.json`，并确认 app key 不随
   `display_name` 改名。
6. 下游项目同步 `.agents/skills/develop-nexora-updater`、其 `updater-protocol.md`、
   `publish-nexora-release`、`rust-code-style` 与最新 CLI 脚手架约束。本版本未修改自定义宏规则，
   不需要 `cargo expand`、bench、bloat 或 asm 验证。
